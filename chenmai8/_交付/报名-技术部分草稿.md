## 1. 定位：我们解决谁的一顿饭

**一句话**：澄勺是一台**千元级桌面助餐机械臂**，为**上肢功能障碍、吞咽功能正常**的
失能/半失能老人与残障人士，把"自己吃饭"这件事从"手到不了嘴边"变成"张嘴就有一口"。

- **不做什么（边界写清楚比夸大更重要）**：不喂面条与汤、不面向吞咽障碍人群、
  不面向重度认知障碍与卧床喂食。
- **目标场景**：固定餐桌、固定座位、一台普通笔记本。用户每天坐下的那 20 分钟。
- **核心主张（三条）**：
  1. **安全来自可证明的数值余量，不是来自"小心一点"**——送达停点与禁入球之间
     有一个每次运行都重算的余量算式，低于 5 毫米即判不合格。
  2. **单目 + 交互设计吸收误差**——不买深度相机，用"勺停口前 5 厘米 + 用户前倾自取"
     把 ±3–5cm 的单目误差变成设计余量，整机成本与安全冗余同时下降。
  3. **失败路径是被设计出来的**——舀空重舀、转头保持、吃饱即止、急停闩锁，
     全部是编排层的显式分支与可断言的状态转移表，不是"祈祷它别发生"。

## 2. MVP 闭环：一口饭的完整状态机

主序列（无打断时严格按序，每口走一遍）：

```
语音点菜 → 选碗 → 舀取 → 勺上检查 → 送达（口前停点）→ 等张嘴 → 等咬合
        → 勺空确认 → 撤回 → 记账 → 下一口
```

- **舀取**：脚本化参数化轨迹 + 腕部相机闭环。舀完立刻低头检查勺上有没有食物，
  没有就重舀，**重试上限 2 次**；重试耗尽仍为空则本口判 `retry`，直接撤回（不进送达）。
- **送达**：逆解目标经安全包络下发，停点固定在**口部中心外 0.17 m**（禁入球半径
  0.12 m + 0.05 m 间隙），**指令本身写不进禁入区**。
- **等咬合**：张嘴边（口部几何口径比 > 0.35）才送；用户闭嘴即判定咬合，随后确认勺空再撤回。
- **记账**：每口写一条记录（口数 / 起点终点时刻 / 结局 / 克数），推送护理看板。

打断分支（每 tick 最高优先级，行为树状态转移表冻结于
`chenmai-feeding-arm/chengshao/cs_orchestra/core.py:7-45`，测试逐条断言）：

| 打断源 | 机器的反应 | 本口结局 |
|---|---|---|
| 软件急停（空格键） | 立即停 + 相机角色回场景 + 闩锁直到显式复位 | `aborted` |
| 禁入区侵入 | 立即停 + 冻结底层 | `aborted`（复位后原路退回并回家） |
| 转头 > 25° / 人脸丢失 > 1 s | **保持不动** + 播报一次，恢复后原地继续 | 不变 |
| "等一下" | 悬停 + 播报 | 不变 |
| "吃饱了" | 撤回、不硬喂 | `rejected` |
| 皱眉 > 0.5 | 暂停 + 询问 | 不变 |

**相机双职台账**：每进入送达的口，相机角色恰好切换 2 次（进送达切到腕部口部追踪、
撤回完成切回场景），无其他切换；切换事件写入 trace 可审计。

## 3. 系统架构与技术栈

七层，每层一个模块，跨层数据全部经冻结契约（`cs_schema`，契约版本 v1.1，8 模型 + 7 枚举，
`extra=forbid` + 跨字段不变式）。

| 层 | 模块 | 职责 | 关键依赖（版本取自 `chengshao/requirements.txt` 锁定清单） |
|---|---|---|---|
| 契约 | `cs_schema` | 跨模块数据结构/枚举/常量的唯一事实来源 | pydantic 2.13.5 |
| 仿真 | `cs_sim` | 模型装载、FK/IK、可达空间、安全包络校验、对抗 oracle | MuJoCo 3.14.0、ikpy 4.1.0、numpy 2.2.6 |
| 执行 | `cs_arm` | 臂接口 + **安全包络硬闸** + Mock 执行器 + 真机骨架（fail-closed） | pyserial 3.5 + 舵机厂商 SDK（骨架期） |
| 感知 | `cs_mouth` / `cs_food` | 口部三维估计（单目主路径 / 腕部瞳距模式 / 深度后端延后保留）；勺上检查与选碗 | MediaPipe 1.0.1（CPU 478 关键点）、OpenCV 5.0.0.93 |
| 交互 | `cs_voice` | 离线语音链路：VAD → ASR → 意图 → 播报 | funasr 1.4.16（小型中文 ASR 模型）、pyttsx3 2.99 |
| 编排 | `cs_orchestra` | 50 Hz 行为树：进食全流程 + 安全/交互打断 + 相机角色台账 | py_trees 2.6.0 |
| 数据 | `cs_dashboard` | 护理看板：HTTP 契约 + SSE 实时刷新 + 离线单页 | FastAPI 0.141.1、uvicorn 0.54.0、SQLite |

**工程取向（三条，评审会问）**：

1. **全离线、全 CPU**：语音与感知均离线运行（eval 期程序化证据为**零外联**），
   一台普通笔记本即可，不需要显卡、不需要云、拔网线可复测。
2. **不引入 ROS**：同进程直调 + 行为树黑板；看板走本地 HTTP + SSE。
   模块边界由契约保证，进程内直调让调试与取证（trace 镜像）成本最低。
3. **一切运动只有一个出口**：行为树不能直接指挥舵机，所有指令经安全包络组装后下发，
   违规指令零运动且不计违规（见 §4）。
4. **证据链**：每个模块有一条 eval 命令，落 `reports/<module>_eval.json`
   （字段 `{module,date,cmd,metrics,thresholds,pass}`），门禁脚本独立重算一遍
   指标与阈值并与自报结论交叉核对。

## 4. 安全设计（本章是本项目的技术核心）

### 4.1 硬闸单点：安全包络

安全包络是包在任意臂接口外的一层，**行为树与真机之间唯一的执行通道**。
每条指令下发前依次过五道闸（`cs_arm/safety.py:7-22`）：

1. 急停闩锁 / 违规未复位 / 未使能 → **拒绝，零运动**；
2. 目标解析：笛卡尔目标由包络层解算为关节目标，无解 → 拒绝；
3. 速度硬限：关节 > 1.5 rad/s 或线速度 > 0.15 m/s → 拒绝（**不静默放行**）；
4. 软限速：进入近脸限速场时通过拉长执行时长把有效速度压到 0.10 m/s；
5. 包络校验：TCP 加密采样扫禁区 + 连杆胶囊扫掠 + 关节角速度，任一违规 → 拒绝。

**语义纪律**：拒绝**不**计入违规状态（拒绝是包络在正常工作）；
违规状态只保留给真实安全事件（急停 / 看门狗 / 禁入区侵入），一旦置位即
`clear_to_move = false`，**直到显式 `reset()`**。

### 4.2 禁入区与限速（数值来自默认工作区配置）

| 约束 | 数值 | 口径 |
|---|---|---|
| 面部禁入球 | 半径 0.12 m，球心 = 口部点 | 整球不可进入 |
| 躯干禁入胶囊 | 半径 0.15 m，位于口部点之后 | 整条胶囊不可扫掠 |
| 接近段线速度上限 | 0.15 m/s | 超过即拒绝 |
| 近脸限速场 | 0.10 m/s（距口部 0.15 m 内） | 软限速，压低有效速度 |
| 关节角速度硬上限 | 1.5 rad/s | 超过即拒绝 |
| 连杆等效半径 | 0.03 m | 扫掠检测用 |
| 送达停点 | 口部外 0.17 m（= 0.12 + 0.05 间隙） | 停点不依赖任何豁免 |

### 4.3 送达余量算式（每口重算，写进报告）

```
余量 = 停点距离 0.17 − 勺尖伸出 0.08 − 跟踪误差界 0.02 − 感知误差界 0.05
     = 0.02 m
判据：余量 ≥ 0.005 m（5 毫米）否则本口判不合格
```

四项全部是保守常量；勺尖伸出为偏大保守取值，臂上件后由实测覆盖。
**这条算式是"敢停这么近"的唯一理由**，也是评审可以当场复核的算术。

### 4.4 交互级兜底：最后 5 厘米由人补上

单目估距在演示主路径上有 ±3–5cm 的横纵误差。我们不靠更贵的传感器消掉它，
而是**用交互设计吸收它**：软质无锐边餐具 + 全程限速 + 送达停在口前 5 厘米 +
**用户前倾自取** + 座位定位贴固定人体位置。机器负责把饭送到嘴边，
**不负责怼到嘴里**——这既是无深度相机路线的安全主叙事，也是成本可控的前提。
