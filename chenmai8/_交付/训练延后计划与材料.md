### 互斥规则（红线）

1. **提供方常驻不碰**：`:8000 / :8001 / :8125`（/opt/gpumachine，anuser 名下）不 stop / 不 kill / 不降显存；训练腾窗只操作我方 `:9001–:9004`。政务 LLM 现转发依赖 ：8001（见 §2.2 ⚠️），任何影响 ：8001 的动作先评估政务链路。
2. **一卡一次只跑一个训练任务**，不与推理服务同卡混跑大任务（<8G 小评测可用 GPU0 免停服碎窗）。
3. **停 ：9001/:9002/:9003 = 短剧 GPU 链路中断**（M4 ASR / M7 TTS / M10 口型）：停卡前知会短剧工作流并确认无在跑任务；恢复用 `repo/gpu-services/{asr_align,tts,lip}/run_gpu.sh`，恢复后跑一次冒烟。
4. **:9004 端口互斥**：政务 llm_openai（现役常驻）与短剧 mt 服务设计端口冲突——`短剧 repo/gpu-services/mt/run_gpu.sh:14` `MT_PORT` 默认同为 9004（其 `pipeline/mt_backends.py:136` M6 默认亦指 9004）。二者不可同时启动；建议训练期把短剧 mt 定为 `MT_PORT=9005` 落定并同步改 tunnel 配置。
5. **Volta 约束全局生效**：仅 fp16（禁 bf16）、无 FlashAttention-2；断点常存（咖啡 every 5 epoch / ACT save_freq=20000），loss spike 即回退（政务预案）。
6. **显存口径校准**：各 plan"32G 单卡放得下"均按独卡口径；实际大窗 ~23.6G / 中窗 ~13.8G，上卡前先 1-batch dry-run 实测，超限按各 plan 自带降档（bs 减半 + accum 翻倍 / 降分辨率 / gradient checkpointing）。
7. **数据与产物**：跨机只走 COS 中转（桶 `everything-1476163454`，写入只用 coscmd）；holdout 永不入训练（咖啡 500 对固定集、短剧 500 句冻结集）；训练报告 JSON 统一落各仓 `reports/`/`out/`，中央台账只引用不复制数字。
