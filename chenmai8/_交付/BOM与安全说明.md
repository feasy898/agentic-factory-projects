## 第二部分 · 软件急停与禁入区设计

> 代码位置（包根）：`chengshao/cs_arm/safety.py`、`chengshao/config/workspace.json`。
> 设计原则：**拒绝 ≠ 违规**。被拒的指令零运动且不计违规（包络在正常工作）；
> 只有真实安全事件（急停 / 看门狗 / 禁入区侵入）才置违规位，置位后必须显式复位。

### 2.1 一切运动只有一个出口

行为树**不能**直接指挥舵机。行为树产出的是目标，经安全包络组装为关节指令后，
才是唯一能到达底层执行器的通道。包络在每条指令前依次过五道闸
（`cs_arm/safety.py:7-17` 冻结表）：

| 闸 | 判据 | 不通过时 |
|---|---|---|
| ① 状态闸 | 急停闩锁未置位、无未复位违规、已使能 | 拒绝，零运动 |
| ② 目标闸 | 笛卡尔目标可解算为关节目标 | 无解即拒绝 |
| ③ 速度硬闸 | 关节角速度 ≤1.5 rad/s；线速度 ≤0.15 m/s | 拒绝（**不静默放行**） |
| ④ 软限速 | 进入近脸限速场后有效速度 ≤0.10 m/s | 拉长执行时长以压低有效速度（改写） |
| ⑤ 包络校验 | TCP 加密采样扫禁区 + 连杆胶囊扫掠 + 关节角速度 | 拒绝，零运动 |

### 2.2 禁入区与限速（数值取自默认工作区配置 `config/workspace.json`）

| 约束 | 数值 | 说明 |
|---|---|---|
| 面部禁入球 | 半径 **0.12 m**，球心 = 口部点 | 整球不可进入、不可扫掠 |
| 躯干禁入胶囊 | 半径 **0.15 m**，轴线位于口部点之后 | 连杆与 TCP 不可扫掠 |
| 接近段线速度上限 | **0.15 m/s** | 硬限，超限拒绝 |
| 近脸限速场 | **0.10 m/s**（距口部 0.15 m 内生效） | 软限速，压低有效速度 |
| 关节角速度硬上限 | **1.5 rad/s** | 硬限 |
| 连杆等效半径 | **0.03 m** | 扫掠检测保守包络 |
| 送达停点 | 口部外 **0.17 m**（= 0.12 + 0.05 间隙） | 停点在球外，**不依赖任何豁免** |

### 2.3 送达余量算式（每口重算，判据 ≥5 mm）

```
余量 = 停点距离 0.17 − 餐具前伸 0.08 − 跟踪误差界 0.02 − 感知误差界 0.05 = 0.02 m
```

四项均为保守常量，餐具前伸取偏大值（保守），臂上件后由实测覆盖。
余量 < 0.005 m 即判本口不合格——这是"敢把勺子送到脸前 5 厘米"的唯一理由。

### 2.4 软件急停（空格键）语义

- **闩锁不是暂停**：`estop()` 同步闩锁，返回即已生效——底层立即冻结，
  且**此后任何写入都被拒绝、零运动**（实测：急停注入后 0.058 ms 停止，
  急停后写入被拒，`clear_to_move` 为假）。
- **必须显式复位**：违规位清除只能由 `reset()` 完成；复位后立即重查禁入区，
  仍在区内则如实重新闩锁——**不会因为"按了解除"就恢复放行**。
- **本机无物理急停硬件**：这是本项目的显式设计选择，安全论证见 §3，
  不是未完成项。若评审要求物理急停，按 §1.3 备查加购并串入电源线。

### 2.5 看门狗

- 使能后 **0.5 s** 内无任何控制活动 → 判定失联：置违规位 + 底层去使能。
- **巡检读数不喂心跳**：安全巡检与状态采样只用于监控，不得把静默计时器清零；
  心跳只由控制活动与底层心跳驱动（否则监控线程永远不会超时——这是常见坑，
  代码里显式规避了）。
- 实测：静默 0.4 s 不误触发、0.6 s 触发去使能、可恢复。

### 2.6 感知级安全打断（与硬闸互补）

| 事件 | 阈值 | 机器行为 |
|---|---|---|
| 转头 | \|偏航角\| > 25°（双向） | **保持不动** + 播报一次，转回来原地继续 |
| 人脸丢失 | > 1 s | 保持 + 播报 |
| 皱眉 | > 0.5 | 暂停 + 询问（打扰比没喂到更糟） |
| 语音"等一下" | 意图优先级 pause > next | 悬停 + 播报 |
| 语音"吃饱了" | 意图优先级 done 最高 | 撤回、会话结束，**不硬喂** |

阈值与优先级为冻结常量（`cs_schema/constants.py:20-23` 及语音规则表）。

## 第三部分 · 兜底设计（无深度相机路线的安全闭环）

### 3.1 四件套：软质餐具 + 全程限速 + 口前 5cm 停点 + 用户前倾自取

1. **软质餐具**：食品级软勺、勺头可拆洗、无锐边（接触面唯一风险源直接消除）。
2. **全程限速**：接近段 ≤0.15 m/s、面部附近 ≤0.10 m/s，且是**硬闸**不是建议值。
3. **口前 5 cm 停点**：勺子停在面部禁入球外 0.05 m 处，指令层面写不进禁入区。
4. **用户前倾自取**：最后 5 厘米由**人**完成。用户主动前倾的动作本身是
   "我准备好了"的显式信号，比机器猜一个时机更安全；同时它吸收了单目估距
   ±3–5cm 的误差——**误差从"安全问题"变成"设计余量"**。

再加一条环境侧约束：**座位定位贴**把用户位置固定，压缩人体相对位姿的随机性。

### 3.2 感知误差的来源与吸收

| 误差源 | 量级 | 吸收方式 |
|---|---|---|
| 单目距离先验（固定先验模式） | 横纵 ±3–5 cm | 口前 5cm 停点 + 前倾自取 + 座位定位贴 |
| 近距腕部视角估距（瞳距先验模式） | 预期优于远距固定先验 | 同上；实测精度待真机四距离点核查 |
| 餐具前伸 | 保守常量 0.08 m | 余量算式内扣除，且取偏大值 |
| 轨迹跟踪 | 界 0.02 m（Mock 实测 0.2–0.31 mm） | 余量算式内扣除 |

**原则**：所有误差都进同一个余量算式，不分散在各处口头承诺。

### 3.3 失效模式与响应（无深度相机 + 软件急停前提）

| 失效 | 机器行为 | 用户可感知 |
|---|---|---|
| 舀空 | 低头检查勺上 → 重舀（≤2 次）→ 仍空则撤回不送 | 停顿后不送这一口 |
| 人脸丢失 / 转头 | 保持不动 + 播报 | 听到提醒，转回来继续 |
| 感知抖动 / 误检 | 阈值偏保守（宁可重舀、宁可停） | 偶尔多舀一次 |
| 禁入区侵入 | 闩锁 + 冻结 + 后撤回安全位 + 需显式复位 | 停住，等复位 |
| 软件急停 | 闩锁 + 冻结，必须显式复位 | 按键即停 |
| 控制失联（看门狗） | 0.5 s 内去使能 | 停止 |
| 深度/相机失效 | 不猜：按缺省固定先验降级；仍不可信则停在安全位播报 | 停止或降级运行 |
| 硬件缺失 | 明确失败退出（占位即契约，不假装成功） | — |

### 3.4 定位声明（诚实边界）

本项目是**桌面助餐辅具原型**，不是医疗器械，也不宣称医疗级安全认证：
- 面向**上肢功能障碍、吞咽功能正常**的用户；**不面向吞咽障碍人群**（误吸风险不可由本系统覆盖）。
- 安全论证建立在"人在场、可随时按键或转头中止、餐具为软质"三条前提上；
  **无人看管、用户失去意识、餐具非软质**三种情形不在本系统设计范围内。
- 真机安全项（腕部视角追踪精度、舀取成功率、送达误差、100 次零侵入、
  真机安全演练）**尚未实测**，接口与判定线已冻结，补测计划见
  `chenmai8/_交付/报名-技术部分草稿.md` §6。

## 第四部分 · 硬件到件后的真机安全验收（计划，入口未实现）

> 以下为计划项，**当前仓库没有对应命令入口**（`docs/assets/specs/hw-toolchain.md:3`
> 与 `docs/assets/manifest.md` 记为 planned）。列出是为了让评审看到验收口径已经想清楚，
> 而不是声称已具备。计划通过线：

| 验收项 | 通过线 |
|---|---|
| 单臂冒烟 | 6/6 舵机连通、回读一致、限位/温度正常、夹爪开合正常 |
| 手眼标定（顶部 + 腕部） | 重投影残差 ≤3 mm 或 ≤2 px |
| 相机验收（双职） | 20–50cm 面部可辨、最近对焦达标、亮→暗曝光恢复 ≤1 s、全行程线缆无牵扯 |
| 口部追踪四点核查 | 20/30/40/50 cm 估距误差 ≤4 cm、检出率 ≥95% |
| 舀取成功率 | 每食物 50 次，最终（含闭环重试）≥90%、首次 ≥70%，分食物报告 |
| 送达精度 | 误差 ≤1.5 cm |
| 安全演练（转头/急停/侵入各 20 次） | 20/20 停止或后撤；禁入区侵入 0 次 |

（抛"硬件不可用"异常 / 非零退出码），**不得以仿真或空数据返回成功**——
这条已写进代码骨架，任何"假装成功"在评审时都属于破坏契约。
