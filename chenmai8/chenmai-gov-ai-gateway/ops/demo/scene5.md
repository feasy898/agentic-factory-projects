# 演示场景 5 · 扫描件体检：扫描 PDF → OCR 体检 HIGH → 重打码导出 → 再体检零残留

> 对应：开发指令 §10 演示场景「扫描件体检」（§10 表中列为场景 3，本任务单
> T4.3 编号为场景 5）；OCR 路径 T4.1（渲染 300dpi → 纯 CPU OCR → 重建可检测
> 文本 + 命中框映射）。
> e2e 对应用例：U6 文件通道（文本层）；扫描件专项验收 = `python -m evals.m6_ocr`。

## 剧情（讲解词）

基层报来一份**纸质公示名单的扫描件**（图片型 PDF，无文字层）。公开前把它交给
网关体检：网关把页面渲染成 300dpi 位图、用纯 CPU OCR 重建出可检测文本，逐个
定位身份证/手机号并给出坐标；导出时对命中处**打黑框后整页重栅格化**——导出物
是纯图像 PDF、不存在可复制的底层文字，再体检零残留。

## 材料

`scan_lowincome_publicity_demo.pdf`（合成扫描件，构建确定性；seeded 值）：

- 身份证 ×3：`460035196203124533`、`110105197502265127`、`460023198506114029`
  （GB11643 校验位合法；批量名单 ≥3 → 风险 **HIGH**）
- 手机号 ×1：`13800138003`
- 敏感属性词：低保对象；人名 ×3：张老年/李老年/王老年（姓氏启发式）

## 步骤

1. 起服务（文件通道不需要 mock 上游）：
   ```bash
   ./.venv/Scripts/python.exe -m gateway --port 9000
   ```
2. 物化材料（或经 `http://127.0.0.1:9000/webui/demo` 下载）：
   ```bash
   PYTHONUTF8=1 ./.venv/Scripts/python.exe -m ops.demo.build_fixtures
   ```
3. 打开体检页 `http://127.0.0.1:9000/webui/files`，上传
   `scan_lowincome_publicity_demo.pdf` → 点「开始体检」。
   预期报告：风险徽标 **HIGH**；种类 `scan_pdf`；命中明细——
   身份证 ×3（**页码 + bbox 坐标**，OCR 重建文本定位）、人名 ×3、手机号 ×1、
   低保对象（敏感属性）×1。
   📸 **截图点①**：HIGH 徽标 + 命中明细表（bbox 列可见 = OCR 命中框映射）。
4. 点「③ 导出净化文件」→ 下载净化版。
   预期：响应头 `X-Sanitize-Method: scan-raster-redaction`（重打码渲染版：
   命中框黑框覆盖 → **整页重栅格化**为纯图像 PDF，零文本层）。
   📸 **截图点②**：导出成功提示 + 下载的净化文件。
5. **现场复核**：把导出物再次上传体检。
   预期：风险 **NONE**、命中 0（再 OCR 复核零残留；导出管线内置同款硬闸，
   不净即阻止导出）。
   📸 **截图点③**：二次体检 NONE 徽标 + 「无非白名单命中」。
6. 肉眼复核：打开导出物，身份证/手机号位置为黑框，其余内容保持原样。
