# 标签体系契约（labels）——实体类别 · 敏感属性子类型 · 密级标识词表

> 版本：v1.0（任务 T1.4，2026-09-28）
> 状态：契约冻结——**只增不改名**（与开发指令 §5 同一纪律；新增值域走"增补字段/追加枚举值"，不改既有值）。
> 自验收：`PYTHONUTF8=1 ./.venv/Scripts/python.exe -m evals.t0_labels`（exit 0 = 本文档与代码常量一致）。

---

## 1. 定位与效力

本文档是本项目**标签体系**的唯一文字契约，覆盖三层内容：

1. **实体类别**（`EntityClass`，19 个）——识别结果 `Finding.type` 的值域，及占位符用的中文标签；
2. **敏感属性子类型**（`SENSITIVE_ATTR_SUBTYPES`，9 个）——`Finding.subtype` 的值域（仅 `type=SENSITIVE_ATTR` 时允许填写）；
3. **密级标识 / 内部资料词表**——规则层逐词匹配、命中即拦截依据的词表及其机制。

效力顺序（冲突时以其上者为准）：

1. 开发指令 §5 冻结契约（规划文档，内部）；
2. 代码常量：`recognizers/models.py` 的 `EntityClass` 与 `SENSITIVE_ATTR_SUBTYPES`；
3. 词表文件：`config/classification_terms.txt`（运行时加载，可扩充）；
4. 本文档文字。

本文档**不定义**归一化规则（§5.3.2，在 `masking/normalize.py`）、占位符算法（§5.3.1，在 `masking/mapper.py`）与路由矩阵完整语义（§5.2，在 `routing/engine.py`），只在表格中引用其口径。

## 2. 依据与核实状态

### 2.1 标准对齐对象

- **GB/T 45574-2025《数据安全技术 敏感个人信息处理安全要求》**。公开检索摘要要点（检索日期 2026-09-28，来源为高校网站通知、标准化技术委员会口径的解读文章、律师事务所解读等**二手公开摘要**）：
  - 2025-04-25 发布，2025-11-01 实施，归口全国网络安全标准化技术委员会；
  - 确立敏感个人信息的识别和界定，规定处理通用安全要求与分类处理安全要求；
  - 公开摘要列举的敏感个人信息类别：**生物识别信息、宗教信仰信息、特定身份信息、医疗健康信息、金融账户信息、行踪轨迹信息、不满十四周岁未成年人的个人信息**，另有解读将**犯罪记录**等列为"其他敏感个人信息"的示例。
- 对齐口径沿用开发指令 §11 风险 10：标准差异**只影响词表与文案，不动冻结契约**。

### 2.2 核实状态声明（务必先读）

## 3. EntityClass 总表（冻结）

下表与 `recognizers/models.py` 的 `EntityClass` 定义一字不差（19 类；常量值即 `Finding.type` 与审计 `class_counts` 键；中文标签即占位符标签，全表唯一）。"检测载体"与"路由影响"两列为实现口径的**当前事实**（标注 v0 已实现者可在代码中复核），不改变 §5.2 冻结矩阵。

| 常量值 | 中文标签 | 检测载体（MVP 口径） | 默认 action_hint | 路由影响（§5.2 矩阵） |
|---|---|---|---|---|
| `PERSON` | 人名 | NER 适配器（P0 空实现，预留）；生成器模板姓名 | MASK | 单个结构化 PII → INTERNET（脱敏后） |
| `ADDRESS` | 住址 | NER 适配器（P0 空实现，预留） | MASK | 同上 |
| `ID_CARD` | 身份证 | 规则正则 + GB11643 校验位（v0 已实现） | MASK | 单个 → INTERNET；同请求 ≥3 → GOVCLOUD（批量名单） |
| `PHONE_MOBILE` | 手机号 | 规则正则（v0 已实现） | MASK | 单个 → INTERNET（脱敏后） |
| `PHONE_LANDLINE` | 座机 | 规则层计划：区号-号码，白名单可豁免 | MASK | 同上 |
| `BANK_CARD` | 银行卡 | 规则层计划：Luhn 校验 | MASK | 单个 → INTERNET；同请求 ≥3 → GOVCLOUD（批量名单） |
| `USCC` | 信用代码 | 规则层计划：GB32174 校验位 | MASK | 单个 → INTERNET（脱敏后） |
| `PLATE` | 车牌 | 规则层计划：含新能源牌照 | MASK | 同上 |
| `EMAIL` | 邮箱 | 规则层计划 | MASK | 同上 |
| `IP` | 地址 | 规则层计划：IPv4 | MASK | 同上 |
| `SECRET_KEY` | 密钥 | 规则层计划：密钥前缀/长熵串特征 | MASK | 同上 |
| `DATE_BIRTH` | 出生日期 | 规则层计划：配合"出生/生于"上下文 | MASK | 同上 |
| `SENSITIVE_ATTR` | 敏感属性 | 政务身份/敏感属性词表（规则层计划）+ 语义层适配器；子类型见 §4 | MASK | **GOVCLOUD（即便已脱敏）** |
| `WORK_SECRET` | 工作秘密 | 词表（规则层计划） | MASK | **GOVCLOUD（即便已脱敏）** |
| `CLASSIFICATION_MARK` | 密级标识 | 密级词表逐词匹配（v0 已实现，见 §6） | BLOCK_FLAG | **BLOCK** |
| `INJECTION` | 注入指令 | 语义层适配器（P0 空；回退规则词表） | BLOCK_FLAG | **BLOCK** |
| `ORG_INTERNAL` | 内部机构 | 词表/模板来源（按需） | MASK | §5.2 矩阵未单列；v0 引擎按 action_hint 处理（见 §9-8） |
| `DOC_NUMBER` | 文号 | 规则层计划：公开文号格式，默认 whitelisted | MASK | 命中白名单 → 不参与脱敏与路由（INTERNET） |
| `OTHER` | 其他 | 兜底（正常情况下不产出） | MASK | §5.2 矩阵未单列；v0 引擎按 action_hint 处理 |

注：`DOC_NUMBER` 的"默认 whitelisted"指规则层计划口径（公开文号默认豁免），不是词表冻结；白名单候选见 §7。

## 4. SENSITIVE_ATTR 子类型（冻结）

值域与 `recognizers/models.py` 的 `SENSITIVE_ATTR_SUBTYPES` 一字不差（9 个；仅 `type=SENSITIVE_ATTR` 的 Finding 允许携带，其余 type 携带 subtype 即校验失败）。"标准类别"列对齐 §2.1 摘要的类别名；对应强度标注沿用 §2.2 口径。

| 子类型值 | 覆盖的政务内容/身份 | GB/T 45574-2025 类别（公开摘要） | 对应强度 |
|---|---|---|---|
| `病症` | 疾病、诊疗、健康状态描述 | 医疗健康信息 | 已核实（摘要）：类别名对应；"病症"入医疗健康为语义推断 |
| `残障` | 残疾状况、残障等级 | 医疗健康信息 | 推断：摘要未逐字列举残障归属 |
| `低保特困` | 低保对象、特困供养人员身份（政务特有，见 §5） | 特定身份信息（推断）/ 项目自定义 | 推断 + 项目自定义 |
| `社区矫正` | 社区矫正对象身份（政务特有，见 §5） | 标准摘要无对应命名 | 项目自定义 |
| `信访人` | 信访人身份（政务特有，见 §5） | 标准摘要无对应命名 | 项目自定义 |
| `金融账户` | 银行/支付账户标识与账户类信息 | 金融账户信息 | 已核实（摘要）：类别名直接对应 |
| `行踪轨迹` | 行踪、活动轨迹描述 | 行踪轨迹信息 | 已核实（摘要）：类别名直接对应 |
| `犯罪记录` | 犯罪/违法记录描述 | 其他敏感个人信息（解读举例提及） | 已核实（摘要）：仅见于二手解读举例，未逐字核对原文 |
| `特定身份` | 上述之外的特殊身份（含证照标识类身份） | 特定身份信息 | 已核实（摘要）：类别名直接对应 |

标准摘要中其余类别（生物识别信息、宗教信仰信息、不满十四周岁未成年人的个人信息）本项目 **v0 未设专门类别/子类型**：文本通道中生物识别多为影像特征而非文本实体，未成年人可由出生日期推算但未单列。此为范围决策（见 §9-5），如需支持属契约**增补**（新增枚举值/子类型，不改既有值）。

## 5. 政务特有身份（低保 / 特困 / 社区矫正 / 信访人）

GB/T 45574-2025 摘要的类别清单不直接命名政务救助与基层治理身份；本项目面向县乡政务文书（低保公示、信访转办单、12345 工单、处罚决定书等模板族），将其**显式单列**为 `SENSITIVE_ATTR` 的子类型：

| 身份 | 子类型值 | 典型文书场景 | 处置口径（冻结矩阵） |
|---|---|---|---|
| 低保对象（最低生活保障） | `低保特困` | 低保公示名单、救助审批表 | 命中即 SENSITIVE_ATTR → **GOVCLOUD（即便已脱敏）**；文件体检 risk_level=HIGH |
| 特困供养人员 | `低保特困` | 特困人员救助供养材料 | 同上 |
| 社区矫正对象 | `社区矫正` | 社区矫正报到/转办材料 | 同上 |
| 信访人 | `信访人` | 信访转办单、接访记录 | 同上 |

设计理由：这些身份一旦关联到人，泄露危害与普通结构化 PII 不同（对象性、群体名单效应），因此路由上**不因脱敏而放行互联网**（§5.2 矩阵原文："WORK_SECRET 或 SENSITIVE_ATTR → GOVCLOUD，即便已脱敏也切政务云"），文件通道上一票定 HIGH（§5.5）。该单列属于**政务特有标签决策**，不主张为标准要求。

## 6. 密级标识与内部资料词表

### 6.1 词表内容（v0，冻结基线）

权威来源为 `config/classification_terms.txt`（运行时可扩充，见 6.3）；v0 共 6 词：

`机密★`、`秘密★`、`绝密`、`内部资料`、`注意保密`、`不得外传`

### 6.2 匹配机制与处置（已实现，可在代码复核）

- 加载：`recognizers/rule/detect.py` 的 `load_classification_terms()`——一行一词、`#` 注释；文件缺失或为空时回退内置兜底词表 `DEFAULT_CLASSIFICATION_TERMS`（与 v0 六词一致）；
- 匹配：原文**逐词子串**匹配（区分写法，含 `★` 等符号），每个命中产出一条 `type=CLASSIFICATION_MARK` 的 Finding；
- 处置：`action_hint=BLOCK_FLAG` → 路由 **BLOCK**（返回保密提示，403 语义；§5.2 矩阵第一行），mock 链路中上游不得收到该请求。

### 6.3 扩充纪律

- 词表扩充只改 `config/classification_terms.txt`（新增行），**不改词的既有匹配语义**；扩充后必须同步本 §6.1 清单并重跑 `evals.t0_labels`（其断言"文档 ⊇ 当前词表"）；
- 兜底词表 `DEFAULT_CLASSIFICATION_TERMS` 仅在词表文件缺失/为空时生效，保持与 v0 六词一致；扩充词不进兜底（避免代码随词表漂移）。

### 6.4 概念区分与背景声明

- **密级标识（CLASSIFICATION_MARK）**：v0 口径下，国家秘密密级字样（`绝密/机密★/秘密★`）与内部资料警示语（`内部资料/注意保密/不得外传`）**一律 BLOCK**——这是 §5.2 冻结矩阵的明确口径（矩阵示例行原文即含"内部资料 注意保密"），不是实现偏差。
- **工作秘密（WORK_SECRET）**：语义上指不属于国家秘密、但不宜公开的工作事项，契约上路由 **GOVCLOUD** 而非 BLOCK。如未来需要把部分警示语从 BLOCK 降级为 GOVCLOUD，属"词表拆分 + 矩阵增补"的契约增补事项，走变更纪律（§10）。
- 背景（常识性，**本文未核对法律/公文格式标准原文**，词表匹配不依赖之）："绝密/机密/秘密"三级为我国国家秘密的法定密级划分；`★` 为公文密级标志的常见排印形式。词表按**字面**匹配，不解析密级期限等扩展写法（见 §9-6）。

## 8. 占位符中文标签

- 形态：`〔中文标签·hex8-10〕`，例：〔人名·7f3a2b1c〕；中文标签取 §3 表"中文标签"列（`EntityClass.label`），生成与还原算法见 §5.3.1（`masking/mapper.py` / `masking/remap.py`）；
- 标签**全表唯一**（19 类互不相同，由 `evals.m0_infra` 断言）；占位符正文中只出现标签与摘要，不含原值；
- 流式还原状态机按 `〔标签·hex〕` 形态识别（≤32 字符缓冲），因此标签用词变更会破坏历史会话还原——**标签字符串与常量值同样冻结**。

## 10. 变更纪律

1. **契约只增不改名**：`EntityClass` 常量值、中文标签、`SENSITIVE_ATTR_SUBTYPES` 值一经冻结不得改名/删除/改义；新增走追加。
2. **三方同步**：§3/§4 表 ↔ `recognizers/models.py` 常量 ↔ 本文示例，任何一方变更必须同一次提交内同步，`evals.t0_labels` 把关（存在性/结构/常量一致性/词表覆盖/不确定项标注五类断言）。
3. **词表扩充**：只改 `config/classification_terms.txt` + 同步 §6.1；兜底词表不随动（§6.3）。
4. 本文档位于 `docs/`，随公开仓导出；行文遵守公开仓卫生纪律（中性名、无上游项目名/许可证字样）。
