## 2. 总体架构

```
windev-01（编排+CPU 链路）                    anolis-gpu-01（2×V100S-32GB）
┌──────────────────────────────┐            ┌────────────────────────────────┐
│ pipeline/ (Python 3.12 venv) │            │ gpu-services/ (FastAPI, 常驻)   │
│  cli.py 任务编排(文件队列)     │  HTTP/SCP  │  :9001 asr-align (ASR+对齐+情绪) │
│  m1 预处理(ffmpeg)            │◄──tailnet──►│  :9002 tts      (dub-tts 主力) │
│  m2 OCR(本机CPU)              │            │  :9003 lip      (lip-fast/精)  │
│  m3 分离(本机CPU可选GPU)       │            │  :9004 mt       (mt-core 本地) │
│  m8 对齐/m9 混音/m11 字幕      │            │ gpu1([内网地址已脱敏]) 两卡分工:      │
│  m12 标识/m13 审校台/m15 指标  │            │  V100#0 = asr+mt+tts            │
│  mt 兜底: OpenAI 兼容 API 抽象 │            │  V100#1 = lip（大模型独占18G）   │
└──────────────────────────────┘            └────────────────────────────────┘
```
- 任务队列：**SQLite + 文件目录**（`jobs.db` + `jobs/<ep>/...`），不用 Redis/Docker。
- GPU 调用：统一 `GpuClient`（HTTP POST 文件→JSON/文件），GPU 侧常驻 tmux 会话，结果 scp 回拉或直接 HTTP 返回（≤100MB 音频直接回传）。
- 翻译双通道：本地 mt-core（GPU）为主，OpenAI 兼容 API 抽象层为兜底（key 由主会话注入 env，不落盘）。

## 4. 模块 spec + eval（M1–M15）

> 每模块验收 = `tests/test_mx.py`（pytest）或 `scripts/eval_mx.sh`，全部真实可跑。
> 标注【本机】= windev CPU 可验收；【GPU】= anolis-gpu-01 上验收。
> eval 通过线是**冻结契约的一部分**，改行为先改 eval。

### M1 摄取与预处理 【本机】
- Spec：任意输入 → 1080×1920/25fps H.264 + 16k 单声道 wav + 48k 立体声 wav；`ffprobe` 元数据回写 `01_media/probe.json`。
- CLI：`python -m pipeline.m1_ingest --ep ep01 --in clips/ep01_raw.mp4`
- Eval：`pytest tests/test_m1.py::test_ingest`：输出存在；`ffprobe` 断言分辨率/fps/采样率；时长差 ≤0.2s。
- 依赖：ffmpeg 6.1.1（已装，含 libass/fribidi/harfbuzz，已核实）。

### M2 硬字幕 OCR + OCR↔ASR 校对 【本机】
- Spec：PaddleOCR(PP-OCRv5/v6 mobile) 按帧采样（每 0.2s，字幕变化处合并去重）→ `ocr_raw.jsonl`；与 M4 的 ASR 按时间重叠≥60% 做对齐投票：**OCR 置信 ≥0.9 时以 OCR 为准，否则 ASR**；产出口径写进 C2 `ocr.agree`。
- CLI：`python -m pipeline.m2_ocr --ep ep01`（依赖 M1、M4，可先用纯 OCR 跑）
- Eval：`pytest tests/test_m2.py`：自拍样片 OCR 文本与人工标注 20 条 CER ≤5%；字幕起止时间误差 ≤0.3s（90% 命中）。
- 上游：PaddleOCR（中性名 cap-ocr）。Windows py3.12：`pip install paddlepaddle paddleocr`（CPU 版）。

### M3 人声/背景分离 【本机（CPU 慢速可用）/GPU 可选】
- Spec：audio-separator 载入 mel-band-roformer karaoke 模型（SDR 12.98 默认）→ `vocals.wav` + `bgm.wav`；默认 CPU 分块处理，`--device cuda` 走 GPU。
- CLI：`python -m pipeline.m3_separate --ep ep01 [--device cpu|cuda]`
- Eval：`pytest tests/test_m3.py`：①输出存在且时长=输入；②人声段 RMS 在有声区间 ≥ 总轨 RMS-6dB、在纯 BGM 区间 ≤-15dB（用 M2 字幕区间当真值）；③60s 素材 CPU 处理 ≤10 分钟（记录实测）。
- 上游：nomadkaraoke/python-audio-separator（中性名 audiosplit）。备选 Demucs(MIT)。

### M4 ASR + 逐字对齐 + 情绪/事件 【GPU】
- Spec：服务 `:9001`：输入 16k wav → ①Qwen3-ASR-1.7B(-hf) 转写（fp16+SDPA，**不用 vLLM/FA2**）；②Qwen3-ForcedAligner-0.6B 用"ASR 文本+修正文本"输出字级时间戳；③SenseVoice 输出 7 类情绪标签+事件（哭/笑/掌声/叹气）；④非语言事件占比高的句子标记 `nonverbal`。**阿语对齐降级**：ForcedAligner 不支持 ar → 按字符比例线性内插（MVP），wav2vec2-CTC 对齐列 post-MVP。
- CLI：`python gpu-services/asr_align/service.py --port 9001`；客户端 `python -m pipeline.m4_asr --ep ep01 --gpu asr`
- Eval【GPU】：`bash scripts/eval_m4_gpu.sh`（ssh 到 [内网地址已脱敏] 执行）：自拍样片 10 句与人工稿 WER ≤8%；字级时间戳抽查 30 字，|Δstart|≤100ms 占比 ≥85%；情绪标签与人工标注一致率 ≥70%；整体延迟 ≤0.5×实时（V100 单卡，记录实测）。
- Volta：0.6B/1.7B fp16 显存约 4–8GB，SDPA 路径避开 FA2；若 transformers 新版 SDPA 在 sm_70 自动回退 math-attention 导致过慢 → 锁 torch 2.3–2.5 区间（D1 实测定版）。

### M5 镜头切分 + 说话人区分 + 角色绑定 + 正脸近景判定 【GPU+本机混合】
- Spec：①TransNetV2 → `shots.json`（本机可跑，小模型）；②CAM++（3D-Speaker，ModelScope 免 gate）说话人嵌入聚类（谱聚类，说话人数 upper-bound=角色数+1）→ `diar.jsonl`；③Light-ASD 判定每镜头在说话人 + MediaPipe 头部姿态（pitch/yaw 阈值 ±25°）+ 人脸框高度 ≥1/4 画幅 → 写 C2 `face.frontal/closeup`；④人工只做一次：给每角色挑 10–15s 干净参考音色入 `voicebank/`，绑定 `char_id`（审校台辅助）。
- CLI：`python -m pipeline.m5_diar --ep ep01`（内部调 GPU :9005 diar 服务或本机 CPU 小批量）
- Eval：`pytest tests/test_m5.py`（本机）：多人样片 3 说话人，DER（人工对齐粗评）≤15%；`face` 标记与人工逐镜标注一致率 ≥80%。
- 上游：3D-Speaker(Apache-2.0)、Light-ASD(MIT)、TransNetV2(MIT)、MediaPipe(Apache-2.0)。pyannote community-1 为可选对比（权重 gated，需要 HF 账号接受条款）。

### M6 整集上下文翻译 + 时长预算 【GPU + API 兜底，本机验收】
- Spec：①通读全部 C2 → 生成/校订 `characters.json`（关系、称谓、专有名词、术语表 `terms`）；②逐句翻译：输入=全剧角色卡+前后 2 句+本句时长预算（按 Hy-MT2 结构化模板传 `[背景信息]` 与术语），输出 3–5 个候选；③音素化估长（pypinyin/cmudict/es G2P/阿语简化音节法 + `models/syl2dur.json` 拟合表，见 training-plan §2）→ 每候选 `est_dur`；④标记 in-budget 候选排序规则（质量分优先、预算内优先）。本地 mt-core(Hy-MT2-1.8B, GPU :9004) 为主，OpenAI 兼容 API 抽象层兜底（同一接口 `MTBackend.translate()`）。
- CLI：`python -m pipeline.m6_translate --ep ep01 --lang en [--backend local|api]`
- Eval：`pytest tests/test_m6.py`：50 句测试集 ①术语命中率 100%（角色名/专名按 terms 渲染）；②预算内命中率 ≥55%（未训 DubMT 的基线，DubMT 后目标 ≥75%）；③大模型评分（1-5）≥3.8；④超预算句 100% 进入 M8 换译流程。
- Volta：1.8B fp16 ~5GB。API 兜底保证本机无 GPU 也可全流程开发。

### M7 TTS 情绪迁移合成 【GPU】
- Spec：服务 `:9002`：按 C5 合成——`voice_ref`=角色音色库参考，`emo_ref`=原片该句人声（**音色与情绪参考可来自不同人，这是情绪迁移的核心用法**），`emo_alpha` 按情绪强度（SenseVoice score 映射 0.5–0.85），`duration_factor` 初值 1.0；哭/尖叫等 `nonverbal` 句直接复制原人声段。引擎：dub-tts（IndexTTS-2.5，zh/en/ja/es/ar）；es 备选 alt-tts-a（Qwen3-TTS-1.7B-CustomVoice）；其他语种 alt-tts-b（VoxCPM2）。**Volta 注意：IndexTTS-2.5 默认 bf16，启动参数强制 fp32/fp16 试验路径（D1 定案），不行则降级 IndexTTS-2(fp16，但只有 zh/en) → 再不行 es 用 Qwen3-TTS、ar 用 VoxCPM2**。
- CLI：`python gpu-services/tts/service.py --port 9002`；`python -m pipeline.m7_tts --ep ep01 --lang en`
- Eval【GPU】：`bash scripts/eval_m7_gpu.sh`：20 句 ①全部产出且时长写入 plan；②音色相似度（CAM++ 嵌入 cosine）≥0.70 vs voicebank 参考；③情绪标签回判（SenseVoice/情绪模型）一致率 ≥70%；④RTF 记录（V100 单卡）。
- 许可：bilibili 模型使用协议——商用免费，月活>1亿/年营收>10亿需授权；保留 LICENSE 副本（内部使用+比赛演示无碍）。

### M8 时长对齐 【本机】
- Spec：合成后实测时长 `meas_dur`：①`lo ≤ meas ≤ hi` → 通过；②超长/过短 → `duration_factor ∈ [0.9,1.1]` 二分搜索重合成（≤3 次）；③仍超长 → 调 M6 请求"更短换译"（把超长量作为硬约束重翻，候选取最短合格者）；④`ffmpeg atempo` 只做 ≤±5% 的最终微调（防止音调失真）。
- CLI：`python -m pipeline.m8_align --ep ep01 --lang en`
- Eval：`pytest tests/test_m8.py`：全片时长对齐率（±10% 命中）≥70%（DubMT 前）/≥80%（DubMT 后）；平均语速调整幅度 ≤1.06；atempo 使用占比 ≤30%。
- 上游：无外部依赖，纯编排。这是 DubMT 的消费方，接口即 C4。

### M9 混音 【本机】
- Spec：`bgm.wav`(M3) + `dubbed.wav`(M7 串接，句间隙保留原时间轴) → ducking（bgm 侧链 -6dB，句内再 -3dB）→ 48k 立体声 `mix.wav`；响度归一 EBU R128 `-16 LUFS`（短剧平台惯例）。
- CLI：`python -m pipeline.m9_mix --ep ep01 --lang en`
- Eval：`pytest tests/test_m9.py`：时长差 ≤0.2s；loudnorm 报告 I∈[-17,-15]；人声段/bg 峰值比 ≥8dB（对白可懂度）。

### M10 按镜头分流口型 【GPU】
- Spec：按 C6 分流：合格镜头 → lip-fast（MuseTalk 1.5，256×256，V100 官方 30fps+，主力）或 lip-pro（LatentSync 1.6，512×512，18GB，V100#1 独占，只给重点镜头）；不合格镜头原画；漫剧/无脸镜头自动跳过；输出逐镜回贴 → `09_lip/done/*.mp4`。
- CLI：`python gpu-services/lip/service.py --mode fast|pro --port 9003`；`python -m pipeline.m10_lip --ep ep01 --lang en [--pro-shots s0007,s0012]`
- Eval【GPU】：`bash scripts/eval_m10_gpu.sh`：抽 10 个口型镜头 ①嘴区无中文残影（人工抽检表）；②SyncNet LSE-C（用 lip-pro 自带 syncnet 权重）处理后 ≥ 处理前；③lip-fast 单镜 RTF ≤1.0（V100 实测记录）；④非合格镜头 100% 未被改动（帧哈希对比）。
- 许可：MuseTalk MIT（权重可商用）；LatentSync Apache-2.0。**Wav2Lip 非商用，禁用**。
- Volta：MuseTalk 官方 V100 验证过（低风险）；LatentSync 1.6 SD-UNet fp16 理论可跑，**D1 冒烟**，失败降级 v1.5（8GB/256px）或全量 lip-fast。

### M11 字幕擦除 + 目标语渲染 【本机】
- Spec：①擦除：video-subtitle-remover CLI（inpaint=LAMA 默认，STTN 备选），擦除区域=M2 检出的字幕带 bbox 外扩 4px，**注意：AI 标识区域（见 M12 位置常量）必须排除在擦除掩码外**；②渲染：生成目标语 ASS（en/es 左下、ar 右对齐 RTL；字体 Noto Sans/微软雅黑/Noto Naskh Arabic），`ffmpeg -vf ass=` 压制（本机 ffmpeg 已含 libass+fribidi+harfbuzz，已核实阿语 shaping 可用）。
- CLI：`python -m pipeline.m11_subs --ep ep01 --lang ar [--skip-erase]`
- Eval：`pytest tests/test_m11.py`：①擦除后重跑 M2 OCR：中文字符命中=0（3 段素材各一遍）；②AI 标识区像素 diff=0（擦除前后裁剪区哈希一致）；③ar 字幕：渲染后抽帧人工核对 5 帧 RTL 方向与字母连接正确（libfribidi 生效）；④60s 素材擦除+渲染 ≤40 分钟 CPU（记录实测；GPU 机 VSR CUDA 12.8 包可加速为备选）。
- 上游：VSR Apache-2.0（GitHub API 核实）；注意其内嵌 inpaint 权重条款逐个记录（默认 LAMA，Apache-2.0 系）。

### M12 合规报告 + AI 标识 【本机】
- Spec：①显式：片头 3s 文字提示（drawtext，位置常量 `configs/pipeline.yaml: label_zone`，默认顶部居中）+ 报告记录；②隐式：按 GB 45438-2025 把 `服务提供者+内容编号` 写入 MP4 元数据（`ffmpeg -metadata` + XMP 自定义字段）；③C2PA：c2patool 给成片注入 manifest（claim=生成工具、时间、content_id）；④音频水印：AudioSeal 嵌 16-bit 负荷（content_id hash）后随混音封装；⑤合规报告：`markets/*.yaml` 规则（亲密/暴力/宗教词表）×（C2 文本 + Qwen3-VL 抽 8 关键帧[可选]）→ findings + 建议 + 人工复核清单；⑥附**标识验证工具** `python -m pipeline.verify_label <mp4>`（读 ffprobe 元数据 + c2patool 校验 + AudioSeal 检测，三项全绿输出 PASS）。
- CLI：`python -m pipeline.m12_label --ep ep01 --lang en --market en-US`
- Eval：`pytest tests/test_m12.py`：①verify_label PASS（元数据字段值精确匹配、C2PA manifest 校验成功、AudioSeal bit-error ≤2/16）；②ar-SA 报告：往测试集塞 2 条亲密镜头规则命中，自动标出且给建议；③去标识攻击冒烟：重编码一次后 AudioSeal 仍检出（bit-error ≤4）。
- 上游：AudioSeal(MIT 含权重)、c2patool(MIT/Apache)。

### M13 审校台 Web 【本机】
- Spec：FastAPI + SQLite + 原生 JS 单页（无构建链）。功能：视频预览+当前句高亮跳转；逐句改译文/改情绪/改语速；单句"重生成"（走 M6→M7→M8→M9 单句管线，≤60s 返回）；角色表/术语表编辑（回写 C3）；最终"导出"（M11+M12+打包 MP4+SRT/ASS+合规报告）。内网使用，无鉴权。
- CLI：`python -m pipeline.review_server --jobs jobs --port 8080`
- Eval：`pytest tests/test_m13.py`（httpx 测试客户端）：①改一句译文→regenerate→导出片段中该句音频变化（波形哈希不同）且其余句不变；②术语表修改后新译文 100% 用新术语；③并发 5 请求无锁死。手工验收：手机浏览器内网可操作。

### M14 任务队列与编排 【本机】
- Spec：SQLite 表 `tasks(ep, module, state, deps, artifact)`；`cli.py run ep01 --to m12` 按依赖图调度（本地进程池 + GPU 调用走 GpuClient）；断点续跑（artifact 存在且 eval 过则跳过）；每步耗时入 `metrics.db`（供 M15 成本核算）。
- Eval：`pytest tests/test_m14.py`：人为 kill 一个步骤后重跑，从断点继续；依赖未满足时拒绝执行。

### M15 指标体系 【本机+GPU】
- Spec：`python -m pipeline.m15_metrics --ep ep01 --lang en` 输出 `12_out/metrics.json`：
  | 指标 | 测法 | 通过线（MVP） |
  |---|---|---|
  | 说话人相似度 | CAM++ 嵌入 cosine(合成句 vs voicebank 参考) | ≥0.70 |
  | 情绪相似度 | SenseVoice 回判一致率 | ≥0.70 |
  | 回听 WER | 目标语 ASR（Qwen3-ASR 多语/whisper-large-v3 备选）转写合成音 vs 译文 | ≤8% |
  | 时长对齐率 | ±10% 命中占比 | ≥70%（DubMT 后 ≥80%） |
  | 口型质量 | SyncNet LSE-C 变化 + 人工 10 镜抽检表 | LSE-C 不降 + 抽检通过 |
  | 每分钟成本 | metrics.db 汇总：GPU 时×单价 + API 费 + 墙钟时间 | 报告值（对标市价 ~50 元/分） |
- Eval：对自拍 ep01 跑全量，`metrics.json` 六项齐全即过（数值本身进演示页）。

## 8. 演示素材自拍方案（3 段，D1 拍摄）

器材与授权见 `hardware.md`。统一竖屏 1080×1920（或 4K 后期缩）、25/30fps、室内安静、领夹麦收音、每段录 2 遍保底。**演员=团队成员本人，现场签声音/肖像授权书（模板见 hardware.md §4）。**

### 素材 A：双人争吵近景（60–90s，主演示）
- 场景：办公室/客厅，两人正脸近景对切（手机固定机位拍双人，再补单人近景机位各一）。
- 台词要点：情绪跨度大（质问→怒吼→哽咽），长句短句混合（测时长对齐），含 2 个专有名词（测术语），1 处哭腔+1 处冷笑（测情绪迁移），1 处拍桌巨响（测分离与事件保留）。
- 台词示例（正式拍摄前定稿 12–16 句）：
  1. "你到底想怎么样？把话说清楚。"（短，质问）
  2. "三年了，程氏的项目、老城的基地，哪一样不是我亲手做起来的？"（长，压抑）
  3. "那你就可以这样对我吗！"（怒吼）
  4. （哽咽）"……我以为你至少会信我。"（哭腔 → nonverbal 边界测试）

### 素材 B：多人群戏（60–90s）
- 场景：会议室，3–4 人围桌争执，固定全景+两人近景。目的：说话人区分、重叠语音、active speaker。至少 2 处两人同时开口。
- 要点：每人音色区分度尽量大（男女搭配）；台词各自带立场（"预算超了""档期不能动""客户明天就要"）。

### 素材 C：海南题材（90–120s，讲好故事展示）
- 场景："东坡渡海"微剧：室内书案场景（古装布景从简：木桌、宣纸、茶壶），旁白+祖孙对话。
- 结构：旁白 2 句（绍圣四年，东坡渡海）→ 祖孙问答 6 句（"为什么要走？""海南孤岛，也有明月。"）→ 收尾旁白 1 句。专名：东坡、琼州、儋州（术语表演示）。
- 目的：呼应省旅文厅"讲好故事"，BGM（古琴垫乐后期叠加）测混音分离，展示文旅宣传片泛化能力。

### 中文硬字幕压制（短剧风格：白字黑边大号，底部安全区）
方式一（推荐，先写 ASS 再烧录，`scripts/make_demo_subs.py` 自动从台词表生成）：
```bash
ffmpeg -i clips/ep01_raw.mp4 -vf "scale=1080:1920,ass=clips/ep01_zh.ass" \
  -c:v libx264 -crf 18 -preset medium -c:a aac -b:a 192k clips/ep01_60s.mp4
```

```ass
[Script Info]

[V4+ Styles]
Style: ZH,Microsoft YaHei Bold,62,&H00FFFFFF,&H000000FF,&H00000000,&H80000000,-1,0,0,0,100,100,0,0,1,3,2,2,60,60,220,1
[Events]
Dialogue: 0,0:00:01.20,0:00:03.40,ZH,,0,0,0,,你到底想怎么样？把话说清楚。
```

方式二（单条 drawtext 示例，快速压制）：

## 11. 对外发布纪律（贯彻到代码注释与 README 模板）

- 未来公开仓：不出现任何上游项目名/许可证声明，全部用中性名（映射表见 `oss-manifest.md` 附录A）；`models.yaml` 公开版只写"权重文件名+SHA256+下载占位符"，由法务统一处理引用声明。
- 训练一律延后：DubMT 只交付数据合成与训练脚本设计（`training-plan.md`），推理链路全部用现成开源权重跑通。
- 演示与成片：所有合成声音的角色必须能出示 `05_cast/consent/` 授权记录；路演材料主动讲授权与标识机制。
