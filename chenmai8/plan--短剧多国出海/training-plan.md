# DubMT 训练计划（延后执行；10 天内只做数据+脚本+评测设计）

> 原则：**训练一律延后**（开发指令 §11）。10 天内交付：数据合成管线跑起来、500 句评测集冻结、
> 训练脚本设计定稿（D6 可选试跑一轮）；正式训练在复赛前 5 周窗口执行。
> 方向：isochrony/isometric MT（时长可控配音翻译），中→英/西/阿，短剧台词域。
> 概念文档核实：该方向无针对中文短剧的开源实现（保留判断：学界有 isometric MT 工作，我们做的是"数据合成+LoRA+音素估长"的工程化组合，差异化在域与评测）。

## 1. 数据合成（D1 启动后台，D6 收尾）

### 1.1 合成规模与分布（目标 2–5 万句，首版 2 万）
| 维度 | 取值 |
|---|---|
| 语向 | zh→en、zh→es、zh→ar（比例 5:3:2，en 优先保证 DubMT-en 复赛可用） |
| 剧情域 | 霸总/复仇/豪门/甜宠/悬疑/宫斗/文旅宣传（海南题材单列 5%） |
| 情绪 | 8 类（对齐 dub-tts 情绪表）均衡采样 |
| 句长 | 4–30 词（中文 6–40 字），短句(≤8字)占 30%（时长对齐最难处） |
| 上下文 | 每句带前后各 1–2 句（训练输入含 context 字段） |

### 1.2 合成方法（强模型生成，脚本 `pipeline/datagen/`）
1. **种子台词**：以 3 段自拍素材台词 + 人工扩写 200 句为 style anchor；不抓取任何在版权益不明的剧集字幕（合规红线，只用自写+OpenSubtitles 公开语料，见 1.5）。
2. **批量生成**：强模型（OpenAI 兼容 API，主会话供 key）按"题材×情绪×句长"网格生成中文台词，每 prompt 20 句+约束（口语句式、语气词、专有名词占位符）。
3. **多候选译文**：每句让强模型写 **3–5 个长短不同**的合格译文（明确要求：意思等价、口播自然、长度从最短到最长覆盖 ±25% 区间），附上下文与术语表。
4. **清洗**：去重（minhash）、长度异常剔除（|dur_est−orig|>30% 全剔）、乱码/占位符残留检测。

### 1.3 音素时长估算（不合成全部候选的关键）
- 音素化：zh=pypinyin 声韵母计数；en/cmudict+es=phonemizer(epitran)；ar=简化音节法（CV/CVC 计数）。
- **拟合表** `models/syl2dur.json`：用 dub-tts 实际合成 ~2000 句（三语各 ~700，覆盖语速窗 0.9–1.1、8 情绪）回归"音素/音节数+情绪+语速 → 时长"；拟合 MAPE 目标 ≤8%。
- 复用：M6 的候选估长也用同一张表（推理期与训练期一致，消除 train/serve skew）。

### 1.4 训练样本构造
- 输入：`<ctx_prev> {src} <ctx_next> <budget_lo> <budget_hi>`（预算换算成目标音节数区间更稳：`<target_syl_lo/hi>`）；输出：挑选出的候选译文（时长偏差 ≤±10% 且质量达标者；多候选则按时长加权采样以教模型"按预算伸缩"）。
- 质量过滤：强模型自评 1–5 ≥4 且时长合格；每语向保留比例自适应（不够就放宽到 ±12%）。

### 1.5 公开数据增强（先核许可再入库）
- OpenSubtitles v2018 中→英/西/阿平行句对（OPUS）：**核对许可/引用要求后**再混入 ≤20%（只取 ≤30 词对白式短句，脚本 `datagen/fetch_opus.py` 输出许可声明存档）。
- FLORES-200（CC-BY-SA？以官网为准）：只用于**评测**通用能力不退化，不入训练。

## 2. LoRA 训练脚本设计（Hy-MT2-1.8B 基座）

> 基座核实：`tencent/Hy-MT2-1.8B`，Apache-2.0，33 语种，术语/上下文/结构保留模板（模型卡核实）。
> 官方有 LLaMA-Factory 微调说明（HY-MT 系），两条路线二选一，**首选 A（依赖少、Volta 稳）**。

### 路线 A：peft+transformers 自写脚本（首选）
- `training/train_isomt.py`：
  - 加载 fp16（**Volta 无 bf16：`torch_dtype=float16`，禁用 bf16 相关 flag**；SDPA attention）；
  - LoRA：r=16, alpha=32, dropout=0.05, target=q,k,v,o,gate,up,down（1.8B 全线性层代价可接受）；
  - 数据：JSONL→collator，max_len=512；loss 仅对译文 token；
  - 超参：bs(per_device)=8 × grad_accum=4（等效 32），lr=1e-4 cosine，warmup 3%，2–3 epoch；
  - 显存估：1.8B fp16 + LoRA + bs8/len512 ≈ **14–20GB**（V100S-32GB 单卡余量足；开 gradient_checkpointing 稳妥）；
  - 输出：`isomt-lora-<lang>` 三个适配器（en/es/ar 各一）+ merge 脚本。
- 训练时数估算（2×V100S）：2 万句 ×3 epoch ≈ 6 万步样本 → 单卡约 **4–6 小时/语向**；三语向并行双卡约 1 天内完成（含评测合成）。

### 路线 B：LLaMA-Factory（备选）
- 若 A 遇到 tokenizer/chat template 坑，切 LLaMA-Factory yaml 配置（Hy-MT 官方文档路径），注意其默认 bf16 → 改 fp16。

### 训练验收（`training/eval_after_train.py`）
1. 训练 loss 收敛且无跳变（记录曲线）；
2. FLORES-200 抽 500 句 zh→{en,es,ar}：chrF 相对基座下降 ≤2 点（通用能力不退化闸门）；
3. §3 评测三项达标（见下）。

## 3. 评测设计（500 句冻结测试集，D6 定稿；D6 前用 200 句开发集）

### 3.1 测试集
- 从自拍素材台词+人工新写台词中取 500 句（按 §1.1 同分布），**永不入训练**；人工标金标：至少 1 条人工理想译文 + 时长预算。

### 3.2 三项主指标（vs 基座 Hy-MT2-1.8B 对照组，同一 TTS、同一评测器）
| 指标 | 测法 | 通过线 |
|---|---|---|
| **±10% 时长命中率** | 译文经 syl2dur 估算+实际 TTS 合成实测，|dur−orig|/orig ≤10% 占比 | 基线≥55% → **DubMT ≥75%**（+15pt 起步） |
| **平均语速调整幅度** | M8 日志汇总 `duration_factor` 偏离 1.0 均值 | ≤1.06（基线 ≤1.15） |
| **翻译质量** | COMET（wmt22-comet-da，HF 下载）+ 强模型 1–5 打分双轨 | COMET 不低于基座 −1 分内；LLM 分 ≥3.8 |
辅助：FLORES chrF（见 §2）、音色/情绪指标不受训练影响（回归验证一遍 M7 eval）。

### 3.3 评测命令（GPU 机）
```bash
ssh root@[内网地址已脱敏] 'cd ~/engine && bash training/run_eval.sh isomt-lora-en base --set test500 --langs en'
# run_eval.sh 内部: 批量翻译(预算条件) → syl2dur 估长 → dub-tts 合成500句 → 实测时长
#   → whisper 回听WER(辅助) → COMET 打分 → 输出 metrics_train.json 与基线对比表
```

## 4. GPU 时数预算（2×V100S-32GB）
| 阶段 | 用时 | 卡 |
|---|---|---|
| syl2dur 拟合数据合成（2000 句 TTS） | 2–3 h | 1× |
| LoRA 训练（三语向） | 12–18 h | 2×（并行语向） |
| 评测合成（500×3 语向 ×2 模型） | 4–6 h | 1× |
| COMET/回听 | 1 h | 1×（或 CPU） |
| 合计 | **约 20–28 GPU 时** | 复赛前周末 1–2 天可完成 |

## 5. 里程碑对齐（与开发指令 §6 呼应）
- D1：数据合成 prompt 模板+脚本上线，后台跑；dub-tts 冒烟后立刻启动 2000 句 syl2dur 拟合合成（挂 GPU 空闲时段）。
- D3–D5：合成数据陆续落盘；每晚跑清洗+估算，产出训练 JSONL。
- D6：**冻结 500 句测试集**（硬里程碑）；基线评测跑完（基座对照组数据必须有——即使训练延后，对照值也要拿到）；时间允许则试训 en 语向一轮。
- 赛后复赛窗口：全量训练 + 评测 + 权重与规则包按开源节奏发布（获奖后）。

## 6. 风险
- 强模型生成质量不稳：每批抽 5% 人工抽检，低于 90% 合格率换 prompt/模型；
- Volta fp16 训练数值不稳：loss scale 动态调整已有（torch AMP 默认）；仍不稳则 bs 减半+grad_accum 翻倍；
- COMET 模型（XLM-R 系）在 V100 加载：fp16 约 2.5GB，可行；不行换 CPU 跑（慢但一次性）；
- OpenSubtitles 许可核查不过：直接砍掉，不阻塞（合成数据自足）。
