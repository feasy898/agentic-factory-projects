# M5 素材处理 —— 构建时函数说明（暂缓独立成管线）

> 重组说明：M5 由"素材管线模块"降级为**构建时的一个函数**。当前无任何生产调用方（三消模板用程序化贴图，
> 零外部素材），按资产纪律**不写可重生 spec**，只有本页边界说明。

---

## 1. 职责（目标态）

读入用户/开源授权素材目录，产出可直接进包的优化素材：

- 压图（无损/有损，Node 图像库）；
- 音频转低码率（ogg/m4a，需本机 ffmpeg）;
- 字体子集化（按 spec `i18n.strings` 实际字符集裁剪，含 RTL/东亚字形；输出 ≤40KB 量级 woff2）；
- 简单 shelf 图集打包（自研，输出 `atlas.json` 供模板加载）。

素材纪律（红线）：**素材仅来自公开授权（CC0/OFL）或用户提供**；每个素材包的许可文件随包留档
（`assets-cc0/` 目前为空目录，如实记录）。

## 2. 为何暂缓

- 三消模板当前**零外部素材依赖**（程序化贴图 + 内置 WAV，见 match3-rules-card §10–§11）——管线没有调用方；
- 演示主路径的"评委输入看得见"只差**一个文件替换**（一张用户 PNG 替换一个棋子），不需要压图/字体/图集全家桶；
- 规划中的验收线（总字节下降 ≥30%、字体子集 ≤40KB、atlas 可被模板加载）属于后续规模化目标，不是演示线。

## 3. 触发条件（满足其一才开工）

1. 第二个模板或演示需要真实外部素材进包；
2. "评委给的输入能改变画面"需要超出单文件替换的能力；
3. 包体逼近渠道上限、必须靠压图/图集救体积。

## 4. 开工第一步（最小函数形态）

`process_one_png(src_path, out_path, max_bytes?) -> {bytes_before, bytes_after}` ——读一张用户 PNG、
写入包体可用的优化 PNG；由模板构建或打包器直接调用。**注意 Windows 中文路径**：图像库选型须支持非 ASCII
路径（cv2 系 API 会失败，需 `np.fromfile + imdecode` 规避——本仓库路径含中文，这是实测坑）。
等第二条流水线真的调用它，再把本页升级为完整 spec（含 atlas.json schema 与音频/字体验收）。
