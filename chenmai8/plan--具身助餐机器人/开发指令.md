## 0. MVP 定义与成功判据

**MVP = 一台桌面主从臂系统，能在桌面场景完成"舀一勺 → 确认勺上有食物 → 送到用户嘴前 5cm → 用户咬走 → 撤回 → 记录一口"的闭环，且语音可打断、转头即停、看板可查。**

无硬件成功判据（D2 晚必须达成，演示给主人看）：
1. 仿真里全流程 mock 跑通（30 次模拟进食 0 安全违规）；
2. 普通摄像头（手机录制视频亦可）口部三维估计 + 张嘴/转头检测跑通；
3. 语音四指令识别跑通（CPU 离线）；
4. 护理看板记录 30 口数据并展示。

有硬件成功判据（D6-D8，v3 硬件：单从臂，无深度相机）：**脚本/参数化舀取（腕部相机闭环+失败重试）每食物 50 次最终成功率 ≥90%，首次成功率 ≥70%（两项分开报告）**；送达误差 ≤1.5cm（mono+静态先验标定下）；100 次送达 0 次进入禁入区。ACT 学习路径整体延后（training-plan.md），不是 MVP 判据。

**明确不做**：喂面条和汤、吞咽障碍人群、重度认知障碍、卧床喂食、学习型舀取与语言条件大模型策略（ACT/SmolVLA/π0.5 全部延后，仅延后叙事不承诺）。

## 1. 总体架构

```
交互层   cs_voice（ASR/意图/TTS）  +  软件急停（空格键，无急停硬件）  +  张嘴触发（cs_mouth）
编排层   cs_orchestra（行为树）：选碗→舀取→勺上检查→送达→等咬合→撤回→记录
感知层   cs_mouth（口部三维，mono 主路径，支持腕部双职模式）+ cs_food（勺上检查/选碗）
         + 顶部相机（全程场景：碗/食物/ArUco）+ 腕部相机（双职：勺上检查→送达阶段切口部追踪），无深度相机
执行层   cs_arm（FeetechArm 单从臂 / MockArm + SafetyEnvelope 限速/禁入区/软件急停/看门狗）
仿真层   cs_sim（MuJoCo + URDF + IK + 可达空间 + 安全包络验证）
数据层   cs_dashboard（FastAPI + SQLite 看板）← 口数/时长/摄入克数
契约层   cs_schema（所有跨模块数据结构，唯一事实来源）
```

数据流（每口一次）：
`行为树 tick(50Hz) → cs_arm.read() → cs_mouth(口部坐标/状态) → 决策 → ArmCommand(经 SafetyEnvelope) → 执行 → cs_food(勺上检查) → cs_dashboard(BiteRecord)`。
相机流另路推送 Rerun（调试）与 cs_dashboard（快照）。所有跨模块消息经 `cs_schema` 定义；进程间先用同进程直调 + 黑板（py_trees blackboard），看板经 HTTP/SSE，**不引入 ROS**。

坐标系约定（冻结）：
- 机械臂基座系 `base`：X 前向（朝用户）、Y 左、Z 上，原点=从臂底盘中心，单位米/弧度。
- 相机系 `cam*`：OpenCV 约定（Z 前向）。`cam→base` 用 4×4 矩阵，存 `config/calib/handeye_<cam>.npz`（key: `T_base_cam`, `reproj_err_mm`）。
- 口部坐标一律输出为 `base` 系。**v3 起无深度相机：`z` 用先验距离，`source="mono"` 为演示主路径**；`depth` 后端保留为将来机构版高配（备查：届时买 Gemini 2 档即可，勿买 335 工业档），接口不变、无感切换。

相机角色约定（v3.1 腕部双职，冻结）：
- **顶部相机**：全程场景职责（碗位/食物/ArUco 选碗/兜底视角），不承担口部追踪。
- **腕部相机双职**：舀取阶段朝下看勺（cs_food 勺上检查+闭环）；行为树在"勺上检查通过→开始送达"转换时发相机角色切换事件，转为**口部追踪相机**——臂抬起伸向用户时镜头自然朝向面部，近距 20–50cm 人脸占满画面；撤回完成/急停切回场景角色。
- **近距单目估距**：瞳距先验（成人 IPD ≈63mm）——标定腕部相机内参 fx 后，Z = fx × 0.063 / ipd_px（ipd_px 取左右虹膜关键点 468/473 像素距）；近距精度优于远距固定先验，预期 ±2–4cm；固定先验模式保留为顶部相机回退路径（config/mouth_prior.json 的 mode 切换）。
- **口部→基座系换算**：`T_base_cam = T_base_flange(FK, 关节编码) × T_flange_cam(腕部手眼外参)`；手眼标定一次（eye-in-hand），不依赖顶部相机。

## 3. 冻结契约（接口 + 数据 schema）

### 3.1 cs_schema（全部 pydantic v2 BaseModel，JSON 可序列化，时间戳 ns）

| 模型 | 字段（类型） | 约束 |
|---|---|---|
| `MouthPose` | `ts_ns:int, valid:bool, x,y,z:float(米,base系), jaw_open:float(0-1), frown:float(0-1), head_yaw,pitch,roll:float(rad), source:Literal["depth","mono"], confidence:float(0-1)` | invalid 时 x/y/z 用上一有效值并 confidence=0 |
| `ArmState` | `ts_ns:int, joint_names:list[str](7), joint_pos:list[float](rad), joint_vel:list[float], ee_pos:list[float](3,base系,FK算出), ee_quat:list[float](4)` | 7 关节 = 6 臂 + 夹爪（SO-101 末关节即夹爪，统一进数组） |
| `ArmCommand` | `mode:Literal["joints","cartesian"], target:list[float], max_speed:float, timeout_s:float, frame:"base"` | 只能由 SafetyEnvelope 下发到底层 |
| `SafetyState` | `ts_ns:int, estop_latched:bool, human_zone_violation:bool, violation:Literal["none","face_in_zone","speed","torque","watchdog"], clear_to_move:bool` | violation!="none" → clear_to_move=False，直到显式 `reset()` |
| `SpoonCheck` | `ts_ns:int, has_food:bool, score:float(0-1), cam_ref:str` | 阈值在 config，可调偏保守（宁可重舀） |
| `VoiceIntent` | `ts_ns:int, intent:Literal["next","pause","resume","done","select","greet","unknown"], slots:dict(dish:str\|None), confidence:float` | select 的 dish ∈ 预注册菜名表 |
| `BiteRecord` | `bite_id:int, ts_start_ns:int, ts_end_ns:int, outcome:Literal["success","retry","rejected","aborted"], grams_before:float\|None, grams_after:float\|None` | grams 字段无称重硬件时为 None |
| `MealSession` | `session_id:str, user_id:str, started_ns:int, ended_ns:int\|None, bites:list[BiteRecord], total_grams:float\|None` | 看板唯一聚合单元 |

### 3.2 模块接口（冻结签名，允许内部重写，不允许改签名）

```python
# cs_sim
def load_arm(physics_model_path: str = "upstream 模型文件路径") -> cs_sim.ArmModel  # 加载并校验
class ArmModel:
    def fk(self, q: list[float]) -> list[float]                       # → ee_pos+quat
    def ik(self, target_pos: list[float], target_quat: list[float],
           seed: list[float] | None = None) -> list[float] | None     # 无解返回 None
    def reachable_map(self, grid) -> dict                             # 可达性体素统计
# cs_arm
class ArmInterface(ABC):
    def read(self) -> ArmState: ...
    def write(self, cmd: ArmCommand) -> None: ...
    def enable(self) / disable(self) -> None
class MockArm(ArmInterface): ...        # 在 cs_sim 中执行，含速度积分
class FeetechArm(ArmInterface): ...     # 真机（leobot feetech 通道封装）
class SafetyEnvelope(ArmInterface): ... # 包装任意 ArmInterface：限速/禁入区/急停/watchdog
def calibrate_handeye(cam, arm, points: list) -> tuple[np.ndarray, float]
    # v3.1：支持 eye-in-hand 模式（cam=腕部相机，板固定桌面、动臂采 N 位姿）→ 产出 T_flange_cam 存
    # config/calib/handeye_wrist.npz；eye-to-hand 模式（顶部相机）产出 handeye_scene.npz，用法不变
# cs_mouth
class MouthEstimator:
    def __init__(self, backend: Literal["mono","depth"] = "mono", prior: MouthPrior,
                 pose_provider: Callable[[], tuple] | None = None)  # v3.1 追加，None=现状不破坏在建代码
    def from_bgr(self, img: np.ndarray, depth: np.ndarray | None = None,
                 *, cam_pose: tuple | None = None) -> MouthPose
    # v3.1 向后兼容扩展（keyword-only 可选参数）：cam_pose = (T_base_flange, T_flange_cam) 即腕部双职模式；
    # 两者皆 None 时行为与 v3 完全一致（顶部固定先验）。G0–G1 在建代码无需改动。
# cs_food
class SpoonClassifier(Protocol):
    def from_bgr(self, crop: np.ndarray) -> SpoonCheck    # MVP 先启发式实现
# cs_voice
class VoiceLink:
    def start(self) -> None                                # 后台线程
    def poll(self) -> VoiceIntent | None                   # 非阻塞取最近意图
    def say(self, text: str) -> None                       # TTS
# cs_dashboard（HTTP 契约，冻结）
POST /api/session/start {user_id} → {session_id}
POST /api/bite      (BiteRecord)   → 204
GET  /api/session/current          → MealSession
GET  /api/stream                   (SSE，看板实时刷新)
```

黑板键（行为树内部共享，也冻结）：`mouth: MouthPose`、`arm_state: ArmState`、`safety: SafetyState`、`spoon: SpoonCheck`、`intent: VoiceIntent|None`、`session: MealSession`、`bowl_sel: int`、`camera_role: Literal["scene","wrist_mouth"]`（v3.1 追加，腕部双职角色开关）。

## 5. 模块 spec + eval

> 每个 eval = 一条可执行命令，退出码 0 即通过，并在 `reports/` 落 JSON 证据（含指标值与阈值）。
> 所有 eval 在本机无硬件可跑（用 MockArm/仿真/预录媒体）；真机 eval 单列，硬件到货后补跑。

### 5.0 cs_schema
- spec：全部 §3.1 模型可构造、可 JSON roundtrip、可校验非法值。
- eval：`python -m pytest tests/test_schema.py -q`
- 通过：用例全绿（含非法值抛 ValidationError 的负例）。

### 5.1 cs_sim（仿真 + IK + 安全包络）
- spec：加载 SO-101 模型；FK/IK 与 MuJoCo 一致；IK 位置误差 ≤5mm、姿态误差 ≤0.05rad；可达空间体素图输出 PNG；安全包络校验器（禁入区=用户面部球域 r=0.12m@口部点外扩 + 躯干胶囊，速度上限：接近段 0.15m/s、面部 15cm 内 0.10m/s）对违规轨迹 100% 拒绝。
- eval：`python -m cs_sim.eval --model <arm 模型文件> --report reports/sim_eval.json`
- 通过线：200 个随机可达目标 IK 成功率 ≥98% 且误差达标；500 条随机违规轨迹被校验器 100% 拒绝；生成 `reports/reach_map.png`。
- 模型获取回退链：TRSA仓库 Simulation/ 的 MJCF → URDF（MuJoCo/ikpy 双吃）→ ikpy 自建链条（6 轴 DH，最后手段）。

### 5.2 cs_arm（Mock 部分，真机部分见 5.9）
- spec：MockArm 在 cs_sim 中按命令做速度受限积分运动，`read()` 返回与仿真一致状态；SafetyEnvelope 拦截一切违规 ArmCommand（改写/拒绝），急停 latch ≤100ms 内 clear_to_move=False 且不再下发命令；watchdog 断连 500ms 主动 disable。
- eval：`python -m pytest tests/test_arm_mock.py -q` + `python -m cs_arm.eval_mock --report reports/arm_mock_eval.json`
- 通过：estop 注入后 ≤100ms 停止；1000 条命令注入 0 条违规执行；MockArm 轨迹跟踪误差 ≤2mm（仿真内）。

### 5.3 cs_mouth（口部三维）
- spec：输入 BGR（+可选深度图），输出 MouthPose。**mono 后端=演示主路径**，两种先验模式（`config/mouth_prior.json` 的 `mode` 切换）：
  - `fixed`（顶部相机回退路径）：固定先验距离缩放（默认 0.42m），误差 ±3–5cm，由"勺停口前 5cm+用户前倾取食+座位定位垫"设计吸收；
  - `ipd`（**v3.1 腕部双职主模式**）：近距 20–50cm 人脸占满画面，Z = fx × 0.063 / ipd_px（瞳距先验 ≈63mm，虹膜关键点 468/473），预期 ±2–4cm；口部点经 `cam_pose=(T_base_flange, T_flange_cam)` 换算到基座系，**不依赖顶部相机**。
  - depth 后端=鼻尖/嘴中心关键点查深度相机像素（**延后保留**，接口不变）。jaw_open>0.35 判张嘴，head_yaw>25° 判转头，frown>0.5 触发询问。切换入 wrist_mouth 角色后先等曝光稳定 ≤500ms 再采口部帧。
- eval（顶部模式，G0–G1 在建，不受影响）：`python -m cs_mouth.eval --input assets/face_samples --report reports/mouth_eval.json`
  通过线：正面样本人脸检出率 ≥95% 帧；张嘴/闭嘴分段与人工标签（labels.json）一致率 ≥90%（或 AUC≥0.9）；转头段 100% 触发转头标志；CPU 单帧 ≤70ms。
- **eval 增补（v3.1 腕部视角）**：`python -m cs_mouth.eval --wrist-view --input assets/face_samples/wrist_view --report reports/mouth_wrist_eval.json`
  通过线：模拟腕部视角样本（近距 20/30/40/50cm × 俯仰 ±30°）检出率 ≥95%；ipd 模式估距误差 ≤4cm（fixed 模式对照一并落报告）；亮→暗曝光切换后恢复可用 ≤1s。**不达标 = 触发 ¥25 第三相机回退（hardware.md §2）**。
- 样本获取：顶部模式样本人人可采（手机：正面 40cm 张闭嘴×10、转头 30°、皱眉+说话各 20s）；**wrist_view 样本补采（D2 前）**：手机手持近距离拍 4 段（20/30/40/50cm，含俯仰角变化模拟腕部逼近视角 + 一段亮暗切换），`scripts/import_face_samples.py --wrist` 入库。
- 静态距离核查（D4，顶部 fixed 模式）：卷尺在 0.35/0.45/0.55m 三点实测，估距误差记录进报告（目标 ≤5cm，超线只修 `mouth_prior.json` 不阻塞）；座位定位贴固定用户位置。腕部 ipd 模式的精度核查以 §5.9 腕部口部追踪 eval 为准。

### 5.4 cs_voice
- spec：麦克风常驻采集→VAD→ASR(SenseVoiceSmall, CPU)→关键词意图解析→VoiceIntent；TTS 用 Windows SAPI（pyttsx3，离线）播报确认语。指令集：下一口/继续/等一下/吃饱了/我想吃X（X∈芋泥、南瓜粥、椰子冻等注册表）。
- eval：`python -m cs_voice.eval --input assets/voice_samples --report reports/voice_eval.json`
- 通过线：20 条预录指令（4 条×4 类+4 条干扰噪声）意图正确 ≥18；单条响应 ≤2.5s（CPU）；全离线（拔网线可复测）。
- 样本获取（D1）：手机录 wav（安静室内），`scripts/import_voice_samples.py` 重采样 16k 单声道入 assets。

### 5.5 cs_food（勺上检查 + 选碗）
- spec：接口 `from_bgr(crop)->SpoonCheck`。MVP 实现 = HSV 启发式（勺区域食物色占比阈值），**接口冻结**，训练好的分类器（training-plan.md §3）延后接入、无感替换。选碗 = 场景相机（套装自带 2MP）ArUco 码贴碗沿（3 碗 3 码），给 bowl_sel。
- eval（pre-hardware）：`python -m pytest tests/test_food_interface.py -q`（接口与 config 阈值装载）；（D4 后，帧源=脚本舀取运行采集的腕部相机帧）`python -m cs_food.eval --data assets/spoon_frames --report reports/food_eval.json`，启发式基线准确率仅记录不设硬线，分类器 ≥90% 才算过（延后）。

### 5.6 cs_orchestra（行为树）
- spec：py_trees 树，50Hz tick。主序列：`选碗 → 舀取(ScriptedScoop：参数化轨迹+腕部相机闭环+失败重试≤2；MockScoop 为其 mock 实现；ActPolicy 为延后替换实现，节点交互不变) → 勺上检查(失败重舀) → 送达(IK+envelope，至口前 5cm) → 等待(jaw_open→咬合→jaw_close) → 勺空确认 → 撤回 → 写 BiteRecord`。打断分支（Selector 高优先级）：软件急停（空格键 latch envelope）/禁入区违规→立即停+后撤 5cm；转头/人脸丢失>1s→保持+播报；"暂停"→悬停；"吃饱了"/"下一口"→对应流转。皱眉→暂停+询问。舀取策略接口说明：行为树对舀取节点的交互以 T8 已实现的 MockScoop 现状为准，ScriptedScoop/ActPolicy 对齐同一交互，**不重构契约**。
- **相机角色切换（v3.1 腕部双职）**：黑板键 `camera_role`。转换"勺上检查通过→开始送达"时置 `wrist_mouth`（cs_mouth 随即以 `cam_pose=FK×腕部手眼` 工作；先等曝光稳定 ≤500ms 再采口部帧）；"撤回完成/急停/中止"回 `scene`。切换事件写入 trace 供审计。
- eval：`python -m cs_orchestra.eval --mock --episodes 30 --report reports/orchestra_eval.json`
- 通过线：30 回合全闭环；注入"第 7 口转头""第 12 口 estop""第 15 口'吃饱了'"，行为响应 100% 符合状态转移表（表写在模块 docstring，tests 断言）；单口仿真时延中位数 ≤20s；**v3.1 增补：每口 camera_role 恰好切换 2 次（进送达 1 次、撤回 1 次）且时序与状态转移表一致，30/30 达标**。

### 5.7 cs_dashboard
- spec：FastAPI+SQLite（文件 `data/care.db`），§3.2 HTTP 契约；单页看板（口数/时长/克数曲线、当前状态、报警高亮），静态资源本地化（Chart.js 单文件 vendor），SSE 实时。
- eval：`python -m pytest tests/test_dashboard.py -q`（起 uvicorn 于随机端口，POST 30 口 + 校验 GET 聚合一致）+ 手工验收：`python -m cs_dashboard` 打开 `http://127.0.0.1:8100` 截图入 `reports/dashboard.png`。
- 通过：30/30 口数据无丢失、聚合字段一致；离线可开。

### 5.8 端到端 mock（无硬件总验收）
- spec：`scripts/e2e_mock_run.py` = MockArm(cs_sim) + 预录 face 视频(cs_mouth) + 预录 wav 队列(cs_voice 注入) + 启发式 cs_food + 行为树 + 看板全链同进程跑 30 口。

## 7. 端到端"跑通"验证脚本设计（scripts/e2e_mock_run.py）

## 10. 工程纪律执行细则

1. 每个构建任务 DoD = 代码 + 该模块 eval 命令跑绿 + `reports/` 落证据 JSON + `git tag`。
2. eval 报告 JSON 必须含：`{module, date, cmd, metrics:{...}, thresholds:{...}, pass:bool}`。
3. 训练相关只产出脚本/配置/命令（training-plan.md），构建工作流**禁止**在本机发起任何真实训练。
4. 所有密钥/摄像头序列号等不入 repo；`config/` 只放结构与默认值。
5. 对外命名检查：`scripts/check_naming.py`（grep 上游项目名清单，CI 式跑，入 e2e 前置）。
6. 文档同步：每 milestone 更新本文件 §6 状态列，偏差写进 `plan/deviations.md`（新建追加式）。
