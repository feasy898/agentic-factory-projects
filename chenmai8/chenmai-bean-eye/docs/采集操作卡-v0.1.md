## 1. 分堆指引（人工，对照 NY/T 1519 缺陷图谱）

### 1.1 怎么分（协议 §2 口径）

1. 对照 **NY/T 1519（生咖啡 / 缺陷图谱，获取见 §0）** 肉眼分拣，**每堆一个类**
   （含好豆堆）；类 key 一律用下表英文 key（入库文件/日志不得出现任何外部数据集
   或项目名）。
2. 拿不准的单粒 → 放 **「待议」堆**，拍照留档（目录/命名见 §5 `images/pending/` 行），
   **不入 v0.1**；复核后归堆或剔除；图谱与 taxonomy 冲突时记 `meta/disputes.md`，
   **不改 taxonomy**。
   **单人替代方案（第二人不在场时）**：照常拍照 + 登记，疑难点注明「单人未复核」，
   **当日不归堆**——次日第二人到岗后复核，或当天把待议照片发给第二人远程复核，
   复核结论记回 sorting_log/disputes 后再归堆或剔除。待议堆本就不入 v0.1，
   此流程不影响当日其余作业。
3. 本批到货含**坏豆对比样**：12 类缺陷优先从对比样里分拣；大/中/小三种分型
   就是后面 §6 的三张全盘照素材。
4. 每堆清点粒数，**当堆分完立即**填 `meta/sorting_log.md`（模板已建）。
   **每类 ≥20 粒是入库门槛**；凑不足的类照记实际数（manifest 标 WARN，
   只用于人工核对，不用于阈值回填），**不要为凑数把疑似豆硬归堆**。

|---|--------|----------|-------|----------------|------------------------------|

## 3. 拍摄参数清单（红线逐条过）

### 3.1 分辨率红线：≥20 px/mm（≤0.05 mm/px）

**通用公式：视野宽(mm) × 20 ≤ 照片像素宽 → 达标；否则凑不够。**

| 设备 | 照片像素宽 | 允许的最大视野宽 |
|------|-----------|------------------|
| 1080p / USB 相机 1080p | 1920 px | ≤96 mm |
| 4K（3840×2160） | 3840 px | ≤190 mm（协议 §3.4 同款算法） |
| 12MP 手机（4000×3000） | 4000 px | ≤200 mm |
| 48MP 手机高像素模式（约 8000×6000） | 8000 px | ≤400 mm（可罩住 300mm 全盘） |

- **单粒特写**：视野通常 20~60mm，上表任意设备都远超红线；让豆占画面 1/3~1/2。
- **13 张散铺照**：把每堆铺进 ≤190mm（4K/12MP）核心区再拍；48MP 可更大。
- **3 张 300mm 全盘照**：需 ≥6000px 宽 → **只有 48MP 高像素模式（或同級相机）能达标**。
  设备达不到时：照拍 + 在 meta 与 photo_log 里**如实记实际 px_per_mm 并标 WARN**
  （该照降级为留档/人工核对用，不得进毫米计量）。
- **实测校验**：拍一张钢尺照（存 `images/_calib/`，命名见 §5），
  `px_per_mm = 量得像素距离 ÷ 实际mm`；每换一次机位/变焦重测一次，结果记入
  meta 的 `px_per_mm`。
- 成像格式：PNG 优先；JPG 须质量 ≥90（协议 §3.4）。

### 3.2 光照（红线）

- **双灯 45° 对称 + 柔光**（柔光罩/硫酸纸）；严禁单侧直射——强阴影/高光斑会
  破坏阈值分割与色差计量（协议 §3.2）。
- 相机**手动模式**：白平衡锁定（用背景卡纸自定义校白或固定同一档）、曝光锁定、
  关自动增益/HDR/美颜；**全批所有照片同一套参数**，参数原文记入 photo_log 表头。
- 环境光稳定：白天拉帘或夜间拍，防频闪（取景器里看有无滚动条纹）。

### 3.3 背景（红线）

- 浅色卡纸，目标色 RGB≈(208,203,200)（与 `configs/synth.yaml`
  `render.background_bgr` 同款浅灰）；**合格容差（本卡内控口径，无标准出处）：
  每通道 ±10 以内**，即 R 198~218、G 193~213、B 190~210。
- **核对方法**：当天同一光照下拍一张卡纸特写 → 手机取色器 App（或传电脑用取色
  工具）在卡纸**中心区域取 5 点平均** → 对照上行区间。超差 → 换纸；当天换不了
  则照拍并在 photo_log 记 WARN（背景色偏差影响分割与色差计量，先记录再评估）。

### 3.4 标定参照（红线）

- 盘面四角贴/摆 ArUco 打印板（§0 生成的 `out/aruco_board.png`，角位
  id0=左上、id1=右上、id2=右下、id3=左下；**摆放旋转无所谓，检测按 id 配对**；
  板的裁剪/贴法见 §0 两方案）。带四角码的整盘照后续直接走 M3 自动标定（px→mm）。
- **单粒特写照不贴码**：用同视场钢尺照换算 `px_per_mm` 记入 meta（协议 §3.5）。

### 3.5 机位

- 三脚架垂直俯拍，传感器平面尽量平行盘面（倾角 ≤5°，用取景框对边与盘边平行核对）；
  **单一机位全程不动**；换机位 = 重测 px_per_mm（协议 §3.1）。

## 4. 每堆怎么拍（流程）

1. **散铺照**（每堆 1 张）：该堆豆自然散铺在盘面中央区（避开四角码），拍 1 张
   `_pile` 照——密度参考；铺得自然些，别叠太高。
2. **单粒照**（每粒 2 张，双面）：从堆里逐粒镊出 → 背景卡上单粒平放 → 拍正面
   （`side=top`）→ 镊子翻面 → 拍反面（`side=bottom`，文件名加 `_b`，见 §5）→
   下一粒。**同一粒两面用同一个 seq 号**（`black_20261003_001.png` 与
   `black_20261003_001_b.png` 是同一粒）。
3. **大/中/小三堆全盘照**（各 1 张）：三种分型原样铺满 300mm 盘面中央（四角码
   露出），各拍 1 张（§6 命名）；设备不够 6000px 时照拍并标 WARN（§3.1）。
4. 拍完 10 张就回看一次：曝光稳不稳、有没有阴影、豆有没有出界/粘连。

## 5. 文件命名与目录（协议 §3.6 / §5.1 + 本卡补充，逐字照写）

```
data/datasets/hn_robusta/v0.1/
├─ images/<class>/<class>_<yyyymmdd>_<seq>.png          # 单粒照（正面，side=top）
├─ images/<class>/<class>_<yyyymmdd>_<seq>_b.png        # 同粒反面（side=bottom，本卡补充后缀）
├─ images/<class>/<class>_<yyyymmdd>_<seq>_pile.png     # 该堆自然散铺照
├─ images/size_trays/size<L|M|S>_<yyyymmdd>_<seq>.png   # 大/中/小三堆全盘照（本卡补充约定）
├─ images/pending/<yyyymmdd>_<seq>_<疑似key>.png        # 待议堆留档照（本卡补充约定；如 20261003_001_black-or-sour.png）
├─ images/_calib/aruco_<yyyymmdd>_<seq>.png             # 标定板照（本卡补充约定）
├─ images/_calib/ruler_<yyyymmdd>_<seq>.png             # 钢尺照（px_per_mm 实测依据）
├─ masks/<class>/<同名>.png                              # 8-bit {0,255} 二值掩码，与图同名（含 _b 反面照）
├─ meta/<图 stem>.json                                   # 每张单粒照一条（必填字段见下方字段表）
└─ meta/sorting_log.md / photo_log.md / disputes.md      # 台账（模板已建）
```

- `<class>` = §1.2 表英文 key；`yyyymmdd` = 拍摄日；`seq` = 该类当日 001 起递增，
  散铺照接续该类序列。
- `side` 不进协议命名：正面不加后缀（缺省 top）；反面加 `_b`（meta.side=bottom）。
  这是本卡补充约定，**入库判定以 meta 的 `side` 字段为准**。
- `images/pending/`、`images/_calib/` 为本卡补充目录：待议照与标定照**不入 v0.1
  登记**（manifest 不计），数据不入 git；目录缺失自建即可。
- 示例：`images/black/black_20261003_001.png`、`images/black/black_20261003_001_b.png`、

## 6. 拍后自检六条（当天下班前逐条打勾；第 0 条是 1~3 的前置）

### 0. 生成掩码（自检 1~3 的前置，每类一条命令）

```bash
.venv/Scripts/python.exe scripts/collect_masks.py extract images/<class> masks/<class>
```

- 产出：`masks/<class>/<同名>.png`（8-bit {0,255}，含 `_b` 反面照；自动跳过
  `*_pile` 散铺照）+ 逐图连通域数 + 全堆面积中位数与 **±40% 异常标记清单**。
- 原理 = 协议 §4.1 自动路线最小实现（灰度 Otsu + 极性自检 → 形态学开闭 →
  连通域滤噪），只用仓库钉版依赖，无新增第三方包。
- **只用于不带四角码的单粒照**；带四角码的散铺/全盘照走 §7 /demo 预标注
  （那条链有码区抑制），本命令会把角码误当豆。
- 极性判反（背景被当前景）→ 加 `--invert` 重跑；噪点豆太多/太少 →
  `--min-area-px N` 调滤噪门槛（默认 500）。

### 1. 掩码数 == 豆数

- 单粒照：extract 逐图打印「连通域 N 个」，单粒照应 =1；≠1 的先看是不是污渍/
  阴影成块（调 `--min-area-px`）或低对比没分出来（`--invert`/补光重拍），
  修完重跑再核。
- 散铺照/全盘照：人工数一遍连通域，与实铺粒数核对（或用 §7 /demo 预标注计数）。

### 2. 面积复核（统计口径已澄清）

- **基准 = 该类堆的掩码面积中位数**（「堆」= extract 一次命令处理的目录，即该类
  全部单粒照，**一图一粒**；散铺照不参与统计）。extract 命令自动把偏离中位数
  >±40% 的粒子列 `[FLAG]`——被标的粒多半是粘连/破碎/阴影，逐张人工复核。
- 协议 §4.3 原文「掩码面积**中位数**偏离堆**均值** ±40%」的基准词有歧义；本卡按
  **堆中位数**执行（本卡补充约定，冲突以协议为准）。extract 输出同时给
  min/max/中位数，需要均值口径可人工换算。
- 该类样本 <3 张时命令自动跳过 ±40% 判定（中位数不稳）→ 人工逐张看。

### 3. 抽检 IoU（工具与命令）

- **手勾工具：labelme**（开源多边形标注，装在 .venv 之外的临时环境，不进仓库
  依赖树：`pip install labelme`；其导出的 JSON 是普通数据文件，工具许可不影响
  数据集）。也可用任何能导出多边形顶点 JSON 的标注工具（JSON 里给 `points`）。
- **步骤**：每类随机抽 10%（每类至少 1 张；13 类合计 ≥13 张）→ labelme 打开
  `images/<class>/<图>.png`，沿豆缘画一圈 → 保存 JSON →

  ```bash
  .venv/Scripts/python.exe scripts/collect_masks.py iou <手勾.json> masks/<class>/<同名>.png
  ```

  → 打印 IoU 数值 + PASS/FAIL（门槛默认 0.95 = 协议 §4.4）。
- **不合格（FAIL）整张重做**：在 labelme 里勾出正确豆缘 → 用

  ```bash
  .venv/Scripts/python.exe scripts/collect_masks.py poly2mask <修正.json> images/<class>/<图>.png masks/<class>/<同名>.png
  ```

  把修正掩码落盘（覆盖不合格掩码），meta 的 `mask_source` 改 `manual_fix`；
  若是原图质量问题则重拍。
- 抽检结论写回该图 meta 的 `qc.iou_spot_check`。

### 4. meta 当日回填

每张单粒照一条 JSON（**必填字段表见 §5，已内联**），**当日回填不补记**；
photo_log/sorting_log 同步收尾。

### 5. 全盘/标定照留档

3 张全盘照已入 `images/size_trays/`，标定板照与钢尺照已入 `images/_calib/`
（命名见 §5 目录树）；photo_log 同步登记拍摄位置与参数；全盘照各记一条 meta
（`px_per_mm` 记 M3 标定结果或钢尺实测值）。
