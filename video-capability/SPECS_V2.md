## 1. 硬件与纪律(沿用 v1)
V100 32GB、Volta(7.0)、fp16 强制、无 FA2/SageAttention、HF 走 hf-mirror、断点续跑、SQLite 状态机、长任务后台化——全部沿用 v1 规格。API 预算计数器不清零,沿用 `config/api.env` 与 v1 的兜底链。新增的所有模型(G7用)部署前必须先过 Volta 兼容性自查。
新增业务原则——**不对称代价(写进门禁校准逻辑,优先级最高)**:餐饮营销中,变形食物触发厌恶反应、摧毁食欲联想,是主动的品牌伤害;而好片段被误杀只损失一次生成机会。因此阈值工作点的选择原则是:**宁可误杀,不可漏网。**误杀率上限可放宽到 25%,漏网率目标压到 0。
## 2. 第一优先级:回归夹具库
在做任何新门禁之前先做这个。没有夹具,G7 无从校准。
**构建方法**:
- **fail 夹具**:从 v1 失败画廊、output、workdir/candidates 中筛出含物体形变的片段,目标 ≥15 个。按现象分四类标注:fluid_melt(流体化/液化)、split_merge(分裂融合)、count_drift(数量渐变)、object_flow(静态物体流动,如锅体)。v1 画廊里不够 15 个的,去候选库里用"首尾DINO相似度低"粗筛补;
- **pass 夹具(负对照组)两类**:
  a) **结构性 pass**:Ken Burns/程序运镜片段 ≥10 个——程序生成物不可能变形,这是门禁的"不会疯狂误杀"对照组;
  b) **候选 pass**:从 v1 候选库中选 G1-G6 高分、且你用 G7e 协议预审无明显形变的生成片段 ≥10 个,标注为"待人工确认",列入最终报告请用户裁定(这是唯一留给人的确认动作);
- 每个夹具一条 SQLite 记录:`fixture_id, path, label(fail/pass_structural/pass_candidate), category, human_source`。
**夹具库指标(硬性)**:G7 在 fail 夹具上拦截率 ≥90%(目标 100%),在 pass_structural 上误杀率 ≤15%,在 pass_candidate 上误杀率 ≤25%(超出部分人工裁定)。
## 3. G7 物体恒存门禁(五个子项)
实现于 `src/gates/g7_object_persistence.py`,与 G1-G6 并列,任一子项触发即 fail。每子项独立打分入 SQLite,总分加权。
### G7a DINOv2 跨步主体一致性
- 模型:DINOv2 ViT-L/14(fp16,hf-mirror 可下),备选 DINOv2 ViT-B/14;
- 方法:对候选视频取帧 t0、t+N/4、t+N/2、t+3N/4、tN(帧间即"跨步",非相邻),对主体包围盒区域(与 G7b 共用检测结果;无检测框时用全帧)提 embedding,计算与 t0 的余弦相似度序列;
- 判据:最小值 < 阈值 → fail。冷启动值 0.75(由夹具 ROC 校准,见 §4);
- 这是对"温水煮青蛙漂移"的直接补丁:相邻帧检查看不见的东西,跨步检查直接看首尾。
### G7b 开放词表检测 + 跟踪计数
- 检测:Grounding DINO(文本提示由镜头卡 subject 生成,如"shrimp""hot pot""bowl"),备选链:OWL-ViT → YOLO-World;Grounding DINO 编译在 Volta 失败时立即切 OWL-ViT,不死磕;
- 跟踪:ByteTrack(纯Python,无GPU兼容性问题);
- 两个硬指标:①物体计数时序方差(帧间计数变化 >2 或方差超阈 → fail);②track churn 率(分裂/合并/ID跳变次数,超阈 → fail)。
- "虾仁从3只变成一片虾的海洋"由①100%命中。
### G7c 静态区域光流(锁定机位镜头专用)
- 镜头卡新增字段 `expected_static_mask`;
- 生成:首帧用 SAM(ViT-B 或 MobileSAM,fp16)按镜头卡 subject 分割出动态物体,反选得到静态区(桌面、锅体、器皿、背景);
- 判据:静态区内光流幅值 P95 超阈 → fail。光流用 RAFT-small(Volta 兼容性自查,失败则退化为静态区相邻帧光度差+SSIM);
- "锅体像水一样流动"由本子项 100% 命中——流场再平滑,发生在不该动的区域就是灾难。
### G7d 首尾漂移检查
- 帧N vs 帧0 的 DINO 相似度,与 G7a 合并计算,单列指标防止 G7a 跨步采样漏掉末段。
### G7e VLM 成对审讯(改版,替换 v1 的十帧网格)
不再问"有没有缺陷",而是给**有序帧对**问**具体问题**。提示词全文(存 `src/gates/g7_vlm_prompt.txt`):
> 你是严格的视频质检员。下面是同一段视频的两个有序帧:左帧是开头,右帧是结尾。请仔细比较左帧中每个可辨识的物体(食物、器皿、家具),只输出一个JSON,不要任何其他文字:
> {"object_shape_kept":0-1(右帧物体是否保持左帧的形状,1=完全保持),"object_count_kept":0-1(数量是否一致),"no_liquid_flow":0-1(固体物体是否出现液化/流动/扩散),"no_split_merge":0-1(物体是否出现分裂或融合),"verdict":"pass|fail","main_issue":"一句话中文"}
> 判定:四项中任一 <0.6 → fail。注意豁免条款:蒸汽、烟雾、火焰、光斑、水中的涟漪这类**本来就是流体/气体的元素**的正常流动不算缺陷;只有固体食物、器皿、金属、桌面等固态物体出现流动、融化、分裂才算。
**豁免条款是必须的**,否则纯生成的蒸汽氛围镜头会被自己的门禁杀掉。VLM 不可用时:G7a/b/c/d 的本地指标兜底,G7e 标记跳过并计入报告。
## 4. G7 校准流程(把"调阈值"变成计算题)
1. 全部夹具过 G7 各子项,输出每个子项在 fail/pass 两组上的分数分布;
2. 画分布图(直方图/箱线图,matplotlib 存图)入报告;
3. 每个子项扫阈值,输出各工作点下的(漏网率, 误杀率)组合,即 ROC;
4. 按 §1 不对称原则选工作点:fail 拦截 ≥90% 约束下最小化误杀;最终阈值写回镜头卡 Schema 的 acceptance 字段,并写入 `config/thresholds_v2.yaml`;
5. 校准后重跑全部夹具验证,结果入 `reports/G7_CALIBRATION.md`。
冷启动值:G7a 0.75、G7b 计数变化容差 2/churn ≤3、G7c 光流幅值 P95 ≤0.5px、G7e 任一项 ≥0.6。全部以校准结果覆盖。
**P2 可选(时间富余才做)**:用夹具库(fail≈15 + pass≈20)微调一个小分类头(DINOv2 特征冻结 + linear probe),作为 G7f 备份判据。数据量不够就跳过,报告说明。
## 5. 三车道重构
### 5.1 镜头卡 lane 枚举更新
`first_frame_i2v | pure_gen_short | compositing_2d5 | evidence_transfer | ken_burns`
(删除 v1 的 t2v 车道用途;future_3d_guided 枚举位保留不实现。)
### 5.2 pure_gen_short(纯生成收缩——只留给环境氛围镜头)
- **时长压缩到 1-2 秒**(漂移随时间累积,5秒是它最肥的土壤);fps 16;
- 固定机位约束写进 prompt 模板("fixed camera, locked tripod, only steam/light moves");
- negative 词表扩充反形变项:"melting, liquid, dissolving, fluid, morphing, splitting, floating debris";
- 首尾帧锚定:有 1.3B 级首尾帧模型则用之;无则用"分段法"——每个关键帧一次短 I2V(≤1s)拼接;
- 几何锁定:Wan2.1-Fun ControlNet depth 模式(1.3B 级),用首帧深度图全序列约束;
- **适用范围:雨窗、夜景街、蒸汽弥漫的空镜。食物镜头禁止进入本车道。**
### 5.3 compositing_2d5(2.5D 合成——食物与产品镜头的默认车道)
- 结构:静态产品图(实拍或生图)为底 → Depth Anything v1 small 估深度 → 按深度分层做视差运镜(纯代码)→ 生成 overlay 图层合成;
- overlay 素材库:用 Wan 生成 3-5 秒的蒸汽/雾/光斑循环素材 ≥6 条(素材入库前单独过 G7 审计,注意豁免条款),ffmpeg 循环拼接;
- overlay 合成用亮度遮罩/screen 混合,限定区域(如食物上方 1/3),纯 ffmpeg/PIL 代码;
- **核心逻辑:生成的循环素材只负责"氛围粒子",物体的形与运动全部来自程序。**食物永远不会变形,因为它根本不参与生成。
### 5.4 evidence_transfer(证据转移车道)
- 本轮**没有真实实拍源**,按以下方式处理:
- 管线代码必须完整实现:输入源视频 → 低强度视频重绘(主选 Wan2.1-VACE-1.3B 或 Wan2.1-Fun 视频条件,denoise 等效强度 0.2-0.35)→ 输出;
- **验证方法(必须做)**:代码合成测试源——用 ffmpeg zoompan+程序粒子对静态图合成已知运动的视频(运动 ground truth 已知),经重绘后对比输出与源的光流场相关性,量化结构保持度,入报告。相关性低的方案弃用换备选;
- 留接口:`assets/evidence/` 目录 + README 写明"用户放入实拍视频(手机竖拍30秒沸腾锅等)即激活本车道";镜头卡 `evidence_asset` 字段;
- 本轮成片中该车道镜头用合成测试源演示,报告明确标注"演示源,非真实实拍"。
### 5.5 镜头卡与叙事模板重写
- 所有食物/产品镜头的 lane 从 first_frame_i2v 改为 compositing_2d5(默认)或 evidence_transfer(有源时);
- 环境氛围镜头改 pure_gen_short,时长字段全部改 1-2s,镜头数量相应增加(25-30s 片子镜头数 8-14);
- v1 的镜头卡模板全部重写,存 `templates/shotcards_v2/`,v1 保留不删。
