# 视频生成技术边界测试方案（2026-09-28 夜间执行版）

> 目的：用一夜时间，以**实测数据**回答四个问题——
> ① 当前本地开源模型（2×V100S-32GB fp16）与闭源 API（MiniMax Design 的 H3 等通道）在各类生成任务上的**能力边界**在哪；
> ② 「VLM 抽帧质检漏检低级错误」的担忧到底多严重，**多 judge + 专用检测器的组合能达标到什么程度**；
> ③ 确定性生成的**确定性梯度**实测如何（同种子同参数→同输出？API 有无种子控制？）；
> ④ 基于以上边界，工程方案 v3 应该如何取舍。
> 方法论：先快速拼装能跑的 oracle 软件（开源+胶水），以它为 oracle 沉淀 **spec+eval 资产**，模块切分、契约冻结、模块内可重生成——本方案本身就是第一份被执行的 spec。

## 2. 测试矩阵

### 2.1 生成边界矩阵（9 轴 × 每轴 4-5 条 prompt）

| 轴 | 考察点 | 示例意图 |
|---|---|---|
| G1 手部 | 手指数量、持物、手势 | 特写数手指；双手交叠拿杯子 |
| G2 文字 | 画面内文字渲染 | 霓虹灯牌写「开放中」；报纸标题 |
| G3 计数/空间 | 数量与相对位置 | 桌上三个红苹果两个绿的；猫在箱子左边 |
| G4 物理时序 | 倒水、弹跳、碰撞 | 玻璃杯倒水不洒；球落地弹三次 |
| G5 多角色一致性 | 两角色对话、跨镜头同角色 | 男女对话正反打；同一红衣女子两个镜头 |
| G6 运镜 | 推拉摇移跟 | 缓慢推进到面部；横摇跟随奔跑者 |
| G7 参考图一致性 | i2v/reference 模式 | 用定妆照生成同角色新动作 |
| G8 风格化 | 漫剧/动漫风 | 赛璐璐风格少女奔跑（漫剧线核心） |
| G9 数字人动作 | 行走/手势/拿起/互动 | 职员走向办公桌坐下拿起手机；主播手势讲解 |

执行：
- **本地**：Wan2.1-T2V-1.3B（fp16，480p，modelscope `Wan-AI/Wan2.1-T2V-1.3B`）与 LTX-Video-2B（hf-mirror `Lightricks/LTX-Video`，用 diffusers `LTXPipeline`），各跑 G1-G9 中适配的轴（i2v 类轴用各自 image-to-video 管线；跑不动的轴记录 N/A），每条 1 个固定种子，失败重试 1 次换种子。产物：clips + 元数据 JSON（模型/种子/耗时/显存峰值）。
- **API**：MiniMax-H3 768P 9:16 5s 全轴跑（G1-G9），G5/G7 加 H3-Max 各 2 条对照；种子控制能力实测（params 里显式塞 `seed`，看 DTO 拒绝与否——被拒即结论「无种子控制」）。
- 每条 clip 抽 8 帧（ffmpeg，均匀采样）存 `frames/<clip_id>/`，供 GLM judge 与检测器用。
- 本地预算：G 轴裁剪后约 35 prompt × 2 模型 ≈ 70 clip；API ≈ 45 clip（≈1.2 万积分，含重试余量 <2 万）。

### 2.2 金标缺陷集（QC judge 基准的 ground truth）

**A 类·注入缺陷（标签 100% 确定，16 条）**：选 A 矩阵中最干净的 clip 做基底，ffmpeg 注入 8 种缺陷 × 各 2 条：
`frame_freeze`（中途定格 2s）、`flicker`（相邻帧交替）、`color_shift`（强色偏）、`face_blur`（人脸区模糊=身份破坏）、`garble_text`（叠加乱码文字块）、`temporal_swap`（两段互换）、`pixelate`（中心像素化）、`ghosting`（帧混叠拖影）。
注入脚本参数化、可复现、记录注入位置。

**B 类·意图缺陷（标签=生成意图推定，标注 probable，~12 条）**：G1-G4 轴中 prompt 故意诱导已知失败模式的 clip（如要求六指、要求画面写出复杂文字），以 prompt 意图为预期标签，单独评测（与 A 类分开计分）。

**C 类·干净对照（~12 条）**：A 矩阵质量最好的 clip。

合计 ~40 条，manifest 记录：clip_id、来源、A/B/C 类、缺陷类型、注入位置（A 类）、预期缺陷（B 类）。

### 2.3 多 judge 盲测协议

每个 judge 独立盲测（不知金标分布、不知其他 judge 结果），对每条 clip 输出统一 JSON：
`{"clip_id", "defect_detected": bool, "defect_types": [...8种+other], "confidence": 0-1, "spans": [...]}`。

| Judge | 实现方式 | 输入 |
|---|---|---|
| J1 GLM-单帧 | 子代理 Read 8 帧 + 评分 rubric | 抽帧 |
| J2 GLM-首中尾+对比 | 子代理 Read 首/中/尾 3 帧对比 | 3 帧 |
| J3 OmniJev-4B | 本地推理，8 种缺陷各出一条 noul 问题（校准概率） | 16 抽帧（模型自己抽） |
| J4 Visual-Jev-4B | 本地推理，choice/noul 打分 | 抽帧 |
| J5 VideoChat3-4B | 本地推理，视频级问答 | 整段视频 |
| J6 专用检测器管线 | OCR 对比、ArcFace 帧间余弦、帧差/光流突变检测、手部关键点计数、CLIP 帧间相似度 | clip+帧 |
| J7 kimi k2.8（可选） | `kimi.exe -p` 通道 | 抽帧（若 kimi CLI 不支持图像输入则记录后跳过） |

指标（确定性 python 脚本算，不走模型）：**A 类上：per-defect-type 召回率、误报率(FPR)、总体 F1；B 类上：与意图标签一致率；校准：OmniJev 概率 ECE；成本：每 clip 判定耗时**。回答核心问题：单 judge 与合议（J1+J6、J1+J3+J6 投票/级联）分别达到什么召回/FPR——给出「该信谁、怎么组合」的实测结论。

### 2.4 确定性梯度测试

| 层 | 方法 | 期望 |
|---|---|---|
| 本地扩散模型 | 同 workflow+同种子连跑 3 次 → 帧感知哈希比对 | 理想为 0 差异；记录跨进程/跨卡差异 |
| 跨卡 | 同种子卡1 vs 卡1（另一进程） | 复现性结论 |
| API H3 | 同 prompt 提交 2 次比哈希；显式 seed 参数试探 | 有无种子控制的结论 |
| 后处理 | 固定 ffmpeg 参数两遍编码 | 字节级是否一致 |
