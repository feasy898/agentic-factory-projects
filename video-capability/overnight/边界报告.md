| 层 | 条件 | 实测结果 | 判定 | 来源 |
|---|---|---|---|---|

| 本地·扩散生成 | LTX 同协议 | 4 次 md5 全等（`be1085fb…`），phash 全 0 | **字节级确定** | 同上 ltx 节 |
| 本地·后处理 | ffmpeg libx264 crf18 medium 编码×2 | wan `674fd804…` / ltx `ab59489b…` 两遍一致 | **编码确定** | 同上 ffmpeg_postprocess 节 |
| 本地·跨卡 | 同种子卡1 vs 卡0 | **未测**——卡0 被生产 vLLM 占用，红线禁用 | 不下结论 | 红线见 `边界测试方案.md` §0 |
| API·同 prompt+同 seed=42 ×2 | 5s 768P 同参数 | 8 帧 aHash 汉明 **均值 102.75/64bit**（min 88 / max 113，逐帧 88–113 全在「完全不同」区），sha256 不同 | **seed 零控制力** | `api_seed_test.json` hash_comparisons[0] |
| API·同 prompt 无 seed ×2 | 同上 | 均值 51.75（min 45） | 同样完全不同 | 同上 [1] |
| API·seed vs 无 seed 交叉 | 同上 | 均值 66.75 | seed 组反而比无 seed 组**更不相似**（n=1 prompt，趋势不外推） | 同上 [2] |
| API·DTO 行为 | params 显式塞 `seed` + 未知键 `unknown_probe_key_zzz` | HTTP 201 放行，无白名单报错 | params 层无 DTO 白名单报错行为——与 07 手册 §七.1 的**顶层**白名单行为不同，属勘误；探测任务真实创建，cancel 在扣费后生效（损失 280） | `api_seed_test.json` dto_conclusion；`api_state.json` seed_probe |

**结论**：确定性只有本地通道成立，且强到字节级（同进程与跨进程一致，含 diffusers 采样全过程）；ffmpeg 固定参数后处理确定。API 通道「接受 seed 但毫无控制力」——比报错拒绝更隐蔽，工程上**不能依赖 API 种子做任何确定性假设**；API 每次提交都是新样本（sha256/帧哈希全不同）。参考：07 手册记录的 224 积分价（年卡8折）在本钱包路径未生效，实扣 280=56积分/s 列表价 × 5s（`pricing_snapshot.json` video 组 costPerSecond、`metadata.json` credit_cost）。

## 7. 本地 vs API：质量-成本-确定性三维对比

| 维度 | 胜者 | 量化依据 |
|---|---|---|
| **质量** | **API（H3/H3-Max）** | 金标 C 类 12 条干净对照全部来自 H3（manifest）；H3 9 轴 5●+4◐ vs LTX 4◐+5○；但 H3 非无缺陷（5 条 B 类），且**失败维度与本地同源**（手/小字/计数） |
| **确定性** | **本地（唯一）** | 本地字节级可复现（md5×4 + phash 全 0）；API 同 seed 汉明 102.75、无任何复现性（§4） |
| **成本** | 各有一半 | 本地 0 积分但 Wan 112× 实时不可量产、LTX 仅 480p 无声；API 3,360 积分/min 但拿到 768P+音轨+一致性，H3-Max 交付速度反而快过本地 LTX |

**结论（直接支撑工程方案 v3 的分工）**：
1. **「确定性重生成」是本地独占能力**：任何要求「同输入→同输出」的环节（参数扫描、回归评测、金标基底、可复现实验）只能本地做；API 侧连 seed 参数都是安慰剂。
2. **「质量上限」是 API 独占**：768P、原生音轨、多参考身份一致性（G5/G7）本地无解（Wan 无 I2V 权重、LTX 只是首帧条件）。
3. **性价比组合**：LTX 做批量草稿/迭代（76.7s、0 积分、确定性）→ 胜出 prompt 用 H3-Max 出终稿（同价 4 倍速）；Wan-1.3B 仅在需要 16fps 电影感低速运动且不计时间时考虑（其质量档并不优于 LTX，速度差 7.4 倍）。
4. **H3-Max 应默认替代 H3**：同价（280/条）同规格，4 倍速 + 约 4–5 倍码率，本轮 4/4 全成且判定干净——除非出现 H3 独有的质量场景（未观察到）。
