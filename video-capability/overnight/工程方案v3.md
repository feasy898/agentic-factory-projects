### 2.3 「无人干预 70 分」定稿形态（实测裁决，边界报告 §8.3）

单通道都到不了 70 分。定稿管线：**LTX 本地零成本草稿迭代（确定性保证可优化）→ 胜出 prompt 交 H3-Max 出 768P 含音轨终稿 → 本地 QC（J3@0.70 主判 + J1 GLM B 类判官 + J5/J6 信号层）拦截结构性缺陷 → 人工灰区（0.7–0.9 与 B 类 flag 100% 抽检）**。已知残余风险两条，如实入账：① 手部/计数/小字缺陷 API 侧必发，B 类召回上限当前 0.75；② 时序类缺陷在 J6 修复前无可靠自动判据（§3.4）。

结构性绕行手段（技术达不到项的替代）：小字→程序渲染字牌（deterministic 镜头，v2 §1.2 原则 4 与实测 G2 边界互相印证）；精确计数→分镜改述（「一排马克杯」代替「5 只」）+同 prompt 多采样后 QC 拣选（API 每次都是新样本，恰好免费获得 N 个候选，见 §5.3）；时序缺陷→终检人工抽检项（在 J6 修复验收前，QC 报告的时序结论不作为自动放行依据）。

### 3.1 QC 成本（实测口径，judge基准报告 §8）

E10 每 clip ≈ **J3 77.2s（V100，逐 clip 实测）+ J1 65.7s（吞吐下界口径，8 批并行可摊）**；并行执行约 77s/clip。J5 3.3s、J6 51.2s（CPU）为可选加层。J4 138s/clip 且无效，弃用本身也是成本优化。

### 3.2 J6 修复清单（逐条可验证，judge基准报告 §11.2；实施后金标复测）

1. **freeze 几何失谐（最优先）**：freeze_ratio 0.35→**0.20** 且该规则抽帧加密至 16 帧，冻结判据改「帧差 < 场景中位帧差的 1/4」（替代绝对阈 freeze_diff=1.2）；修完复测 017/028 必须触发、004/016 不触发。
2. **garble**：要求「字块 OCR 置信 <0.78 **且** 存在可检出文字轮廓」，emit 0.45→0.6（本轮 conf_drop/uniform_low 11 误报对 3 真阳）。
3. **hue_shift**：帧间相对比较替代绝对 30° 阈；低饱和场景关闭（026/032 误报 conf=1.00）。
4. **scene_cut**：cut 两侧各取 0.5s 内容相关性比对，仅内容不连续且与注入位置吻合才报 swap（026/028 误报）。
5. **补 ghosting/pixelate 检测器**（本轮零覆盖，golden_034 空候选）：SSIM 双高判拖影、块状梯度周期性判像素化。

### 3.3 J3 已知误报机理（不修阈值、修认知与通道）

FPR 0.25 的 3 条误报（golden_010/025/032）全部来自 color_shift 通道把电影感调色当偏色——**API 片调色重，此机理只对 API 产物显著**。业务若要 FPR≤0.1：切 `thr_fpr_first=0.80`（代价召回 0.875），或等 hue 修复后重扫工作点。**判定阈值改动必须重跑 eval_run.py 并不得低于准入线**（thresholds.yaml 修改规程）。

### 3.4 QC 已知残余盲区（向下任不对内宣称已自动化）

时序四类（frame_freeze/temporal_swap/ghosting/flicker）：10.1 实锤（定格 2s 三 VLM 全漏）+10.2（自相似段互换类型级 6/6 全错）。在 3.2 修复验收前，时序缺陷按「人工抽检项」管理；QC 报告中时序类判定仅作线索。

## 5. 确定性工程（种子/契约/内容寻址缓存实测结论）

### 5.1 确定性梯度定稿（边界报告 §4 全表，此处为工程结论）

| 层 | 实测 | 工程承诺 |
|---|---|---|
| 本地扩散生成 | Wan/LTX 同种子同参 4 次连跑（含换进程）**md5 全等、phash 两两全 0**（`local_determinism.json`） | local 镜头承诺**像素级复现**（字节级）；`gen_local.py` 种子恒定入 gen_meta（SPEC §2.1） |
| 后处理 | ffmpeg libx264 固定参数两遍编码 md5 一致 | 合成层承诺字节级 |
| 跨卡 | **未测**——卡0 生产红线禁用 | 不承诺；如需测须生产停机窗口（§7 P2-11） |
| API | seed 零控制力（同 seed 汉明 102.75 > 无 seed 51.75）；每提交皆新样本 | api 镜头**不承诺任何复现**；确定性验收只覆盖 deterministic/local 镜头（与 v2 P1 验收口径一致并被实测强化） |

### 5.2 契约工程（vpipe 实测）

三契约（shot/qc_report/asset_manifest，JSON Schema draft-07，schema_version 1.0）已冻结：模块间禁 import、判定数值只存 `thresholds.yaml`、失败写 `errors` 不许静默（SPEC §0）。`thresholds_sha256` 进每份 QCReport 判定可追溯；manifest 以 sha256 为资产身份。**40/40 QCReport 过契约校验、eval 复验 ACCEPT（本会话 V3）**——契约路线被实测证明可执行、可验收、可复跑。

### 5.3 内容寻址缓存实测结论（对 v2 §3.4 规范的三点实测修订）

1. **本地层**：内容指纹→像素级命中的前提成立（同种子字节级复现），v2 缓存键=sha256(内容指纹) 对 local/deterministic 镜头**按原设计执行**。
2. **API 层（v3 新增结论）**：同指纹重提交必然产出**新样本**（sha256 不同）——缓存键对 API 镜头只能命中「提交参数」层，不能命中「输出」层。故：api 镜头产物以 sha256 登记进 manifest、**重跑=新资产+重新 QC**；edit-op（reseed 类）对 api 镜头退化为「强制重生成」。
3. **无 seed 的正面利用**：API 重提交即免费获得独立新样本 ⇒ best-of-N 在 API 侧=同 prompt 重提交 N 次（每次 280 积分）；在本地侧=换 seed 重跑（0 积分）。v2 的 BoN 晋升制在两层各有一套实测可行的 N 采样机制。

### 6.3 模块重生成规程（定稿，SPEC §6 为准，此处补实测注）

1. 输入只许读 SPEC.md + contracts/ + eval/，**禁读旧实现源码**（防锚定旧 bug，阈值只从 yaml 读）；2. 按职责单文件重写、不 import 兄弟模块；3. 硬闸门=`eval_run.py` **ACCEPT（exit 0）**，REJECT 时如实报差距，**禁止放宽 eval_admission**；4. 回归：其余模块既有产物必须仍被 eval 接受；5. 演练基线=§6.1 的 qc_orch 40/40 ACCEPT（昨晚执行、今晨复验）。

### 6.4 多次生成改进 spec 的迭代循环（v3 形式化定义）

```
loop(n):
  S(n)   = spec_v(n)                     # shot JSON 集（prompt/参数/参考图/种子策略）
  G(n)   = gen(S(n))                     # 本地 LTX 草稿（确定性：可归因）∪ API 终稿候选
  Q(n)   = qc_orch(G(n))                 # E10 判定 + 处置分类
  分类： pass          → S(n+1)=S(n)（收敛该镜）
        auto_reject   → 反馈注入：J3 通道类型 → 定向改 prompt/换参考图/换轴绕行
        manual_review → 人工裁决回流：确证缺陷→金标正例池（只作评测，永不入训练）；
                        误报→难负例池 + 修 judge（阈值改动→重跑 eval）
  收敛判据：单镜 pass 且 QC 报告无未处置 error；整集=全部镜 pass + report.py 对账 miss=0
  上升：同镜修订 ≤2 轮仍不过 → 人工工单（v2 表 2-1 镜头重试口径沿用）
```

实测依据：本地确定性保证「改动→效果」可归因（同 prompt 改一词，其余像素不变可 diff）；API 侧改 prompt 后新旧样本本就全不同，归因靠**同 prompt N 重采样**的 QC 通过率统计而非逐帧 diff（§5.3-3）。该循环即「spec 即资产」的运营形态：每次人工回流与 QC 误报都在增厚金标与阈值证据，spec 与 eval 同步进化。
