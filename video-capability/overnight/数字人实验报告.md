# 数字人通道最小链路实验报告（Vidu avatar + 双路 TTS）

> 成稿：2026-09-30｜执行：数字人集成实验通道
> 上游资产：`overnight/数据/vidu_avatar_client.py`（Vidu 通道，status=ok）、`overnight/数据/stepfun_client.py`（StepFun 通道）、MiniMax Design 网关（本机 127.0.0.1:8001）。
> 依据方案：`overnight/工程方案v3.md`、`边界测试方案.md`（项目根目录）。预算红线：Vidu avatar 积分本次 ≤800（实际用 ~32，见 §4）。

## 0. 一句话结论

**「台词 → TTS → Vidu avatar → ffmpeg 拼接」最小链路一次走通**：同一参考图（charA 林夏）+ 两版 TTS 音频（StepFun 磁性男声 / Design 温柔女声）各生成一段数字人讲述，拼成 30.0s 成片（`dh_final_30s.mp4`，826×1114 竖屏 24fps）。口型/时序可用性检查全过（嘴部活动正常、无冻结、跨拼接段身份一致）；J6 修复版对数字人素材新发现两类**误报机理**（说话头低运动平台→ghosting、同人物 A/B 拼接→temporal_swap），对 QC 集成是重要输入。成本上 Vidu avatar = **1 积分/秒**，是既有 H3 数字人轴（56 积分/秒，MiniMax 积分体系）的 **1/56**——口播类数字人主体镜头的性价比通道。

## 1. 链路图（实测拓扑）

```
台词 line.txt（64 字，overnight/数据/digital_human/line.txt）
  │
  ├─ TTS-A ─ StepFun stepaudio-2.5-tts（voice=cixingnansheng 磁性男声）
  │            POST {STEPFUN_BASE_OPENAI}/audio/speech，instruction="语速适中，口播风格，清晰亲和"
  │            → tts_stepfun.mp3（mp3 24kHz mono，14.256s，229,546B，4.79s 出片）
  │                 └─ Vidu s_avatar/offline（image=charA_linxia_red_dress.png，audio 驱动，720p）
  │                      → avatar_out/dh_stepfun_720p.mp4（15.0s，826×1114，h264+aac）
  │
  └─ TTS-B ─ MiniMax Design 网关 backend=seedaudio（voice_id=Chinese_wenrounvxing 温柔女声）
               POST /api/generate/speech/submit → 轮询 41s → 工作区产物复制
               → tts_design.wav（pcm_s16le 40kHz stereo，16.5s，2,642,108B）
                    └─ Vidu s_avatar/offline（同一参考图，audio 驱动，720p）
                         → avatar_out/dh_design_720p.mp4（17.0s，826×1114，h264+aac）
                                    │
                                    ▼
        ffmpeg trim(13.90s + 16.10s) + concat + fade → dh_final_30s.mp4（30.04s，8.19MB）
        同参数二遍编码 md5 一致（§5.4，确定性承诺成立）
```

封装脚本（本次新增，均在 `overnight/数据/digital_human/`）：
- `dh_design_tts.py`——Design 网关 TTS 调用器。出站目标只有写死的本机网关常量（非外部输入 URL，无任意抓取面）；产物不走 URL 下载，按工作区相对路径复制并做 `is_relative_to` 收敛。
- `dh_lipcheck.py`——口型/时序可用性确定性检查（§5.2）。
- Vidu 通道沿用既有 `vidu_avatar_client.py`（SSRF 防护 + 输出路径收敛 + key 掩码，本次直接复用未改动）。

### 3.2 口型活动检查（`dh_lipcheck.py`，确定性 CPU 脚本）

方法学说明（如实）：本机 opencv 5.0 已移除 Haar CascadeClassifier、其新 DNN 导入器无法解析 YuNet 旧 opset onnx（实测报错 `Can't read ONNX file ... ONNXImporter2::parseFile`），故**放弃自动人脸定位**，改为「抽帧人工目检标定嘴部归一化 ROI（两片共同 `x∈[0.44,0.62], y∈[0.30,0.38]`）+ 确定性帧差计算」。无 SyncNet 类音画同步打分器（边界测试方案 §0 早已声明装不上则口型维度降级人工抽检——本轮维持该降级）。

| 指标 | dh_stepfun | dh_design | dh_final |
|---|---|---|---|
| 嘴部帧间差 mean / median / p90（0-255 MAD） | 4.18 / 2.54 / 10.73 | 4.28 / 2.86 / 8.60 | 4.70 / 2.74 / 10.88 |
| 静止帧占比（diff<1.5） | 26.5% | 21.9% | 24.9% |
| **最长口型静止连跑** | 7 帧 = 0.292s | 5 帧 = 0.208s | 7 帧 = 0.292s |

**对照 VPO 口型窗概念**：`D:\workspace\video-Ontology\schemas\l2\limited-motion-intent.schema.json:100-127` 定义 `lips.set ∈ {vpo:motion.lip_set.flap_2state|aiueo_closed|viseme_8_plus}`、**`max_error_frames` const=3**、`blend_ms/unit=ms`——VPO 的验收语言是「aiueo 闭集唇形分类下帧级误差 ≤3 帧」。本检查无唇形分类器，用「嘴部 ROI 帧间差静止连跑」作量级对照：最长 7 帧（0.29s）连跑，时长与 TTS 自然停顿（含语音末端 0.36s 静默段）同量级，未见「该动不动」型口型失效（静止连跑未逐帧归位到停顿时间轴，此点如实标注）；但不满足 ≤3 帧的字面口径。**结论如实写：VPO 窗口作为 shot 契约验收语言成立（写进契约即可），但自动执行需补唇形分类器（aiueo 闭集分类或 SyncNet 类），当前只能人工抽检兜底。**

### 3.3 J6 修复版时序检测（`vpipe/src/qc_detectors_v2.py`，全序列原生帧率）

| 片 | 判定 | 候选 | 人工复核结论 |
|---|---|---|---|
| dh_stepfun | detected | ghosting 1.00–3.08s（dip_ratio 0.497，conf 0.769） | **误报**：4 帧目检（mancheck/sf_strip.jpg）人脸锐利无拖影，span 为说话自然低运动平台（帧差凹窗被误读为 tblend 混叠） |
| dh_design | detected | ghosting 4.00–5.58s（dip_ratio 0.594，conf 0.643） | **误报**：同上（mancheck/dz_strip.jpg），span 为慢语速段 |
| dh_final | detected | **temporal_swap 13.917s**（单切点 back_score 0.978、匹配 0.042s 开头，conf 0.822）+ ghosting 1.00–3.25s | swap=**设计性误报**：拼接硬切点两侧是同人物同构图（A/B 两版），天然命中「子段重复」规则；ghosting 同上误报 |

**对 QC 集成的两条新机理（金标上未见过，数字人素材特有）**：
1. **ghosting 规则在数字人上 2/2 误报**——说话头大量存在低运动平台（帧差中位降至周围一半），`rect_dip` 凹窗判定与「自然慢速说话」不可区分。J6 v2 在金标 C 类 12 条上 FPR 0/12，但金标来自 H3 叙事短片，无口播类素材。
2. **同人物 A/B 拼接必触发 temporal_swap**——后向重入相似度 0.978 远超 `swap_single_back_min=0.85`。量产数字人拼接需：切点白名单进 QCReport 契约，或拼接改叠化转场，或 swap 规则加「同参考图来源豁免」。

这两条与工程方案 v3 §3 的既有定位一致（J6 修复版**只作信号不作否决**，升否决层须过 promote_criteria），本轮数据进一步支持该定位。

## 5. 质量结论

1. **链路成立**：台词→TTS→audio 驱动 avatar→拼接，全链无人工干预一次成功；Vidu avatar 对 24kHz mp3 与 40kHz wav 两版音频都正常驱动。
2. **口型同步目检可用**：抽帧序列上口型开合与语音节奏对应，音频结束后自然待机；自动音画同步打分（SyncNet/唇形分类）未装机，此结论止于目检+活动度量级，不宣称量化口型达标。
3. **身份保持良好**：同参考图两次生成 + 跨拼接段均无可见漂移（抽样目检级）。
4. **两版 TTS 听感差异**（时长学证据，未做人耳盲测）：StepFun 口播节奏紧凑（4.6 字/s、停顿<0.6s）；Design 温柔女声带 >1s 长停顿三处（4.0 字/s），人设感强但节奏拖。**StepFun 磁性男声 × 女性角色=性别错配**——StepFun 内建音色清单 API 不可查（`GET /audio/voices` 实测只返回克隆音色，5 个女声 id 试探全 404），本实验未再花预算盲试；工程化前应先用 3s 克隆通道（smoke 已验证可用）克隆女声再上 avatar。
5. **拼接观感**：A/B 同词重讲结构作为对比 reel 成立；做正片需同 voice 单版或加转场（叠化可顺带消除 J6 swap 误报）。
6. **QC 新知**（§3.3 两条机理）已可回填 judge 修复清单。

## 6. 与既有 G9 轴（纯文生视频数字人）对比

G9 既有结论（边界报告.md §2/§10.2：H3 ● 5/5 全含原生音轨、走-坐-拿-看动作链连贯、golden_013 入 C 类；H3-Max ● 但终帧趋怼脸+图表虚化；Wan/LTX ◐）对比本轮 Vidu avatar 实测：

| 维度 | H3/H3-Max 纯文生视频（G9 既有） | Vidu s_avatar audio 驱动（本轮实测） |
|---|---|---|
| 驱动方式 | prompt 直出（人物+动作+音轨一体生成） | 参考图 + 真实 TTS 音频驱动 |
| 口型-语音关系 | 音轨原生生成，**与口型同步性无保证、无文档承诺** | 口型由上传音频直接驱动，目检同步成立 |
| 音频可控性 | 不可控（模型自生成音轨） | **完全可控**（TTS 音色/台词/语速全部前置可控，可克隆） |
| 动作编排 | 走-坐-拿动作链连贯（G9 强项） | 站姿口播+自然手势/待机动作，无大位移动作链（未测行走类 timeline 动作） |
| 身份一致性 | 依赖参考图（G7 轴能力） | 参考图即身份源，两版音频×两次生成无可见漂移 |
| 计费粒度 | 280 积分/5s = **56 积分/s**（MiniMax 体系） | **1 积分/s**，按音频秒取整（Vidu 体系，两钱包不可直接换算，同体系内差 56×） |
| 规格 | 768P 横竖屏可选，5s 粒度切片 | 826×1114 竖屏 720p 档，时长跟随音频（秒级粒度，本次 15/17s） |
| 确定性 | seed 零控制力（§5 实测） | 未测（API 通道，按 §5.3 口径默认不承诺复现） |
| 时长边界 | 4-15s 已测（工程方案 v3 §7 P1-6 长时程未测） | 本轮 15/17s 直接成立；更长（分钟级）未测 |

**分工结论**：两者不是替代关系——**口播播报主体镜头（人设号、新闻播报、课程讲述）用 Vidu avatar**（真口型+音频可控+1 积分/s）；**有场景叙事/动作链的数字人镜头（走向工位坐下拿起手机类）用 H3 系**（动作链是它的强项，但音频不可控）。Vidu avatar 补上的正是 G9 缺失的「可控语音+真口型」这一环。

## 7. 进入工程方案 v3.1 的集成建议

**建议在 v3 的 §2.1 G9 行与 §6.2 S 系列上做如下增量**（全部有本轮实测支撑）：

1. **环节分工定稿（G9 细分）**：数字人轴拆两路——`G9a 口播主体` = TTS → Vidu avatar（本轮验证）；`G9b 叙事动作链` = H3/H3-Max（既有 G9 结论）。QC 沿用 E10 双判官 + 人工灰区。
2. **vpipe 契约扩展（对接 S1/S3）**：shot.schema 的 `audio` 字段升「可执行」时，登记 `tts_engine: stepfun|design-seedaudio`、`voice_id`、`duration_s`；新增 `avatar` 镜头类型（image ref + audio ref + resolution + watermark），对应新模块 `gen_avatar.py`（封装 vidu_avatar_client.run，积分守卫沿用 §2.2 口径：提交前查 `/ent/v2/credits`，**该余额端点建议写进 SPEC**）。
3. **TTS 选型**：默认 **StepFun stepaudio-2.5-tts**（节奏紧凑、OpenAI 兼容单端点、克隆已验证）；Design seedaudio 作对照/备用（voice_id 生效已验证，但 07 手册的 official 批量 TTS 已不可用、DTO 必填 backend=seedaudio 需勘误进 07 手册）。量产前用克隆通道统一音色性别与人设。
4. **QC 增量**：
   - L0 预检对 avatar 片的时长偏差校验改为「成片时长 = ceil(音频时长)」已知项豁免（Vidu 整秒取整是平台行为，本轮 0.744s 垫尾不是缺陷）；
   - J6 ghosting 补「低运动平台豁免」实验项；拼接件的 temporal_swap 按切点白名单过滤（QCReport 契约加 `known_cuts` 字段）；
   - 口型维度维持人工抽检，shot 契约写入 VPO 语言 `lips.max_error_frames=3 + lip_set` 作为**验收规格**（可执行化待唇形分类器/EchoMimic 线装机）。
5. **排期建议**：本轮把「数字人播报」从 v2 E 系列的待测项（E4 EchoMimicV3/MimicMotion 本地线）变成了一条已验证的 API 通道——本地口型线优先级可继续让位于 QC 收口（与 v3 §7 P2-13 的裁决一致），除非出现「必须本地零成本产口播」的需求。
6. **待测边界（下轮）**：Vidu avatar 时长上限（分钟级）、横屏/不同分辨率、timeline 动作编排（文档支持 `{"actions":[{"text":"比个心","time_range":[5,10]}]}`，本轮未用）、克隆音色端到端、同 avatar 长期人设的跨集一致性。
