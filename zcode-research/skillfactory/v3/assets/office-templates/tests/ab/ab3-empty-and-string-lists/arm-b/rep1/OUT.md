## 4. 分歧清单（仅 2 处，全部为逐字实证）

### D1 · 周报信息行：缺失文本字段的段落处理
- 位置：周报 case2 信息行（A01 vs B01，见 §3.1）。
- A（被测技能）：缺失的 `部门` 在**信息行中整段消失** → `填报人：赵倩　　周期：____`。
- B（参照实现）：保留标签并占位 → `填报人：赵倩　　部门：____　　周期：____`。
- 附加观察：A 的处理**内部不一致**——同一缺失字段在标题里用 `____`（`____工作周报`）占位，在信息行里却整段省略；B 两种位置统一用 `____`。双方台账对此字段的 `rendered_as` 均记 `以____占位`（A 台账声明与其信息行实际渲染不完全吻合，占位仅体现在标题）。
- 注意：`部门` 缺失是任务描述未提及的输入事实（§1），但它恰好是本轮周报侧唯一的文本级分歧来源。

### D2 · 工作总结：选填列表节省略后的章节编号
- 位置：工作总结 case2（A05 vs B05，见 §3.2）。
- 两边都把缺失的 `三、存在问题` 整节省略（省略行为本身一致）。
- A（被测技能）：保留模板原编号 → `四、下一步工作打算`。
- B（参照实现）：重排连续编号 → `三、下一步工作打算`。
- 周报侧无此问题，因为被省略的 `三、问题与需协调事项` 恰为最后一节。

## 5. 结论（arm-b/rep1 判定）

1. **占位条目**：两实现行为完全一致——必填列表为空数组时，保留小节标题并渲染单个占位条目 `1．____`；台账记 `missing` + `rendered_as='以____占位条目'`（未虚记 filled）。
2. **省略**：两实现行为一致——选填列表缺失时整节（标题+条目）省略，台账记 `missing` + `rendered_as='省略该条目/小节'`；唯一分歧是省略后的**章节连号**：A 保留模板原编号（四），B 重排（三）。
3. **字符串单项化**：两实现行为完全一致——列表字段误给字符串时，静默包装为单元素列表（`str` → `[str]`），台账记 `filled` 且无任何类型异常备注，docx 渲染 `1．<原文>`。
4. 台账层面 A 与 B **深度等价**（去掉 `$.outputs` 路径后逐字一致）；两边的 schema 一致性检查全部通过（字段名/spec 顺序、required 标志、kind、filled/missing 计数与列表、missing_required 名单、unknown_keys=空）。
5. 空串标量（周期）两边均按缺失处理（占位 `____`，不记 filled）；选填标量缺失（成文日期）两边均留空渲染——与台账声明一致，无虚假记账。
6. 全部 A/B 差异汇总：**D1**（缺失文本字段在信息行：A 整段省略 vs B 保留 `部门：____`）与 **D2**（省略选填节后 A 不重排编号 vs B 重排）。docx 字节差异为样式表级（styles.xml 规范化哈希不同），与列表行为无关。
