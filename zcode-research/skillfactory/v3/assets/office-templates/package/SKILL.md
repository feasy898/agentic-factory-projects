# SKILL.md — office-templates：中文办公模板技能（周报 / 请示函 / 会议通知 / 工作总结）

## 1. 名称与描述

**office-templates**：将四类中文事务文书（周报、请示函、会议通知、工作总结）的数据 JSON，
按 GB/T 9704 风格版式一键生成 `文书.docx` + 字段填充台账 `fields.json`——缺数据不编造
（必填缺失以 `____` 占位、选填缺失留空或省略，并如实记账），产物确定性可复现。

## 2. 何时使用 / 何时不用

**何时使用**：
- 需要把结构化的周报、请示函、会议通知、工作总结数据规范化成文（居中标题、顶格称谓、
  首行缩进两字符、右对齐落款的公文版式）；
- 需要向交付方如实说明"哪些字段填了、哪些缺了、缺的怎么渲染的"（fields.json 台账）；
- 需要可复现、可程序验收的批量成文（同一输入连跑两次产物一致）。

**何时不用**（非目标，见 spec §12）：
- 模板定制、字段增删、多文档合并；
- docx→pdf 转换、红头文件/公章/版记等公文要素；
- 数据语义校验（日期格式、电话号码合法性按原样字符串处理）；
- 文辞润色/审美优化（文案由数据公式化推导）。

## 3. 输入要求

### 3.1 数据 JSON

顶层必须是 JSON **对象**（键=字段汉字名，值=字符串或字符串数组），UTF-8 编码。
四类模板的完整版式与字段规范见 `references/` 下同名文档，字段表如下
（\* = 必填；(列) = kind=list 数组语义，其余 kind=text）：

| 模板 | 字段（\* = 必填；(列) = list） |
|---|---|
| 周报（7） | 部门\*、填报人\*、周期\*、本周工作内容\*(列)、下周工作计划\*(列)、问题与需协调事项(列)、报送日期 |
| 请示函（8） | 请示事由\*、主送机关\*、请示缘由\*、请示事项\*、请示单位\*、联系人、联系电话、成文日期 |
| 会议通知（11） | 会议名称\*、召开单位\*、主送对象\*、会议时间\*、会议地点\*、参会人员\*、会议议题、会议要求(列)、联系人、联系电话、发文日期 |
| 工作总结（7） | 总结主体\*、总结时段\*、工作回顾\*(列)、主要成绩\*(列)、存在问题(列)、下一步工作打算\*(列)、成文日期 |

### 3.2 字段语义（F1–F6，准备数据与核对台账时逐条对照）

- **缺失判定**：键不存在，或值为空白字符串（strip 后为空）；列表字段的空数组、全空白数组亦为缺失。
- **F1 必填文本缺失** → 文中以 `____` 占位；台账记 `status="missing"`、`rendered_as="以____占位"`。
- **F2 选填文本缺失** → 行内留空、标签保留（如 `联系电话：`）；记 `rendered_as="留空（渲染为空字符串）"`。
- **F3 列表取值宽容**：字符串 → 单项；数组 → 逐项 `str().strip()` 去空；其他类型 → `str().strip()` 单项。
- **F4 列表缺失**：必填 → 占位条目 `1．____`（`rendered_as="以____占位条目"`）；
  选填 → 该条目/小节整节省略、文中不出现节头（`rendered_as="省略该条目/小节"`）。
- **F5 填充值 strip**：文本与列表项入文前均 `strip()`，台账 `value` 即 strip 后的值。
- **F6 模板外键**：数据中未被模板消费的键按字典序记入 `summary.unknown_keys`，不影响文书与台账。
- **必填缺失不是运行错误**（F7/C3）：正常退出码 0、正常产出，如实记账即可。

## 4. 用法

```bash
python package/scripts/gen_doc.py --template <周报|请示函|会议通知|工作总结> --data <数据.json> --outdir <输出目录>
# 例：python package/scripts/gen_doc.py --template 周报 --data 周报数据.json --outdir out/周报/case1
```

| 参数 | 必填 | 语义 |
|---|---|---|
| `--template` | 是 | 恰为 `周报` / `请示函` / `会议通知` / `工作总结` 四个汉字名之一 |
| `--data` | 是 | 数据 JSON 文件路径（UTF-8，顶层为对象） |
| `--outdir` | 是 | 输出目录；不存在则递归创建 |

**退出码**：`0` 成功（含必填缺失等数据边界，按 F1–F6 记账），stdout 打印一行摘要；
`2` 非法输入被拒（见 §7），stderr 中文报错，**不产生产物、不建产物目录**。

## 5. 产物说明

每次调用在 `--outdir` 内恰产出 2 个文件：

| 文件 | 说明 |
|---|---|
| `文书.docx` | GB/T 9704 风格版式的成文（版式见 §6；内容全部由输入数据推导，无当前时间/随机内容） |
| `fields.json` | 字段填充台账，UTF-8、`ensure_ascii=false`、缩进 2。顶层恰 7 键：`template`（模板名）、`title`（与文书标题段全文相等）、`filled_fields`（已填字段名序列）、`missing_fields`（缺失字段名序列）、`fields`（明细数组）、`summary`、`outputs` |

`fields` 明细每项：`{name, required, kind, status, value}`，缺失项另含 `rendered_as`；
`status ∈ {filled, missing}`，filled 项 `value` 非 null（text 为字符串、list 为字符串数组），
missing 项 `value` 为 null。`summary` 恰 6 键：`{total, filled, missing, missing_required,
missing_required_names, unknown_keys}`，且计数与明细自洽（`filled + missing = total`，
`missing_required_names` = 缺失且必填的名字序列）。

## 6. 版式规范（逐条对应 spec.md §4，口径可追溯）

| 规则 | 内容 |
|---|---|
| **V1 页面** | A4（21.0×29.7 cm）；页边距 上 3.7 / 下 3.5 / 左 2.8 / 右 2.6 cm（GB/T 9704 版心） |
| **V2 标题** | 首个非空段水平居中；eastAsia=黑体、22pt（二号）；文案公式：周报 `{部门}工作周报`；请示函 `关于{请示事由}的请示`；会议通知 `关于召开{会议名称}的通知`；工作总结 `{总结主体}{总结时段}工作总结`（缺失字段以 `____` 代入） |
| **V3 称谓顶格** | 仅请示函（`{主送机关}：`）与会议通知（`{主送对象}：`）：第二非空段无首行缩进、全角冒号收尾；周报与工作总结无称谓段 |
| **V4 正文** | 首行缩进两字符（`w:firstLineChars=200`）；run eastAsia=仿宋、16pt（三号）、ascii/hAnsi=Times New Roman；固定行距 28 磅、段前段后 0 |
| **V5 落款** | 末个非空段右对齐、右缩进两字（≈32pt）。周报一行 `报送日期：{报送日期}`；请示函两行 `{请示单位}`+`{成文日期}`；会议通知两行 `{召开单位}`+`{发文日期}`；工作总结两行 `{总结主体}`+`{成文日期}`（日期行为裸日期，无标签） |
| **V6 小节与条目** | 列表小节按"一、二、三、"编号（节头黑体、首行缩进两字符）；条目以 `1．2．3．`（全角点）编号；选填小节缺失整节省略 |
| **V7 占位符** | 必填字段缺失处文中出现字面 `____`（四个下划线） |
| **V8 无时间源** | 文书内容全部由输入数据推导，不含当前时间、随机内容（保证可复现） |

## 7. 错误处理

退出码 `2` = 非法输入被拒：stderr 打印中文错误、**不写任何产物文件、不建产物目录**。四种非法输入：

| # | 非法输入 | 行为 |
|---|---|---|
| 1 | `--template 证书`（不在四类之名） | argparse choice 报错，exit 2 |
| 2 | `--data` 指向不存在的文件 | exit 2，报"数据文件不存在" |
| 3 | `--data` 内容不是合法 JSON | exit 2，报"数据文件不是合法 JSON" |
| 4 | `--data` 顶层是数组等非对象 | exit 2，报"顶层必须是对象" |

注意：必填缺失/选填缺失/模板外键/空列表/字符串型列表**都不是错误**（退出码 0，按 §3.2 记账）。
除 0/2 外不应出现其他退出码；未捕获崩溃属实现质量问题。

## 8. 环境依赖

- Python 3.12+；`python-docx>=1.1`（实测 1.2.0，见 `requirements.txt`；安装 `pip install -r package/requirements.txt`）。
- Windows 假设：入口脚本按 contract §2 以 `python package/scripts/gen_doc.py ...` 直接运行；
  脚本已强制 stdout/stderr UTF-8，避免 GBK 控制台乱码。
- 字体说明：仿宋/黑体是 docx 内的字体**声明**（写入 XML 即达标），渲染字形取决于查看机
  字体库，不做真实渲染目检。

## 9. Agent 工作流（选择模板 → 准备字段 → 调用引擎 → 核对留空字段）

1. **选择模板**：按文书类型在 `周报` / `请示函` / `会议通知` / `工作总结` 四名中严格取同名
   模板（汉字完全一致）；先读 `references/<模板名>.md` 核对该类文书的版式结构与字段规范。
2. **准备字段**：把用户素材整理成顶层对象的数据 JSON——键用 §3.1 字段表的汉字字段名；
   文本字段给字符串，列表字段给字符串数组（给单项字符串也行，引擎按 F3 宽容处理）；
   收集不到的字段**宁缺勿编**（缺了会占位/留空并记账，编造违反"缺数据不编造"）。
3. **调用引擎**：按 §4 命令行运行（模板名、数据路径、输出目录三参数齐全）。
   退出码 0 → 继续第 4 步；退出码 2 → 按 stderr 修正输入（模板名/文件路径/JSON 格式）后重试。
4. **核对留空字段**（交付前必做）：读 `fields.json`，
   - `summary.missing_required_names` 非空 → 文书含 `____` 占位，向用户如实指出缺哪些必填字段，
     补齐后重跑一次即可覆盖；
   - `missing_fields` 中 required=false 的项 → 已按"标签留空/小节省略"处理，交付时说明即可；
   - `summary.unknown_keys` 非空 → 提示这些键未被模板消费（数据里多给的）；
   - `title` 应与预期标题公式一致（§6 V2），发现不符回到第 2 步检查字段取值。
5. **交付**：把 `--outdir` 下的 `文书.docx` 与 `fields.json` 一并交付，缺数据情况以
   `fields.json` 记账为准，不口头承诺"应该没问题"。
