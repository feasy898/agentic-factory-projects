# 获客素材与对比演示设计（Phase 3）

> 合规红线：全部文案不承诺就业、收益、涨薪、涨粉或任何结果类回报；只演示与承诺「交付过程的确定性——每一步有验证命令、有预期输出、可复跑」。

## 一、核心演示：「裸 agent vs 带资产 agent」（第 0 讲主菜）

### 演示 A：会议转写映射（SM）

- 裸臂话术指令：「把这份转写稿的 SPEAKER_00 换成王总」——现场让学员看裸跑输出：格式漂移、无验收手段、好不好全凭感觉；
- 资产臂：`python oracle/map_speakers.py --transcript … --mapping … --out …` + `python eval/runner.py out/student_run1 oracle/out` → 屏幕打出 **4/4 checks，exit 0**；
- 反手演示红路：`python eval/runner.py _red_empty oracle/out` → **exit 1**。「评测器连空交付都拦得住——这就是确定性」。

### 演示 B：部署包生成（DP）

- 裸臂：让 agent 现场写一个 docker-compose——学员检查有没有漏服务、漏环境变量，全靠肉眼；
- 资产臂：`gen_deploy.py --services asr,minutes,todo --out …` + `validate.py --pack …` → **ALL GREEN 7 pass**；再故意删一个服务 → **C 项击穿，机器判红**。

### 演示 C：数据背书（只引用台账真实数字，注明出处）

- 双臂盲评历史轮：Δ+5.25 / +1.20 / +6.10，三包 8/8、5/5、5/5 全胜（REGISTRY L14-L16，2026-09-30 轮）；
- 扩线首批小样本：zctl-mcp 2/2、acceptor-agent 2/2（2026-10-02 夜班登记节，n=2 标签互换）；
- 演示话术：「同一批评委、双臂盲评、标签互换——资产臂胜率与 Δ 全部留在台账里，可复跑对账」。

## 二、三则报名钩子文案（合规版）

### 钩子 1（痛点型）

> 你让 AI 写过部署包吗？写完你敢直接用吗？
> 来课堂上亲手跑一遍：一条命令生成、一台机器判收（ALL GREEN 7 项），
> 红路演示告诉你什么叫「评测器连空交付都拦得住」。
> 你带走的不是截图，是 6 条能在自己电脑上复现的命令。

### 钩子 2（确定性型）

> 我们讲课不靠 PPT，靠 exit code。
> 三个真实资产、六道确定性门、学员当场交付当场验收——
> 每一步都有「操作+验证命令+预期输出」，走不走得通，机器说了算。

### 钩子 3（产线型）

> 这门课背后是一条产线：生成 → 确定性评测 → 双臂盲评 → 体检 → 准入入册。
> 18+ 资产在册，台账公开可查（REGISTRY）。
> 你学的不只是三个工具，是「把 agent 的活变成可验收交付」的完整方法。

## 三、使用纪律

1. 所有数字必须能指到 REGISTRY/eval-round 的具体行与文件；不允许「最高提升 10 分」式无出处话术；
2. 红路演示必须保留 exit 1 画面——「敢演示失败路径」本身是信任资产；
3. 每则钩子末尾固定附一句：「课程只承诺带你走通真实交付的过程，不承诺任何就业或收益结果。」
