## 五、Agent 配置体系与 kit 冒烟结果

### 5.1 KIT-SPEC v0.1 要点（`v2/agentkit/KIT-SPEC.md`，本轮全文实读）

- **定义**：kit = 面向一个任务域的专用 agent 全部配置件 + 「按任务配置」说明书的打包资产；三判定标准——域集中、可装配（AGENTS.md 指引下全部路径 kit 内相对引用）、可整包评测（EVAL.md 双臂方案对接 EVAL-SPEC §6.3）。kit 是**组合资产**：引用单件而不重复实现，验收单位是整包；引用的单件必须标注验收状态。
- **范式来源（如实）**：任务指定的 `alibaba/cloud-agent-handbook` 经 WebSearch 实测**不存在**；实访最接近权威 **aliyun/ai-agent-handbook** 两次（根页 + 02-build），取其 Harness 三主线作骨架——任务（Agent Loop/状态机/门禁）、信息（Context Builder/Session/Memory/Knowledge/Skill）、行动（Action Plane/MCP/A2A/权限/HITL）【KIT-SPEC §0.1-0.2 实访口径】。骨架不给配置件接口，落地件取自 Claude Code 系官方规范：入口件=AGENTS.md 规范、技能件=agentskills.io 标准 + SEP-2640（skill 与 MCP 合流）、护栏件=hooks 33 事件×5 handler、插件件=knowledge-work-plugins 四件套、工具件=MCP 生态、评测件=本厂 EVAL-SPEC v0.2。**如实声明的局限**：骨架与接口面不是同一家的自洽体系，组合方式是本厂决策（KIT-SPEC §4）。
- **全量件清单（9 件）与决策规则**：AGENTS.md（必配，唯一强制入口）、skills（manifest 引用不复制正文，主力技能取验收状态最好者）、MCP（需要读写 kit 外真实系统才配，纯文本进出不配——MCP 只添攻击面）、hooks（「每条红线配一个 hook，模型负责遵守、hook 负责验证」）、commands（≥2 个高频固定工作流才配）、plugin（壳是分发形态不是验收前提，选配）、记忆与知识（知识件随 kit 分发、个人记忆不进 kit）、工具与沙箱（最小权限三档，写类/外发类不低于 ask）、**评测与观测（必配，无豁免——没有 EVAL.md 的目录不是 kit，只是配置文件堆）**。
- **四步配置法**：任务画像五格（输入形态/交付物/确定性要求/风险面/运行环境）→ 选件矩阵（9 件逐条判必配/选配/不配并落选件理由）→ 装配（固定目录骨架，单向引用禁止循环）→ 两级评测（冒烟出方向信号；验收级=EVAL-SPEC §6.3 整包评测：≥5 任务、n≥2、**token 补偿控制**——baseline 放等量中性占位文档，复合线三条件）。
