## 三、方法说明

- **双臂盲评、同模型同通道**：treatment 臂挂载被测资产文档，baseline 臂不挂载；两臂同用 GLM-5.3-Flash（`builtin:bigmodel-coding-plan/GLM-5.3-Flash`，zcode CLI headless 执行），同 prompt 模板、同采样参数，**唯一差异 = 资产挂载**（EVAL-SPEC-v0.2.md §4.1/§4.2-1，`skillfactory/v2/standard/EVAL-SPEC-v0.2.md:206-216`）。
- **甲乙交替**：两臂产物落盘为 `tasks/<slug>-tN/arm-a|arm-b/OUT.md`，甲乙（呈现位置）按协议在任务间轮换，防顺序偏置（§3.2-4，`:150`）。裁判盲态、禁止同情分、评分必须附实测证据——本轮判词可见大量「python 复算/脚本复跑/抓取官方仓库/GitHub API 实测」类证据（§3.4-4，`:168`）。
- **计分口径**：0–10 加权制；Δ = 治疗臂均分 − 基线臂均分；胜率 = treatment 胜任务 ÷ 任务总数，平局不计胜（§3.3）。
- **判定口径**：EVAL-SPEC v0.2 复合线 = Δ≥1.0 且 任务级胜率≥60% 且 反向任务≤1（§3.6，`:176-186`）。按本轮数据复算：仅 lark-cli 三条件全过；redbook-creator 与 excel-mcp-server 仅 Δ 未达线；knowledge-work-plugins、langgpt Δ 与胜率均未达；agents-md-spec、hooks-mastery、wshobson-commands 三条件全不过（后两者反向任务各 2 条）。下发 `accepted` 字段与复算结论一致（8/8 吻合，脚本核对）。
- **数据保全**：本轮 8 组结果的逐任务分数、胜负与判词由评测轮下发；本榜单生成时用脚本将逐任务分数复算聚合值，与下发均分/Δ/胜率逐项对账通过（容差 1e-9，8/8 资产吻合），并核对了胜负 token 与分数的一致性（treatment⇒治疗>基线、baseline⇒基线>治疗、tie⇒相等，全部通过）。**本榜单编写者未重跑盲评本身**；产物原文在 `evalbench/<slug>/tasks/`。

## 四、局限声明

1. **任务规模不足，全部结论为「中期信号」**：每资产仅 3 任务、每任务每臂 1 对产物，低于 v0.2 §3.1-1 的任务数下限（≥5）与 §3.2-1 的每臂重复下限（n≥2）。按协议，<5 任务**禁止**出具验收结论——包括 lark-cli 的「通过」在内，本榜单所有判定都不得作为最终验收依据，须按 v0.2 复检（任务扩至 ≥5、n=2、含裁判复评抽检）。
2. **单轮、无稳态**：单轮 Δ 不满足对外引用单点值的稳态条件（两轮独立同向且均 ≥1.0，§3.7-1）；本榜单数字外引时必须随附任务数、每臂重复数、模型钉版与协议版本（数字四随，§3.7-2）。
3. **MCP/插件型为文档增益评测**：excel-mcp-server（MCP）、knowledge-work-plugins（plugin）评的是文档包增益而非服务本体（§6.2）——结果不等于真实 server/plugin 的运行增益，未验证真实安装运行行为，存在文档-实现漂移风险，证据等级 provisional。
4. **裁判与被测同模型**：双臂与裁判均为 GLM-5.3-Flash，存在同源自评偏置风险；协议规划的跨模型双裁判矩阵升级（§4.2-2）尚未执行。
5. **判词文本截断**：下发 notes 的逐任务判词在多处句中截断（如「lark-base-field-s」「references/lark」处）。`ab_summary.json` 的 `verdicts[].note` 按下发原文逐字保全、未做补写；本榜单引文同此口径，截断处以 [……] 或原样截断呈现。
