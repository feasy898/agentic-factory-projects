# 大表分页读取方案（orders.xlsx · Sheet「订单」）

## 0. 已知条件（照录任务给定事实）

- 工作簿 `orders.xlsx`，Sheet「订单」，第 1 行为表头；
- 自第 2 行起共 **9,876 行数据**（即数据占据工作表第 **2 ~ 9,877** 行：`2 + 9,876 − 1 = 9,877`）；
- 列：A 订单号 | B 客户 | C 金额 | D 状态（读取范围固定 4 列，`A:D`）；
- Excel MCP 工具单次读取有行数上限，按**每页 4,000 行**分页。

## 1. 分页方案：共 3 页，无重叠、无遗漏

**行号换算规则**：数据第 k 行 = 工作表第 k+1 行（表头占了第 1 行）。
**通用公式**：第 p 页起始行 = `2 + (p−1)×4000`；结束行 = `min(起始行+3999, 1+总数据行数)`。

| 页次 | 覆盖数据行 | 工作表行号 | 读取范围 | 本页行数 |
|---|---|---|---|---|
| 第 1 页 | 1 ~ 4,000 | **2 ~ 4,001** | `A2:D4001` | 4,000 |
| 第 2 页 | 4,001 ~ 8,000 | **4,002 ~ 8,001** | `A4002:D8001` | 4,000 |
| 第 3 页（末页） | 8,001 ~ 9,876 | **8,002 ~ 9,877** | `A8002:D9877` | **1,876** |

页数 = ⌈9,876 ÷ 4,000⌉ = **3 页**（前 2 页只能覆盖 8,000 行，余 1,876 行进第 3 页）。

- **无重叠**：每页起始行 = 上一页结束行 + 1（4,001+1=4,002；8,001+1=8,002），行区间两两不相交；
- **无遗漏**：三页合并恰好是连续区间 2 ~ 9,877，即全部 9,876 条数据。

## 2. 核对总量的方法

1. **页行数之和 = 数据总行数**（主校验）：
   `4,000 + 4,000 + 1,876 = 9,876`，必须等于给定数据总行数 **9,876**；不等即分页设计有误。
2. **连续性校验**：下一页起始行 − 上一页结束行 = 1（得 4,002−4,001=1、8,002−8,001=1），保证既不重叠也无缝隙。
3. **全局跨度校验**：末页结束行 − 首页起始行 + 1 = `9,877 − 2 + 1 = 9,876`，与总数据行数一致。
4. **与工具返回核对**：逐页实际读取后，把每页实际返回的数据行数累加，应等于 9,876；若工具能报告已用区域（used range）/总行数，其最大行号应为 **9,877**（= 1 行表头 + 9,876 行数据）。
5. **边界行抽检**：A2 应是第一条订单、A9877 应是最后一条订单；A4001 与 A4002、A8001 与 A8002 应是相邻的两条订单（用于确认分页切割处没有丢行/重行）。

## 3. 最容易出错的两个边界及本方案的规避方式

### 边界一：首行偏移（表头占用第 1 行）

- **错法**：把"前 4,000 行"直接写成 `A1:D4000`。这样第 1 页混入表头、实际只读到 3,999 条数据，且后续每页整体上移 1 行，末尾必然丢最后一条数据——这是 Excel 行号（含表头，从 1 起）与"数据行序号"（从第 2 行起）之间的差一错误。
- **本方案规避**：显式建立换算规则"数据第 k 行 = 工作表第 k+1 行"，首页从 **A2** 起读、完全不含表头；每一页的工作表行号都由公式 `2 + (p−1)×4000` 推出，而非由数据序号直接充当行号。

### 边界二：末页余量（总数不是页大小的整数倍）

- **错法 a**：末页也按整页写 `A8002:D12001`（8,002+4,000−1），会越界读到大量空行，可能触发工具报错或混入空记录；
- **错法 b**：末页结束行顺手写成 **9,876**（`A8002:D9876`），恰好漏掉最后一条数据——因为最后一条数据在**第 9,877 行**，不是第 9,876 行。
- **本方案规避**：先算余量 `9,876 − 2×4,000 = 1,876`，末页行数按余量截断（1,876 行，而非 4,000）；末页结束行用 `1 + 总数据行数 = 9,877` 收口，得到 `A8002:D9877`；再以第 2 节的"和 = 9,876 + 跨度 = 9,876"双重校验兜底。
