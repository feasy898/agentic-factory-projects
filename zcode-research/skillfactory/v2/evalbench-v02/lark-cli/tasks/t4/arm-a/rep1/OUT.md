## 4. 命令清单（按序直接执行）

### ① 获取 tenant_access_token

```bash
TENANT_ACCESS_TOKEN=$(curl -s -X POST 'https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal' \
  -H 'Content-Type: application/json; charset=utf-8' \
  -d '{"app_id":"<APP_ID>","app_secret":"<APP_SECRET>"}' \
  | jq -re '.tenant_access_token')
```
**理由**：后续发送以应用身份鉴权，必须先取 `tenant_access_token`（依据 ①）；`jq -re` 在取不到 token 时以非零退出中断，避免带着空 token 误发。

### ② 发送 → 群「3.8 迭代同步群」（`oc_aaa111`）

```bash
curl -s -X POST 'https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=chat_id' \
  -H "Authorization: Bearer $TENANT_ACCESS_TOKEN" \
  -H 'Content-Type: application/json; charset=utf-8' \
  -d '{"receive_id":"oc_aaa111","msg_type":"interactive","uuid":"gray38-plan-change-oc_aaa111","content":"{\"type\":\"template\",\"data\":{\"template_id\":\"<TEMPLATE_ID>\"}}"}' \
  | tee /tmp/lark_send_oc_aaa111.json | jq -c '{code, msg, message_id: .data.message_id}'
```
**理由**：按官方格式向第一群发送已发布的搭建模板卡片（`receive_id_type=chat_id` + `msg_type=interactive` + `content` 为序列化 JSON 字符串，依据 ②③）；`uuid` 保证网络重试不会重发重消息；`tee` 留存响应原文供汇报与排查。

### ③ 发送 → 群「测试环境通知群」（`oc_bbb222`）

```bash
curl -s -X POST 'https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=chat_id' \
  -H "Authorization: Bearer $TENANT_ACCESS_TOKEN" \
  -H 'Content-Type: application/json; charset=utf-8' \
  -d '{"receive_id":"oc_bbb222","msg_type":"interactive","uuid":"gray38-plan-change-oc_bbb222","content":"{\"type\":\"template\",\"data\":{\"template_id\":\"<TEMPLATE_ID>\"}}"}' \
  | tee /tmp/lark_send_oc_bbb222.json | jq -c '{code, msg, message_id: .data.message_id}'
```
**理由**：同 ②，第二群；使用与 ② 完全相同的 `<TEMPLATE_ID>`，三群内容一致由同一模板保证。

### ④ 发送 → 群「灰度值班群」（`oc_ccc333`）

```bash
curl -s -X POST 'https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=chat_id' \
  -H "Authorization: Bearer $TENANT_ACCESS_TOKEN" \
  -H 'Content-Type: application/json; charset=utf-8' \
  -d '{"receive_id":"oc_ccc333","msg_type":"interactive","uuid":"gray38-plan-change-oc_ccc333","content":"{\"type\":\"template\",\"data\":{\"template_id\":\"<TEMPLATE_ID>\"}}"}' \
  | tee /tmp/lark_send_oc_ccc333.json | jq -c '{code, msg, message_id: .data.message_id}'
```
**理由**：同 ②，第三群。三条发送顺序执行（同 token 有效期内完成，间隔远小于 5 QPS 限频，无并发需要）。

### ⑤ 汇总并汇报（本地聚合，不再调用任何查询接口）

```bash
jq -c '{file: input_filename, code, msg, message_id: .data.message_id}' \
  /tmp/lark_send_oc_aaa111.json /tmp/lark_send_oc_bbb222.json /tmp/lark_send_oc_ccc333.json
```
**理由**：把三份已留存的响应汇总成三行 `code/message_id`，直接作为向用户的汇报内容；任务要求「发送完成后直接汇报、不做多余查询」，故**不回读消息、不查询群信息**，仅本地聚合。

## 5. 占位符与返回值来源表

| 占位符 | 含义 | 来源 |
|---|---|---|
| `<APP_ID>` / `<APP_SECRET>` | 机器人应用凭据 | 飞书开发者后台「凭证与基础信息」/ 凭据管理者提供；本会话未获取（未实例化） |
| `<TEMPLATE_ID>` | 搭建工具发布的卡片模板 ID | 步骤 A3：卡片搭建工具发布页复制的模板 ID（模板内容即步骤 A1 的标题/正文/按钮） |

| `message_id`（三群） | 每群发送结果的消息 ID | 对应命令 ②③④ 响应的 `data.message_id` 字段（依据 ②）；同时检查 `code == 0` |

## 6. 注意事项

- **内容一致性**：三群共用同一 `<TEMPLATE_ID>`，正文不可能出现三群不同文案；若需临时改文案，只能在搭建工具改模板后重新发布，不可在命令里改 JSON。
- **失败处理**：任一响应 `code != 0`，先核对该群 `chat_id` 与模板是否已发布（200380 = 模板未发布，依据 ⑤）；token 失效则重跑命令 ①。
- **安全**：凭据不进 shell 历史/日志/git；`/tmp/lark_send_*.json` 为飞书返回体，汇报后可删除。
- **未实测声明**：本会话无真实凭据且 chat_id 为任务给定占位值，命令未实际调用成功过；全部端点/字段/格式均以第 1 节官方文档与官方 SDK 为唯一依据。
