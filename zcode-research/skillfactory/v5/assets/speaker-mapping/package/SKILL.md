# SKILL：说话人标签 → 人名映射（人机协作）

## 什么时候用

你手上有一份**说话人分离（diarization）产出的转写稿**：行首是 `[时间戳] SPEAKER_XX:`。
目标：把 `SPEAKER_XX` 换成真实人名（王总/李工……），且除标签 span 外一个字节都不动
（时间戳、冒号、正文、行尾、行数全部保持原文）。

分工原则：**机器做机械扫描与替换，人负责拍板"谁是谁"**。Agent 不得替人编造人名，
只能提供上下文线索、候选与草稿。

## 三步流程

### 第 1 步 discover —— 机器扫描（agent 执行）

```bash
python map_speakers.py --discover --transcript T.txt            # 打印到 stdout
python map_speakers.py --discover --transcript T.txt --out draft.json   # 或写文件
```

得到 JSON：`transcript`（路径回显）、`total_utterances`（标签行总数）、
`speakers`（**按首次出现顺序**，含每人发言数）、`draft_mapping`（每个标签 → 空字符串）。

- 给人看：几个说话人、谁话多（话多者通常是主持人/主讲）。
- `draft.json` 就是第 2 步要填的表，可直接分发。

### 第 2 步 人工确认 —— 填名（人主导，agent 辅助）

把 `draft_mapping` 里的 `""` 逐个填成真实人名，存为确认稿（如 `confirmed.json`）。

- **人**：对照会议主题/称呼/发言内容判断每个标签是谁；拿不准的**先留 `""`**——
  空字符串值视为未映射，工具会原样保留并警告，绝不会错替换。
- **agent 辅助**（不拍板）：把每个标签的首条/全部发言摘出来给确认人看；
  提示统计特征（发言条数、首次出现时间）；把改好的 JSON 回显给人复核。
- 填名完成后由人确认一遍再进第 3 步。

### 第 3 步 apply —— 机器替换（agent 执行）

```bash
python map_speakers.py --transcript T.txt --mapping confirmed.json --out T_named.txt
```

看退出码与 stderr：

| 信号 | 含义 | 动作 |
|---|---|---|
| `WARNING: 未映射说话人标签 "X"，出现 N 次，已原样保留` | 有标签没填名 | 回第 2 步补填（或明确决定保留） |
| `WARNING: 映射键 "X" 在转写稿中未出现` | 映射里的键写错/稿里没这个人 | 回第 2 步核对键名 |
| `INFO: 写出 …（共 N 行，替换 X 处，未映射 Y 种）` | 汇总信息 | — |
| exit `0` | 成功（含仅警告） | 交付产物 |
| exit `2` | 输入文件不存在 / 参数错误 | 检查路径与参数 |
| exit `1` | 映射文件不是合法 JSON / 顶层非对象 | 修 JSON 后重跑 |

补填后重跑即可；对已映射产物重复跑同一映射是**幂等**的（中文名不匹配标签正则，
输出与输入逐字节一致，exit 0）。

## 为什么这个流程敢自动化（安全特性，spec.md R2/R3/R4）

- 只替换行首标签 span：时间戳段、冒号（半角/全角）、空白、正文逐字节不动；行数不变；CRLF/LF 行尾按原文保留。
- 未映射标签**原样保留 + 汇总警告**，绝不猜名替换。
- 行中出现的 `SPEAKER_xx:`（时间戳不在行首）不识别为标签，不会被替换。
- 输出确定性：同输入同映射重跑，产物逐字节一致；无网络、无随机、无时间戳。

## 已知限制（spec.md R10）

- 英文冒号行（如 `Note: ...`）也命中标签正则：discover 会计为标签、apply 时若未映射会警告——人工确认时注意甄别。
- 标签 token 仅支持 ASCII（`SPEAKER_00`、`Agent_A` 等）；中文标签不支持（这也是幂等性的来源）。
- 一行只识别行首一个标签；输入约定是已含 `标签:` 行的文本转写稿，本工具不做说话人分离本身。
