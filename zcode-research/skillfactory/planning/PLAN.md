## 1. 战略主线与北极星

### 1.1 一句话主线

**资产=弹药，eval=壁垒，迭代到合成极限再交 owner。** 本工作区为人类讲师提供资产弹药（owner 拍板 3），资产本身要真的有价值：竞争优势是「专有 eval 集驱动的资产迭代」（owner 意图 3，本厂实测不同任务类型增益差 6.6 个 Δ 点：−0.5 到 +6.10，轨迹1 §2.3）；进入真实人类使用的决策权留 owner（§3.7）。

### 1.2 指标体系（北极星 + 先行指标）

| 层 | 指标 | 定义 | 依据 |
|---|---|---|---|
| 北极星（资产价值） | **合成极限达成 + 弹药包交付** | 三型资产迭代至四信号全绿（§3.7），连同增益档案、内部指南、任务包、验收尺交付 owner（§7 WS14） | 意图 3；轨迹3 RC-13 |
| 主指标（迭代） | **delta_vs_prev** | 三臂对照中 A_new vs A_old 的配对差 | 轨迹3 RC-4：边际才是「不断跑迭代」的主指标 |
| 先行指标（真实分布） | **内测红率** | 每轮内测中任意输入验收尺（§6.3）判红比例 / 总内测产物；趋势上升=资产对未见输入覆盖在退化 | 轨迹4 §2.9「课堂红率」思路的内测化（v1.1：数据源从课堂改为内测） |
| 质量底线 | **题面缺陷率** | 每轮抽审失败题的归因中「题面问题」占比，>10% 该轮数字不得引用 | 轨迹3 RC-8 |

### 1.3 五条战略原则（每条注明依据）

1. **A 值优先于市场规模**：先选「资产增益已被实证」的任务，再谈市场大小；选错任务类型，eval 迭代到极限也到不了可售增益（轨迹1 推理链 1；反例：paper-to-skill Δ−0.5，REGISTRY.md:28）。
2. **三形态互补三角**：skill 注入知识（怎么做对）、MCP 注入动作（能办成事）、agent 设置/护栏注入执法（错误必然被拦）；交付确定性来自三角咬合，缺任一角就塌（轨迹2 链 1）。
3. **bench 是软件，要像软件一样维护**：语义版本 + removed/fixed/added 三分类 CHANGELOG + reuse→regrade→rerun 次序（轨迹3 RC-9；Terminal-Bench 4.0 实访）。
4. **资产价值判据 = 未见输入上的验收尺绿与三臂增益**：合格的资产是「对未见输入仍产出合规产物、且增益可复现」，不是 oracle 复现（轨迹4 结论 2 与轨迹1 推理链 2 的汇合；v1.1 由课堂判据内化为资产判据，装置见 §6.3）。
5. **通道现实决定矩阵**：模型矩阵的臂位排布由本机实测遥测决定（限流率、可达性），不由文档声称决定（轨迹5 §2.1/§2.5，db 级证据）。

## 2. 高价值任务类型定义

### 2.1 选型框架（五维 + 三门 + 定律 + 立项门）

- **五维打分**（1–5 分）：F 频率 / B 可感知收益 / P 痛感 / D 非专业开发者可交付性 / A 资产可加成性（轨迹1 §2.1）。
- **三道工厂适配门**：E 门（确定性可验收：能否造 oracle+runner）、R 门（现有资产复用度）、L 门（合规与责任风险）（轨迹1 §2.2）。
- **选任务定律**（轨迹1 §2.3，置信度高，基于本厂双臂盲评实测）：**A 分高的任务画像 = 领域程序性 know-how 密集 + 输出格式强约束 + 可机判的结构/格式/合规要求**；A 分低 = 通用能力任务（裸模型已够好）或纯连接需求（那是 MCP 的活）。
- **立项预检门（新增，硬门）**：任何新任务类型立项前先跑「3 任务 × 双臂 × 2 重复」迷你盲评，**Δ<1.0 不立项**（轨迹1 建议 2——定律的可操作化，比市场论证便宜且可复算）。首发三型中 meeting-minutes 已有 Δ+5.25（v0.2 规模）、hot-templates Δ+6.10（B 级留档）可豁免；office-templates Δ+1.20 为单轮信号，须按新协议复跑确认（见 §7 WS4）。

### 3.2 三臂对照与主指标（轨迹3 RC-4，采纳）

- **臂结构**：`none`（裸模型）/ `A_old`（上一版资产）/ `A_new`（本版资产）。首轮基线轮为两臂（none / A_cur），**自第二次资产迭代起强制三臂**。
- **落盘字段（固定，防「Δ」一词三种含义）**：`delta_vs_none`（资产总价值）/ `delta_vs_prev`（本次迭代边际，**主指标**）/ `delta_vs_none_prev`。
- 依据：arXiv:2608.11888 差分分析框架（307 例 skill 致害 = 125 功能失效 + 182 效率回退，效率回退在两臂框架里不可见）；三臂免费得到三个数字。四臂（组合臂）排三臂跑通之后（§4.4）。
- **饱和问题（为什么必须改）**：现有主力题集 treatment 臂均分恒为 10.0（meeting-minutes 8 任务 treatMean 全部=10，轨迹3 实读），按 Terminal-Bench 4.0 定义已饱和——**饱和的度量计测不出迭代**，当前 bench 只能回答「有没有资产」，不能回答「这版比上版好在哪」（轨迹3 RC-3）。
- **难度带**：L2 迭代题锚在 **treatment 臂通过率 60%–90%**（无资产臂 20%–50%）；treatment >90% 进轮换池，<60% 进归因五分类。**[假设] 具体数值带待首两轮实测校准，不得写成已验证数字**（轨迹3 RC-6/风险 4）。
- **指标结构**：保留 0–10 rubric（可解释性）+ **并置任务级二元 pass/fail**（进 McNemar 检验、画饱和曲线的量）；均分差报 bootstrap 95% CI。三种「没差异」必须分开报：`真无差异` / `测不出差异（天花板）` / `不可判（ujudgeable+infra）`（轨迹3 RC-11）。

### 3.3 任务包格式（轨迹5 §2.3，采纳）

```
packs/<task-id>/
  brief.md          任务指令（两臂逐字相同；禁出现资产名，EVAL-SPEC §4.3-2）
  inputs/           黄金输入（两臂同等提供，§4.3-4）
  rubric.md         维度×权重×0/6/10 分档（§5.1 L3）
  out/<arm>-<run>/  臂产物
  transcript/       过程轨原始转录
  records/          model_pin.json / exit_code / wall_ms / token
# oracle/ 不入包——留在包外，只有裁判可见（§4.3-4）
```

**两条硬不变量（可机检）**：
1. 每臂 cwd 是一份 **inputs-only 独立目录树**，资产树与 oracle 树都不在其中；臂要跑生成器必须先复制到自己的 scratch 副本。
2. **跑批前后各算一次 oracle 树 sha256，不一致即 abort**。——存在性理由：`hotwords/oracle/run_all.py:31,56-58` 硬编码 `OUT=oracle/out` 且 `shutil.rmtree(OUT)`，K-3 彩排 D3 已实际触发一次清空参照区（classroom/rehearsal/round-1/record.md:42）；多臂并发下这是头号事故源（轨迹5 §2.3）。

**runner 零改动铁律**：`v5/assets/*/eval/runner.py` 一个字不改（TASK.md:76 红线 + 红路 fail-closed 是 A 级信用资产，BASELINE.md:100）；任务包用**薄封套** `checks/run_check.py` import 资产树里的原版 runner 透传 exit code——装置钉版在文件层可查（轨迹5 §2.3）。

### 3.4 分层规模（轨迹3 建议 6.3，采纳；数字含 [假设] 待校准）

| 层 | 题数 | 模型 | 臂 | n | runs | 用途 | 触发时机 |
|---|---|---|---|---|---|---|---|
| smoke | 3 | 1 | A_new | 1 | 3 | 改动后 5 分钟回归，红即停 | 每次资产改动 |
| dev | 8（3 题来自 holdout 公开子集） | 1–2 | 3 | 2 | 48–96 | 版本比较主力，判迭代是否有效 | 每轮迭代 |
| full | 25 | 2（补齐后 4） | 3 | 2 | 300（600） | 里程碑验收 + 增益档案 | 每里程碑 |
| holdout | 10 | 2（补齐后 4） | 3 | 2 | 120（240） | **只报不调**，防过拟合 | 里程碑 + 交付 owner 前（WS14） |

注：**盲评门（L2 准入）以 dev 轮规模为底线**（≥5 任务、每臂 n≥2、三类用例配齐——满足 EVAL-SPEC §3.1-1/§3.2 出具验收结论的最低规模）；full 轮服务增益档案与里程碑。

**holdout 纪律**：holdout 题永不进入任何资产作者/迭代者上下文；真实素材回流数据只进 dev/full，永不进 holdout；每轮结束对全部转录做资产正文片段扫描，命中即该题两臂作废（EVAL-SPEC §4.3-3「污染即作废」）。

**v1.1 holdout 取舍明示**：班级向反作弊/防泄漏应急已随课堂删除（owner 自理区）；上表 holdout 层与 §3.5 防污染纪律保留并压缩——理由：「资产要真的有价值」（owner 拍板 3）依赖**诚实的增益度量**，holdout 防的是**我们自己迭代过拟合 dev 题**，不是防学员；若 owner 认为连这也不要，可再砍（届时增益数字只能标注「dev 内自洽」，不得声称泛化）。

### 3.5 防污染纪律（轨迹3 RC-7，采纳）

公开 bench **借结构不借实例**：借 SpreadsheetBench 的多测试表判分（每题 ≥2 实例变体，两变体都对才算过）、terminal-bench 的三件套与端态验证、TB4.0 的版本纪律；实例与 oracle 全部自造（直接搬 SpreadsheetBench 912 题被否决：域不对+污染+授权，见附录 10.2）。

**防污染三件套 + 断网**：
1. **nonce 化实例**：每题关键实体（人名/编号/日期/金额/部门名）生成时注入一次性随机值，oracle 参照产物由独立参照实现按同一 nonce 程序化生成。
2. **holdout 物理隔离 + 转录扫描**（形态按 §8 O-11 建议默认值：独立目录 + 访问纪律 + 扫描兜底）。
3. **禁止外网取解**：跑批 harness 出口按题类型分（本题不需要外网 → 断网跑），封死 Terminal-Bench ForgeCode 那种「curl 解法进 AGENTS.md」的路径。

### 3.6 题面缺陷率纪律（一等指标，轨迹3 RC-8，采纳）

- 每轮 L2 跑完，抽 **20% 的失败题（绝对下限 5 题）** 做根因审计，三分类：`模型问题 / 题面问题（歧义|约束互斥|兜底缺失|参照错）/ 装置问题（infra）`。
- **题面缺陷率 >10% 时该轮分数不得用于任何引用**（含内部交付档案；v1.1 无对外口径）。
- 本仓实证：v5/eval-round-20261001/scorecard.md 一轮 41 门 38 PASS / 3 FAIL，**3/3 全部诊断为 bench 侧问题**（墙钟戳口径过严 / 对比口径 / 平台路径形态）——失败不是模型不行，是尺子坏了。
- 每次修题留档（题号/旧文本/新文本/缺陷类型/判定人）并 bump bench 版本。

### 3.7 饱和判定与合成极限判据（轨迹3 RC-13，采纳；v1.1：切真实人类改为建议书）

**饱和定义**（TB4.0 口径）：最新一代模型在某题 solve 5/5 → 该题移出迭代池。**「treatment 打满」是「该加题了」，不是「资产到顶了」**。

**合成极限达成 = 四信号合取**：

| 信号 | 定义 | 阈值 |
|---|---|---|
| S1 饱和 | sat% ≥60% 的题已移出迭代池 | 全绿 |
| S2 边际 | delta_vs_prev 相对变化连续 3 轮 ≤0.10 且方向不显著 | **[假设] 阈值待首两轮校准** |
| S3 反向 | A_new 任务均分 < A_old 的任务数 | ≤1（EVAL-SPEC §3.6③） |
| S4 题面可信 | 题面缺陷率 | ≤10% |

+ 已积累 ≥2 个完整里程碑的迭代数据 → 产出「**进入真实人类使用**」建议书，**决策权留 owner**（§8 O-12 v1.1 已裁定；§7 WS11/WS14）。若 owner 决定启动，L3 有自己的回退门（EVAL-SPEC §5.3-2 三条件：无任务 treatment=0；无任务基线反超 ≥1.0；真实集 Δ ≥ −0.5）——判据保留供建议书引用。

### 3.8 bench 自身迭代机制（轨迹3 RC-9/RC-12，采纳）

- **语义版本 + CHANGELOG 三分类**（removed 附饱和证据 / fixed 附缺陷类型+复现命令 / added），跨版本 Δ 禁止并列（EVAL-SPEC §4.4）。
- **变更次序**：reuse → regrade → rerun（能复用旧 trial 先复用；判分标准变了才 regrade；题本身变了才 rerun）。
- **通胀对策（硬规则）**：每新增 N 题必须退役 M 题（**[假设] N:M 起步 4:1，首轮后按实测调**）。
- **先修尺子再加题**：新增题目的前置门 = **checker 对拍**（用人工金标样本反测 checks，准确率与召回各自 ≥95%；EVAL-SPEC §6.4-1 写了门槛但从未执行，REGISTRY 已把 office-eval-suite「对拍法未做」列为欠账）。理由：ELT-Bench-Verified 证明错误 ground truth 会系统性惩罚正确输出；加得越多废得越多。
- **题面种子与蒸馏四段**（成本为 [假设]，首两轮用实测替换）：
  - 起点：office-eval-suite oracle 版 50 题/8 域（程序化率 67.4%，实测高于 50% 底线）；
  - 改造：① 注入 nonce；② 每题扩 ≥2 实例变体；③ 替换裸字面量存在性 check（现占 15.7%，实测）为结构化断言或改判 semantic；④ 三层用例配比（positive / near-negative / adversarial，EVAL-SPEC §3.1-2）；⑤ 首轮 8 题试跑做难度标定；
  - D1 来源→题面（四项自检，人工过）→ D2 题面→实例+oracle（同种子逐字节可复现、生成器红绿自检）→ D3 判分器化（人工金标对拍 ≥95%）→ D4 校准入池（难度带内才入池）。**全自动蒸馏被否决**：人工必须过 D1 和 D3。

## 4. 资产体系

### 4.1 形态学与三角咬合（轨迹2 链 1，采纳）

按**注入面**划分（否决「技术载体」三分法）：

| 形态 | 注入什么 | 不能做什么 | 交付角色 |
|---|---|---|---|
| skill | 上下文（知识/流程/约束） | 新增动作能力；强制执行 | 让使用者**做对** |
| MCP | 能力（真 API/真数据/真子进程） | 提升知识判断（装了不会用=零增益） | 让事**真能办成** |
| agent 设置 | 角色与护栏（专责角色 + hook 确定性拦截） | 角色文本本身无执行力 | 让错误**必然被拦** |

### 4.2 任务包 bundle 规格 v1（轨迹2 链 4/链 6 + 建议 2/3，采纳）

**交付单元 = 任务包 bundle**（一个任务类型 = manifest 绑定的 skill(s)+MCP(s)+设置+eval+走查，版本化为一个分发单元）；单件资产只是 bundle 的构件。依据：一次真实交付的最小可独立走通单元是 bundle（v1.1：售卖/分发归 owner，交付对象为内部指南与模拟任务包）；EVAL-SPEC §6.3 整包 kit 评测协议（含 token 补偿控制 :292-299）已就位。

- **双根结构**：资产根（工厂内不分发：`spec.md` + `contract.md` + `eval/runner.py` + `oracle/` + 可选 `blind/`）+ 交付根 `package/`。
- **manifest 字段**：`name / version(semver) / form(TAXONOMY 14 形态之一) / license / compatibility / standards(skill_spec 与 mcp_protocol 钉版+查询日期) / task_types / dependencies(资产依赖+外部二进制+运行时) / eval(runner sha256 + oracle 指纹 + 红路矩阵) / clients(支持矩阵) / evidence(三齐状态+evidence_level)`。
- **分形态 package 布局契约**（按 §8 O-4 建议默认值先收窄三形态，hook 留接口）：
  - `skill`：严格 agentskills.io 布局（目录名=`name`；必备 name/description；version 入 metadata；**禁止自造顶层字段**）；
  - `mcp`：server 实现 + INSTALL.md（四节模板：前置/安装片段/自检绿红双路/安全说明，zctl-mcp 已是样板）+ `oracle/expected_tools.json` 工具集恰等+forbidden 双向冻结；manifest 记 mcp_protocol_version；
  - `agent-config`：**双层**——`agent.md` 通用角色定义（职责/输出契约/禁令三节，acceptor-agent 模式）+ 每客户端适配薄壳（无跨端标准，内容与壳分离）。
- **bundle 自带 eval**（整包 kit 评测法），防「混装后反而变差」不可知；blind/ 样本剥离到 bench 侧（盲态隔离更干净）；oracle 新鲜度/重建、benchmark.json 落盘、evidence_level 判定权归 bench 侧，资产侧 manifest 只引用（轨迹2 接缝分工）。

### 4.4 组合 / 通用化路线与端到端盲评门（轨迹2 链 4 + 轨迹3 RC-4(c)，采纳）

- **准入铁律（反面教材条款）**：任何路由/合并/分层组合必须过**端到端盲评复合线**（EVAL-SPEC §3.6：Δ≥1.0 且 任务级胜率≥60% 且 反向任务≤1）才准入。铁证：ppt-method-router 确定性门 6/6 全过、路由一致率 1.0（20/20），盲评 Δ0/胜率 33%——**路由对了但端到端零增益**（REGISTRY.md:27）。架构正确≠有增益。

| 触发证据 | 判定 | 动作 |
|---|---|---|
| 产物轨红（runner exit 1），转录命令正确 | 资产**生成侧**缺陷 | 改资产，不改协议 |

### 9.2 方法论与业务风险

- **bench 通胀**（题越多判分质量越降）→ 新增/退役硬规则（§3.8）。
- **裁判漂移**（模型版本升级→裁判行为变化→分数不可比）→ 钉版五元组强制落盘 + 跨族 Δ 不可比条款。
- **范围蔓延**（三型同时铺开、基建不收口）→ 以 meeting-minutes 线先行走通「迭代→判定→交付」全链再横向复制（§7 关键路径）。
- **把「内测没过」归因给测试执行者** → 失败先归因再聚合（五类归因，§6.3），只有「资产缺陷」进 backlog。

### 10.5 内部术语表（v1.1 新增；全文只用内部语言，不讨论对外命名）

| 术语 | 一句话定义 |
|---|---|
| 资产 | 用于通用 agent 后大幅提高其特定任务能力并交付有价值结果的构件（skill、MCP、agent 设置等）。 |
| 任务包（bundle） | 一个任务类型 = manifest 绑定的 skill(s)+MCP(s)+设置+eval+走查，版本化的最小可独立走通交付单元。 |
| 模拟真实任务包 | bench 任务包的实操形态，一物两用：资产内测素材 + 人类讲师演示素材（§6.2）。 |
