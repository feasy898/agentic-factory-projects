## 1. 展开方法

### 1.1 我怎么拆解这个问题

第一约束是人类意图近乎逐字的 #4：「判断一系列适合普通个人——公司职员、小老板、个体户——的高价值任务类型……可以有开发，但一定不面向专业开发者；一定是非专业开发者可以交付的、对他有价值的业务成果。」我把这句话拆成三重约束，任何候选必须同时过：

- **约束 A（人群与成果）**：目标用户是公司职员/小老板/个体户；交付物是他「拿走就能用」的业务成果（一份文件、一组物料、一条可跑的产线），不是一个开发工具。
- **约束 B（产线工艺）**：本工作区只管 skillfactory 产线（BASELINE.md:6 范围声明），产线的准入是「生成 → 确定性评测 → 双臂盲评 → 体检 → 准入入册」（zcode-research/README.md:17）；一个任务类型若造不出确定性 eval（oracle + runner，exit 0/1/2），它在**这条产线上**就等于不可建资产——这与人感觉中的「价值」无关。
- **约束 C（商业模式）**：收费逻辑 = 「听课是仪式、实际是交付——为 Agent 资产的分发收费」（人类意图 #1），仓库口径为「带着学员借助 skill、MCP 直接走一遍获得真实交付的过程，课堂高度确定性」（zcode-research/TASK.md:4）。所以候选必须支撑「课堂内一次可验收的交付」这个动作，且存在现成的付费对标（外包价/SaaS 价/代运营价）。

然后我按三条线收集：① 仓库既有资产与实测增益数字（决定「资产可加成性」的锚点）；② 仓库两份市场研究（六画像需求 + 课程市场证据）；③ 本会话 WebSearch 校准外包价格与耗时调查。

## 2. 「高价值」的可操作定义：评估框架

### 2.1 五个核心维度（任务书给定，1–5 分）

| 维度 | 定义 | 打分锚点 |
|---|---|---|
| **F 频率** | 目标人群多久遭遇一次该任务 | 5=每天/每周多次；4=每周；3=每月一次（或有季节性集中）；2=每季；1=一年一两次 |
| **B 可感知收益** | 交付前后差异能否**当场看见并量化**（省了多少分钟/多少钱/少改几稿） | 5=有明确时间/金额账可算；3=知道有改善但说不清；1=很弱 |
| **P 痛感** | 现状有多疼（拖到最后一刻/怕错被打回/正在花钱外包） | 5=普遍花钱外包或情绪强烈；3=抱怨但忍着；1=无所谓 |
| **D 非专业开发者可交付性** | 非开发者学员在课堂+资产帮助下，能自己交付业务成果的程度 | 5=填表/照手册即可；4=照手册+少量命令；3=需要环境部署等轻度技术动作；2=需写配置/脚本；1=需开发 |
| **A 资产可加成性** | skill/MCP/agent 设置能把「普通模型」在该任务上的表现拉高多少（相对裸模型） | 关键：**本仓库有实测锚点**（见 2.3），不是拍脑袋 |

### 2.2 三道「工厂适配门」（我自己加的，理由见下）

打完五维分我发现还不够：有些任务五维分很高却建不了资产，或者进了首发会把产线拖死。所以加三道定性门：

- **E 门·确定性可验收**：能不能造出 oracle 参照 + runner 确定性检查（强/中/弱）。**依据**：产线信用底线是红路 fail-closed（TASK.md:24 G0-2），meeting-minutes 的全胜增益被归因于「聚焦单能 + 确定性 oracle + 逐字溯源」组合（plan/MASTER-PLAN.md:159）；反之 monthly-report-ppt 正是卡在确定性门（REGISTRY.md:26）。
- **R 门·现有资产复用度**：REGISTRY 18 资产 + v3/v4 基建件能直接踩上多少（高/中/低）。决定 D0-30 能不能出 v0.2 资产。
- **L 门·合规与责任风险**：交付出错的经济/法律后果（低=内部文书改了重写；中=对外内容有平台规则；高=钱和法律责任）。

**弯路 3（框架迭代记录）**：我最初的框架只有五维，第一轮粗评时「月度汇报生成器」因 B/P/D 全高分差点进首发——但它恰恰是被仓库实测拦下的资产（monthly-report-ppt 确定性门未过，REGISTRY.md:26；MASTER-PLAN.md:30 记录 16 项全过与任务下发口径的张力待复裁）。加 E 门后才把它正确拦到「条件转正」位。这个弯路本身就是证据：**五维分预测的是市场价值，E 门预测的是这条产线的可制造性，两者缺一就会误判。**

### 2.3 A 维（资产可加成性）的仓库内实测锚点

这是本研究最有分量的输入：**本厂已经用双臂盲评把不同任务类型的「资产增益」实测出来了**（REGISTRY.md 盲评列 + MASTER-PLAN.md:149-154）：

| 资产（任务类型） | 盲评 Δ | 胜率 | 结论 |
|---|---|---|---|
| hot-templates（四平台爆款内容骨架） | **+6.10** | 100% | 厂史最高——「平台规范/爆款结构 know-how 密集」任务，裸模型很弱 |
| meeting-minutes（会议纪要三段式） | **+5.25** | 100%（8/8） | 「格式强约束 + 逐字溯源反幻觉」任务，高增益 |
| office-templates（四类中文办公文书） | +1.20 | 100%（5/5，单轮信号） | 刚过线——纯模板套壳类任务裸模型差距不大 |
| ppt-method-router（PPT 方法路由） | 0 | 33% | 「路由对了但端到端零增益」——路由不产生价值 |
| paper-to-skill（知识蒸馏器） | **−0.5** | 0% | 「有 skill 反而更差」——相关但误导的流程最害人 |
| lark-cli（第三方飞书技能包） | +1.6875 | 75% | 现成成熟技能包仍有增益空间 |

从这组数字提炼的**选任务定律**（我的归纳，置信度高）：A 分高的任务画像 = 「领域程序性 know-how 密集 + 输出格式强约束 + 可机判的结构/格式/合规要求」；A 分低的画像 = 「通用能力任务（裸模型已够好）」或「只有连接需求没有知识需求（那是 MCP 的活，不是 skill 的活）」。这条定律直接决定了下面每个候选的 A 分，也让「资产可加成性」从口号变成了可预判的筛选器。

### 3.2 逐个论证（交付物 / 痛点 / 竞品 / 提效机制 / 收费场景）

**#1 会议纪要一条龙（F5 B5 P5 D4 A5 = 4.8）**
- 交付物：学员拖入自己的真实会议录音，本机跑出「分发言人逐字稿 + 决议/待办/风险三段式 Word 纪要 + 已登记的催办任务」——文件级业务成果，非开发者可直接交差。
- 痛点（Web，聚合）：中国职场人年均 328 小时耗在无效会议（德勤报告，经 21 经济报道/虎嗅引用）；职场人平均每周花 4 小时整理纪要、30% 行动项被遗漏（deeppath.cc 聚合）。
- 竞品：讯飞听见 0.33 元/分钟、人工精转 18 元起；通义听悟免费额度制；飞书妙记/腾讯会议 AI（Web 聚合）。SaaS 能给「转写文本」，给不了「合本单位格式的成品 docx + 数据不出本机」——录音敏感场景私有化是 SaaS 结构性短板（oss-research-report.md:41「数据不出本机是录音/工资表等敏感场景的刚需」）。
- 提效机制：FunASR/转写链解决「听见」，meeting-minutes 资产解决「写成合格纪要」（Δ+5.25 实证），speaker-mapping/hotwords 解决「谁在说 + 行业热词」（v5 在库），deploy-pack 解决一键私有化部署。**从转写到成品纪要的最后一公里全是本厂资产**。
- 收费场景：课程定价 199–1999 带（MASTER-PLAN.md:234）；ToB 延伸=按席位的小型部署服务。市场基数：中国智能会议工具市场 2025 约 123.6 亿元（虎嗅援引，聚合）。
- 与现有资产衔接：**R 门最高分**——meeting-minutes（dist，REGISTRY.md:14）+ speaker-mapping（L164）+ hotwords（L162）+ deploy-pack（L163）+ office-guard-hooks（PII 拦截，REGISTRY.md:30）全在库，等于这条任务类型的资产链已经基本齐装，缺的只是 bench 加厚与盲评复跑。

**#2 爆款内容与营销文案家族（F5 B4 P4 D5 A5 = 4.6）**
- 交付物：学员输入自家主题+卖点，产出四平台（抖音/小红书/公众号/视频分镜）内容骨架与发布就绪的图文卡片、获客文案与私域话术库。
- 痛点：个体户/小老板日更内容靠自觉；自媒体人「选题枯竭、人工一篇 4-6 小时」（oss-research-report.md:187）；代写市场单价低但量大（小红书文案 20–200 元/篇，Web 聚合）。
- 竞品：代写（单件 20–200 元）、代运营（月费 2000–数万元 + 佣金，Web 聚合）、各平台 AI 助手。我们的位置=「把代运营月费里的内容生产环节用资产+agent 打掉」。
- 提效机制：hot-templates Δ+6.10 是厂史最高盲评——证明「平台规范+爆款结构」是裸模型的强短板、资产的强增益区；content-evaluator（44 极限词+平台阈值，REGISTRY.md:36）把广告法合规变成机判护栏，恰好把 L 门的「中」转成资产卖点。
- 收费场景：对标代运营 2000+/月，「你的店每月 900 条内容骨架+排期表，成本是代运营的零头」；个人付费走 199–1999 课程带。市场基数：触网经济个体工商户 1900 万户（市场监管总局，聚合）。
- 与现有资产衔接：hot-templates（dist，REGISTRY.md:16）+ content-evaluator + prompt-regression；获客文案/私域话术/图文卡片作为同族新 skill 立项（guizang-social-card-skill 7.3k★ 是第三方先例，oss-research-report.md:201）。

**#3 中文办公文书 + 公文格式合规（F5 B3.5 P4 D5 A4 = 4.3）**
- 交付物：合 GB/T 9704 版式的公文、合单位字体字号的周报/请示函/通知/总结 docx，配 fail-closed 格式校验 hook（交付前机器验格式）。
- 痛点（Web，聚合）：超 70% 职场人每周写周报超 2 小时、近三成认为毫无价值（deeppath.cc 2026-09 聚合）；「格式一错就被打回」是打工人 8 类需求之一（oss-research-report.md:89 需求⑤）。
- 竞品：公文写作研修班数百–数千元、遴选协议班 2–5 万元（Web 聚合）——付费意愿已被现有市场验证；「中文公文写作无高质量开源专项（GB/T 9704 版式/文种全无）」是调研确认的空白（oss-research-report.md:115 空白①）——空白即壁垒。
- 提效机制：office-templates Δ+1.20 提示「纯模板套壳」增益弱，所以本候选的资产设计必须把增益压在「格式规则 + 文种结构 + guard-hooks 校验」上——把「被打回」这个痛变成机判对象，这正好是确定性 oracle 的甜点区（版式规则全可机判）。
- 收费场景：体制内与国企行政人群付费意愿强（遴选班价格佐证）；office-templates-skill 已是 dist 候选（REGISTRY.md:15，标注 single_round_signal）。
- 衔接：office-templates + office-guard-hooks（7/7，REGISTRY.md:30）+ office-eval-suite（50 题×8 域×230 checks，REGISTRY.md:35）+ prompt-regression——基建件全齐。

**#4 月度汇报生成器（F3 B5 P5 D4 A4 = 4.2，条件转正）**
- 交付物：指向 Excel 台账文件夹，产出套公司模板、真 PowerPoint 打开不跑版的可编辑 pptx + 一页 Word 摘要。
- 为什么 B/P 都是 5：月末汇报是「一天到两天」的集中痛，「在真 PowerPoint 里不跑版 + 像我公司出的」是可当场验收的差异。

## 4. 关键推理链（含采纳/否决分支）

**推理链 1：先选「资产增益已被实证」的任务，再谈市场大小 → 采纳。**
考虑过的分支：从市场规模倒推（个体户 1.1 亿户 → 什么都能卖）。否决理由：人类意图 #3 明确竞争优势是「专有 eval 集驱动的资产迭代」，而本厂实测已经证明不同任务类型增益差 6.6 个 Δ 点（−0.5 到 +6.10）——选错任务类型，eval 迭代到极限也到不了可售增益。市场规模只决定天花板，A 值决定这门生意成不成立。
（旁证：MASTER-PLAN.md:118 已经实践了同一逻辑——「排产优先级：课程需求倒排」。）

**推理链 2：「课堂 v0.1 教学路径」与「高价值任务类型」存在系统性错位 → 采纳（本研究最重要的横向发现之一）。**
证据：当前课堂三课的学员交付物是——24 个映射 JSON 文件（walkthrough.md:99-103）、三个部署文件 docker-compose.yml/.env.example/DEPLOY.md（walkthrough.md:150-156）、热词库导出文件（walkthrough.md:215-220）。按约束 A（业务成果）衡量：DP 是纯开发者工具，SM/HW 是转写链的零件——**没有一个交付物是小老板/普通职员拿走就能用于他业务的成果**。这不是否定既有工作：SM/DP/HW 三课的真正价值是证明了「过程确定性」（K-3 彩排零上下文走通、6 门全绿，worklog.md:17），它们是**产线的验收仪式**，不是业务的交付成果。处置建议（给撰写者）：教学路径分两层——第 0 讲保留工具件「确定性仪式」（裸 agent vs 带资产 agent 对照，course/outline.md:7-12 已有此设计），第 1–3 讲换成任务型交付（真实录音→纪要、真实卖点→四平台内容、真实场景→公文/周报），背后资产恰好对应三个 dist 包。

**推理链 3：首发任务类型优先选「资产链已在库」的，把「市场大但资产链薄」的排后 → 采纳。**
三个 dist 包（meeting-minutes/office-templates/hot-templates，REGISTRY.md:14-16）与我的首发 #1/#3/#2 一一对应——这意味着首发三型的「资产+eval」半成品已经存在，D0-30 的工作量在「bench 加厚+盲评复跑+课堂化」，而不是从零造资产。反之 #4 汇报生成器、#6 门店工厂、#9 对账都要先造评测资产（模板保真校验器/成片结构校验/票据语义层）。在「迭代到公共知识效果极限再进真实人类使用」（人类意图 #3 总路线）的约束下，先跑满已齐装的线是唯一理性序。

**推理链 4：门店短视频工厂为什么压到第二波 → 采纳（否决「研究报告课程三提前」分支）。**
研究报告把课程三列为优先级第三（oss-research-report.md:42），但那是「市场潜力排序」；其开发序判断（§5.4.1 先课程二后课程一/三）与我的 E 门/彩排时间盒分析同向。加上发布端「平台无发布 API+风控对抗」的结构性风险（oss-research-report.md:424 空白②），首发不碰整链成片，先以 #2 家族的门店模板轻形态落地。

**推理链 5：财税/招聘的砍单理由是「责任与合规」而不是「需求不真实」 → 采纳。**
这两类被砍最容易被误读为「没人需要」。证据恰恰相反：财税有强外包市场（代账 200–500 元/月）、招聘有强工具市场（北森/Moka）——但两者都被专业供给占据了，且错误后果是法律责任/PII 合规。人类意图 #4 要求「非专业开发者可以交付」，而出错担责的交付物不能交给非专业者。这个否决标准值得写进规划的准入原则：**交付责任必须落在学员可承担的范围内。**

**推理链 6：B 线 FunASR 彩排欠账对首发 #1 的影响 → 如实标注。**
REGISTRY.md:216 记录「FunASR 彩排缺音频环境（沿袭）」——首发 #1 的课堂化需要先把音频环境通道打通（anolis-gpu-01 或本机麦克风+样例音频），这是一个工程前置项而非阻塞项（确定性评测本身不依赖音频，依赖的是转写文本 fixtures——v5 资产全是文本 fixtures 驱动）。

## 7. 倾向性结论（逐条标置信度）

1. **首发三型=会议纪要一条龙、爆款内容与营销文案家族、中文办公文书+公文合规**；它们与三个 dist 包一一对应，是 D0-30 内可完成「资产+bench+课程」闭环的最小组合。（置信度：高）
