# spec.md — 会议纪要三段式（转写稿进、决议/待办/风险纪要出）

| 项 | 值 |
|---|---|
| 资产 | `skillfactory/assets/meeting-minutes/` |
| 技能名 | `meeting-minutes` |
| 规格依据 | 参照实现 `oracle/oracle.py` 的**实际行为**（本会话已通读源码并实际运行验证，见文末验证记录） |
| 冻结口径 | 本文规则逐条可判定；实现（package/）可在接口内自由重写，但产物行为必须满足本文 |

---

## 1. 目标

把一份会议口语转写稿（txt，每行一条发言）确定性地转成三段式会议纪要：

- **输入**：一个转写文本文件（UTF-8，容忍 BOM）。
- **输出**：一个输出目录下的两份产物——`纪要.docx`（三段式纪要文档）与 `summary.json`（条数统计）。
- **三段**：一、决议事项；二、待办事项（表格）；三、风险与关注。

不做语义理解、不做摘要改写：**条目内容逐字引用原句**，归类只靠关键词规则。

## 2. 输入格式（R1）

- R1.1 每行至多一条发言，格式：`[hh:mm] 说话人: 内容`（时间括号内 1–2 位时:2 位分；说话人与内容之间的冒号中英文均可；说话人不含冒号）。
  - 正则口径：`^\s*\[(\d{1,2}:\d{2})\]\s*([^：:]+?)\s*[：:]\s*(.+?)\s*$`（oracle.py:29）。
  - 验证：三份样例（`oracle/inputs/case1..3.txt`）全部行命中该格式；合成用例中英文冒号混用可解析。
- R1.2 空行直接忽略（不计入任何统计）。
- R1.3 无法解析为发言格式的**非空行**（寒暄开场、口误更正的无时间戳行、散会行、乱码行等噪声）跳过，不进入任何章节。
- R1.4 命中发言格式、但内容不含任何 11 个关键词（见 R2）的行，同样不进入任何章节。
  - 验证：case1 第 1–2、4 行（寒暄、无关键词发言）未出现在 docx 任何章节；edge 用例"吴十: 今天下午随便讨论。"被丢弃。
- R1.5 文件以 `utf-8-sig` 读取（容忍 BOM）。

## 3. 关键词分类规则（R2）

逐行扫描每个解析成功的发言，按**子串包含**匹配下列 11 个关键词；**一行至多归入一类**，按优先级 决议 > 待办 > 风险 取第一个命中的类（oracle.py:31-35, 103-106）：

| 优先级 | 类别 | 关键词（子串即命中） |
|---|---|---|
| 1 | 决议事项 | 决定 / 议定 / 同意 / 结论 |
| 2 | 待办事项 | 需要 / 负责 / 跟进 / 截止 |
| 3 | 风险与关注 | 风险 / 延期 / 不确定 |

- R2.1 同行命中多类时只归优先级最高的一类。
  - 验证：case3 第 9 行"……一旦出现**延期**迹象……这个**结论**请各位记牢"归**决议事项**（docx 三、风险节中无此条）；合成用例"这个风险很大，我们决定暂停项目"归决议。
- R2.2 分类只看关键词，不看行位置：含关键词的收尾行（如 case2"结论：培训未完成……散会"）照样收录；不含关键词的散会行（case3"谢谢各位，散会"）不收录。
- R2.3 口误更正不做上下文关联：更正前后的行各自独立按关键词处理（case1"我刚才说错了……"无关键词被丢；更正后"我需要再压一轮"含"需要"归待办）。
- R2.4 三类互不重叠：每条目恰属一类；各类条目在 docx 中按**原转写行序**排列（case1 决议节顺序 09:02→09:06）。

## 4. 纪要 docx 结构（R3）

产物 `<outdir>/纪要.docx`，结构固定如下（oracle.py:118-182，三例产物 + edge 用例验证）：

- R3.1 标题段落：`会议纪要`（居中、18pt、加粗）。
- R3.2 元信息段落：`来源：<输入文件名> ｜ 解析发言 <合计> 条（决议 <a> · 待办 <b> · 风险 <c>）`。
- R3.3 节标题三段，顺序固定、文本精确：`一、决议事项`、`二、待办事项`、`三、风险与关注`（各 14pt 加粗）。
- R3.4 决议与风险两节的条目为编号段落：`<i>. 【<hh:mm> · <说话人>】<内容原文>`，i 从 1 连续编号。
- R3.5 待办事项节为一张表格（样式 `Table Grid`），3 列，表头精确为 `事项 | 负责人 | 期限`；每个待办条目一行，事项列填内容原文。
- R3.6 某节条目为 0 时该节标题仍在、其下无条目（edge 用例：决议 0/风险 0 时三标题齐全，文档仍可被 python-docx 打开）。
- R3.7 中文字体显式设为宋体（含 eastAsia）；除此之外不做任何版式要求（页边距、页眉等自由）。

## 5. 待办两列的确定性启发式（R4/R5）

对每个待办条目，从**该条内容原文**中按下列顺序尝试提取，全部失败填 `待定`：

- R4 负责人（oracle.py:37-41, 58-69）：
  1. `我(们)负责` → 该行说话人；
  2. `由|让|交给 + X + 负责` → X（1–6 字，中英文数字·）；
  3. `负责人 是/：/: + X`（X 后跟标点/空白/行尾）→ X；X 为 `我/我们/自己` 时替换为说话人；
  4. `@X`（X 后跟标点/空白/行尾）→ X；
  5. 都未命中 → `待定`。
  - 验证：case2"负责人是我，本周五之前出结果。"→ `质检钱主任`（规则 3 命中"我"→替换为说话人）；case3"公告由医务处负责……"→ `医务处`；合成用例 `交给王五负责`→王五、`负责人：钱七`→钱七、`@周九`→周九；无主语句→`待定`。
- R5 期限（oracle.py:43-50, 72-78），顺序即优先级：
  1. 完整日期（`yyyy年m月d日`、`yyyy-m-d`、`yyyy/m/d` 等变体）；
  2. `m月d日`（可带"之前/前"）；
  3. `(本周|下周|这周)?(周|星期)X`（X=一二三四五六日天，后缀可带"之前/前/以前/底"）；**「本周/下周/这周」前缀只参与命中、不进入提取结果**——提取从 `周X`/`星期X` 起（case2"本周五之前"提取为"周五之前"）；
  4. `本(周|月|季度)(底|末|内)?`；
  5. `今天|明天|后天|月底前?|下月|本周末`；
  6. `截止(于|到|至)?X`（X 取 1–8 个非空白且不属于 `，。；;` 的字符）；
  7. 都未命中 → `待定`。
  - 验证：case1→`周五前`；case2→`5月20日之前`、`周五之前`；case3→`周五`（"明天…截止到周五"行按顺序 3 命中"周五"而非顺序 5 的"明天"）；合成用例`截止到月底`→`月底`（顺序 5）；无时间语→`待定`。
- R4.1/R5.1 负责人与期限仅作用于待办表格，决议/风险条目不解析这两列。

## 6. summary.json（R6）

产物 `<outdir>/summary.json`，UTF-8、四键、缩进 2、不转义中文（oracle.py:201-207）：

```json
{"决议事项": <a>, "待办事项": <b>, "风险与关注": <c>, "合计": <a+b+c>}
```

- R6.1 四键数值必须与 docx 实际内容一致：决议/风险计数 = 对应节编号条目数；待办计数 = 表格数据行数；合计 = 三者之和。
- R6.2 与 R3.2 元信息行中的三个数字一致。

## 7. 命令行契约（R7）

- R7.1 `python oracle.py --input <转写.txt> --outdir <输出目录>`；两参数必填；`--outdir` 不存在自动创建；输入文件不存在时以非 0 退出并报错，不产出文件。
- R7.2 确定性：同一输入重复运行，`summary.json` 逐字一致，docx 的**文本内容**（全部段落 + 全部表格单元格）逐字一致；docx 为 zip，字节级因内嵌时间戳不可比，**不要求**字节一致。
  - 验证：本会话复跑 case1–3 与现存产物比对，`text_equal=True, summary_equal=True` ×3。

## 8. 边界与非目标

- **不做**：语义去噪（噪声仅靠格式+关键词规则排除）、上下文纠错与口误合并、多会议合并、纪要摘要/改写、除 `[hh:mm] 说话人: 内容` 外的转写格式、非 txt 输入（docx/audio）、负责人/期限的语义推断（抓不到就"待定"，不猜）。
- **已知可接受的"错"**（规则如此，不视为缺陷）：含否定词的句子按关键词照样归类（case1"承诺**不能延期**"归风险；"这个方案就**议定**下来"归决议）；关键词命中即整句收录，不截断。
- 空文件/全噪声输入：不报错，产出三节皆空、summary 全 0 的合法 docx（已固化为 golden case4：全噪声转写稿，三标题齐全、待办表格仅表头行、summary 全 0，2026-09-29 增补）。

## 9. 交付物与验收流程（DoD —— 重生成实现必须遵守；2026-09-29 增补）

> 背景与前两轮失败定性：连续两轮重生成中，被测产物目录 `package/out/<case>` 均不存在，
> eval 15 项检查全部以「被测用例目录不存在」判红（runner.py:100-118 前置短路）。这是**交付
> 流程缺陷（未产出被测对象）**，不是行为规则不可满足——见 §10 验证记录：仅依据本 spec 撰写的
> 独立实现对全部 4 个用例可判绿（20/20，exit 0）。本节把"必须先产出被测产物"固化为可判定要求。

- D.1 交付物 = `package/`（`SKILL.md` 与 `scripts/minutes.py` 契约入口等，见 contract §2/§3）**加** `package/out/<case>/` 评测产物：对 `eval/golden.json` `eval_inputs` 列出的**每个** case，实现方必须亲自运行 `python package/scripts/minutes.py --input inputs/<case>.txt --outdir package/out/<case>`，使每个 case 目录下都真实存在 `纪要.docx` + `summary.json`。**先产出、后评测**；未产出即运行 eval 属于流程违规。
- D.2 输入样例位置：资产根 `inputs/<case>.txt` 是黄金转写稿的实现者副本（与规范源 `oracle/inputs/<case>.txt` **字节一致**，2026-09-29 建立）。「禁止读取 oracle/」的隔离规则指不得读 `oracle/oracle.py`（参照实现）与 `oracle/out/`（参照产物）；两处**输入样例是评测材料**，实现方经 `inputs/` 使用，无需触碰 `oracle/`。
- D.3 评测命令固定：`python eval/runner.py package/out oracle/out`（可从资产根或经 workflow 目录联接执行），exit 0 为通过。`no_fabricated_entries` 检查由**参照目录上推一级**定位转写稿（`<参照>/../inputs/<case>.txt`，runner.py:172-173），因此 eval 必须按资产布局以 `oracle/out` 为参照目录运行，参照目录不可移动或改名。
- D.4 自查顺序（实现方在返回前完成）：① 运行 §9 D.1 全部 case；② 运行 D.3 评测命令；③ 若有检查失败，修实现后重跑 ①②；返回中必须附 eval 的真实 stdout 与 exit code。
