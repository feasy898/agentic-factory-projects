# meeting-minutes

## 权威规则（置顶）

1. 【MUST RELOAD】多轮对话中出现新指令时，第一个工具调用必须是重新 Read 本 SKILL.md。
2. 本技能引用的 references 必须完整读完再动手，禁止凭记忆复述规则。
3. 两条红线：①条目内容**逐字引用**转写原句，禁止改写、摘要、合并或编造；②负责人与期限只按确定性规则从原句提取，抓不到一律填「待定」。

## 何时使用

用户给出会议转写/录音整理文本（`[hh:mm] 说话人: 内容` 每行一条），需要抽出**决议、待办、风险**三段式纪要并落成 docx 交付时。典型输入文件名如 `case1.txt`、`meeting-transcript.txt`。

## 输入格式

- 每行至多一条发言：`[hh:mm] 说话人: 内容`（时 1–2 位、分 2 位；中英文冒号均可；说话人不含冒号）。
  解析正则：`^\s*\[(\d{1,2}:\d{2})\]\s*([^：:]+?)\s*[：:]\s*(.+?)\s*$`
- 文件按 UTF-8 读取（容忍 BOM）；空行直接忽略。
- 噪声自动排除，**无需人工挑拣**：无法解析为发言格式的非空行（寒暄开场、口误更正的无时间戳行、散会行、乱码行）不进入任何章节；解析成功但不含 11 个关键词（见下表）的发言同样不进入。

## 三段式判定规则

逐行按**子串包含**匹配 11 个关键词；一行至多归一类，按优先级 **决议 > 待办 > 风险** 取第一个命中的类：

| 优先级 | 章节 | 关键词 |
|---|---|---|
| 1 | 一、决议事项 | 决定 / 议定 / 同意 / 结论 |
| 2 | 二、待办事项 | 需要 / 负责 / 跟进 / 截止 |
| 3 | 三、风险与关注 | 风险 / 延期 / 不确定 |

- 分类只看关键词、不看行位置：含关键词的收尾行（如「结论：……。散会」）照样收录，不含关键词的散会行不收录。
- 同行命中多类只归最高优先级一类（如「一旦出现**延期**迹象……这个**结论**请记牢」归决议）。
- 三类互不重叠；各节条目按**原转写行序**排列，编号从 1 连续。
- 已知可接受的「错」（规则如此，不要自作聪明修正）：「承诺**不能延期**」归风险；「就**议定**下来」归决议；关键词命中即整句收录，不截断。
- 口误更正不做上下文关联：更正前后的行各自独立按关键词处理。
- 模糊话术与边界的完整口径见 references/classification-rules.md。

## 使用步骤

1. **运行脚本（优先）**：
   ```
   python <本包目录>/scripts/minutes.py --input <转写.txt> --outdir <输出目录>
   ```
   - `scripts/gen_docx.py` 是等价别名入口，参数与产物完全相同，任选其一。
   - 参数均必填；`--outdir` 不存在自动创建；路径相对当前工作目录解析。
   - **成功判据（写后回读三态）**：退出码 0 **且** `<输出目录>/纪要.docx` 与 `<输出目录>/summary.json` 都真实存在（用 ls/dir 回读确认）。只有退出码 0 不算完成；两者都在才算 verified。
   - 输入文件不存在时脚本以非 0 退出且不产出半成品——此时停止并向用户确认正确路径，禁止自己编造输入。
2. **验收（在 skillfactory 资产内时）**：
   ```
   python eval/runner.py <被测out> oracle/out
   ```
   exit 0 即通过。5 项检查：三节标题齐全／待办表格含负责人、期限列／summary 四键与 docx 实际条数一致／每条目可在转写稿逐字溯源（含时间+说话人）／与参照产物各类条数差 ≤2。
3. **无脚本执行条件时（无法运行 python）**：按 references/docx-and-summary.md 的结构约定**手工产出同名产物**（`纪要.docx` + `summary.json`），产出后逐条自查该文件末尾的验收清单。

## 产物与验收

| 交付物 | 回读命令 | 通过条件 |
|---|---|---|
| `<outdir>/纪要.docx` | python-docx 打开，遍历段落与表格 | 标题+元信息+三节标题齐全；决议/风险为编号条目；待办为 3 列表格（事项/负责人/期限） |
| `<outdir>/summary.json` | 解析 JSON 四键 | 决议事项/待办事项/风险与关注/合计，与 docx 实际条数逐项一致，合计=三者和 |
| 条目内容 | 与转写稿逐行比对 | 每条都能在原稿找到出处行，且出处行含该条时间与说话人 |

## 边界（非目标）

- **不做**：语义去噪（只靠格式+关键词规则排除）、上下文纠错与口误合并、多会议合并、纪要摘要/改写、`[hh:mm] 说话人: 内容` 之外的转写格式、非 txt 输入（docx/audio 请先转成 txt）、负责人/期限的语义推断。
- 空文件/全噪声输入**不报错**：产出三节皆空、待办表格仅表头行、summary 全 0 的合法 docx。
- **红线**：不确定的负责人/期限如实填「待定」；禁止编造负责人、禁止猜测日期。

## gotchas（实测坑）

- 「本周五之前」的期限提取结果是「周五之前」——本周/下周/这周前缀只参与命中、**不进**提取结果。
- 待办表格「事项」列也必须逐字引用原句（评测对表格行同样逐条溯源）。
- 产物文件名固定中文「纪要.docx」与「summary.json」，不要改名、不要加日期后缀。
- summary 四键名必须精确为「决议事项/待办事项/风险与关注/合计」，数值与 docx 实际内容一致。
- 某节 0 条时该节标题**仍然保留**，不要删标题。
