# contract.md — 月度汇报生成器 模块契约（冻结）

- 版本：1.0（冻结于 2026-09-29）
- 效力：本文件冻结**对外接口**。接口之内（算法、绘图细节、PPT 排版实现、内部模块划分）实现自由。
- 语义基准：行为语义以 `spec.md` 为准；本文只定接口与结构。冲突时以 spec.md 为语义权威。

---

## 1. package/ 必须包含的文件

```
package/
├── SKILL.md                      # 必备结构见 §4
├── scripts/
│   └── monthly_report.py         # 唯一入口脚本（文件名固定），CLI 见 §2
└── requirements.txt              # 至少：openpyxl>=3.1、matplotlib>=3.11、python-pptx>=1.0
```

- 允许 `package/` 内有其他内部模块/资源文件（如字体、工具库），但**不得改变 §2/§3 的对外接口**。
- 入口脚本必须可直接以 §2 命令运行（允许内部 import 同目录模块）。

## 2. scripts 命令行契约（冻结）

```
python package/scripts/monthly_report.py --input <台账.xlsx> --outdir <输出目录>
```

| 参数 | 必填 | 语义 |
|---|---|---|
| `--input` | 是 | 台账 xlsx 路径（第一个工作表，表头含 日期/事项/类别/数量/状态） |
| `--outdir` | 是 | 输出目录；不存在则递归创建，已存在则复用（不清空旧文件） |

**退出码**：

| 码 | 条件 | 行为 |
|---|---|---|
| 0 | 成功 | stdout 打印人读摘要（行数/关键汇总/产物路径，格式自由） |
| 2 | 输入文件不存在；第一个工作表无表头行；表头缺任一必需列 | stderr 打印中文错误信息，**不产生产物**，不写半成品 |

- 不允许其他退出码语义；未捕获异常导致的崩溃按实现质量问题处理，不算合法契约行为。

## 3. 产物契约（<outdir> 内，文件名与 schema 冻结）

固定 5 个产物（与 oracle 完全同名）：

| 文件 | 冻结点 |
|---|---|
| `月度趋势.png` | 各月数量合计折线图；中文 Microsoft YaHei、`axes.unicode_minus=False`；空数据画提示文案不报错 |
| `类别分布.png` | 各类别条目数条形图；排序与「条目最多类别」口径同 spec S3 |
| `状态占比.png` | 各状态条目占比饼图 |
| `汇报.pptx` | 16:9（13.333×7.5in）；页数 ≥4，前四页语义固定（封面/数据概览嵌月度趋势图/类别明细表格+嵌类别分布图/结论与下月计划）；P2、P3 必须内嵌图片；全部文案由数据推导，**禁止当前时间/随机内容**；表格列＝类别/条目数/数量合计/占比，含合计行 |
| `summary.json` | 顶层与「关键汇总数字」键集合**完全等于** spec §7 所列（可判定：键集合相等）；数值口径同 spec §3/§4；UTF-8 |

**summary.json 顶层键**（9 个，缺一不可、不得增删）：
`输入文件, 原始行数, 重复行数, 去重后行数, 空行数, 图数, 页数, 图表, 关键汇总数字`

**关键汇总数字键**（14 个）：
`数量合计, 月份数, 统计区间, 月度数量合计, 类别数, 类别条目数, 状态数, 状态条目数, 已完成条数, 完成率, 阻塞条数, 缺失日期行数, 缺失数量行数, 条目最多类别`

**确定性（MUST）**：同输入连跑两次，5 个产物逐字节一致（zip 条目时间戳须归一化，如固定 1980-01-01；写文件遇 PermissionError 允许有限次重试）。

**脏数据口径（MUST）**：按 spec §3 R1–R6 执行（空行剔除、重复去重保留首条、缺失日期不进趋势、缺失类别→「未分类」、缺失状态→「未知」、缺失数量按 0、完成态全等匹配、阻塞子串匹配）。eval 将从源 xlsx 独立重算并核对，数值容差 5%。

## 4. SKILL.md 必备结构

SKILL.md 必须包含以下小节（顺序不限、标题措辞可调，内容缺一不可）：

1. **名称与描述**：一句话说明“Excel 台账 → 3 张图表 + 4 页 PPT + summary.json，确定性可复现”。
2. **何时使用 / 何时不用**：使用场景（月度复盘、定期汇报）；不用场景（对应 spec §10 非目标，如多表合并、模板定制）。
3. **输入要求**：五列表头、日期/数量可解析格式、容忍的脏数据类型（引用 spec §2/§3 规则编号 R1–R6）。
4. **用法**：与 §2 完全一致的命令行示例（--input/--outdir、退出码 0/2）。
5. **产物说明**：5 个文件清单 + summary.json 字段表。
6. **清洗口径**：逐条引用 spec.md 的规则编号（R1–R6、S1–S5），保证口径可追溯。
7. **错误处理**：§2 的退出码表与三种错误输入示例。
8. **环境依赖**：Python 3.12+、openpyxl/matplotlib/python-pptx 版本、Windows + Microsoft YaHei 假设。

## 5. eval/ 契约（冻结）

- `eval/golden.json` 结构固定：`{"skill", "eval_inputs":[{"case","input","output"}], "ab_tasks":[{"id","instruction","input","rubric":[]}]}`；`eval_inputs.input/output` 用**资产根相对路径**（如 `oracle/inputs/case1.xlsx`、`oracle/out/case1`）。
- `eval/runner.py` 命令行契约（冻结）：

```
python eval/runner.py <被测输出目录> <参照输出目录> [--inputs <xlsx 目录>]
# 例：python eval/runner.py package/out oracle/out
# 自校验：python eval/runner.py oracle/out oracle/out   → 全过 exit 0
```

- runner 检查项（固定五类，输出 `{"ok", "tested", "reference", "checks":[{"name","pass","detail"}]}`）：
  1. pptx 可被 python-pptx 打开且页数 ≥4，且 summary 报告的 页数 与实际一致；
  2. 3 张指定图表 PNG 齐全，且 pptx 中 ≥2 页内嵌图片（图表确实进了 PPT）；
  3. summary.json 数字与 runner 从源 xlsx 的**独立重算**一致（数值相对容差 5%，集合/字符串精确）；
  4. 脏数据处理正确：`去重后行数=原始行数−重复行数`、缺失日期行不计入月度合计、缺失数量按 0 计；
  5. 被测与参照的 pptx 页数差 ≤2。
- 全部通过 → 打印上述 JSON 且 **exit 0**；任一失败 → 同样打印 JSON（失败项 `pass=false`）且 **exit 1**。
- runner 自身确定性：不含时间/随机源，同一输入两次运行输出一致。
- 源 xlsx 定位顺序（供检查 3/4 重算用）：`--inputs` 目录 → `<被测根>/inputs` → `<被测根>/../inputs` → `<被测根>/../../inputs` → `<参照根>` 同样三级；文件名取自 summary.json 的 `输入文件`。

## 6. 冻结与变更管理

- §1 文件清单、§2 CLI、§3 产物名与 summary schema、§4 SKILL.md 结构、§5 eval 结构与检查项 = **冻结接口**。
- 实现自由区：图表配色/字号/留白、PPT 文案措辞（语义不变）、内部代码组织、PNG 的像素内容。
- 破坏性变更：必须升本文件版本号，并同步修订 spec.md、golden.json、runner.py 三处，在变更记录注明日期与原因。
