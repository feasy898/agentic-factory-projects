# spec.md — 月度汇报生成器（Excel 台账进、图表+PPT 出）行为规格

- 版本：1.1（2026-09-29）：新增 §12「交付物与自评」（回应连续两轮"只交脚本、从未运行"的失败）；§1–§11 行为条款未改动。
- 依据：参照实现 `oracle/oracle.py` 的实际行为逐条固化；本文每条规则都可通过运行 oracle 判定。
- 参照环境：Python 3.12.10 + openpyxl 3.1.5 + matplotlib 3.11.2 + python-pptx 1.0.2（Windows）。
- 验证方式标注：【实测】= 本会话实际运行过并给出命令/结果；【码读】= 由 oracle 源码推导（附行号），语义明确但未构造专门样例。

## 1. 目标

给定一份月度工作台账 Excel（xlsx），确定性地产出：

1. 3 张统计图表 PNG（月度趋势、类别分布、状态占比，中文渲染）；
2. 1 份 16:9 汇报 PPT（封面/数据概览/类别明细/结论与下月计划）;
3. 1 份 `summary.json`（机器可读的关键汇总数字）。

核心卖点：**同输入重跑，产物字节级一致**（确定性，无时间/随机源）；对脏数据（重复行、空行、缺失值、字符串日期、负数数量）有明文且稳定的清洗口径。

> **实现者注意**：本文 §1–§11 只定义行为语义；交付物必须包含什么、脚本必须实际运行、
> 被测产物落在哪个目录、交付前自评怎么跑——见 **§12 交付物与自评（MUST）**。
> 只写代码不运行 = 直接评测失败（历史已两次发生）。

## 2. 输入契约

- **I1 工作表选取**：只读第一个工作表；以 `data_only=True, read_only=True` 打开（公式取缓存值，无缓存则视为空）。（oracle.py:113）
- **I2 表头识别**：从首行开始找**第一个非空行**作为表头；表头之前的全空行被跳过且不计数。【码读 oracle.py:117-121】表头行本身不计入任何行数统计。
- **I3 必需列**：表头必须含 `日期/事项/类别/数量/状态` 五列；多余列忽略；缺任一列 → 输入错误（见 §8 E2）。【实测：3 列表头报“表头缺少必需列：数量”，exit 2】
- **I4 日期解析**（oracle.py:67-81）：date/datetime 单元格直接取日期（datetime 丢弃时分秒）；字符串按以下格式依次尝试：`%Y-%m-%d`、`%Y/%m/%d`、`%Y.%m.%d`、`%Y年%m月%d日`、`%Y%m%d`（strptime 允许非补零，如 `2026/7/5`）。全部失败 → 视为缺失日期。【实测 case2：`2026/07/18`、`2026年7月25日` 均解析成功】
- **I5 数量解析**（oracle.py:84-96）：int/float 直接用；**bool 不算数字**；字符串去半角逗号后按 float 解析（`"6"` → 6.0）；空/非法 → 缺失数量。【实测 case2：数量为字符串 `"6"` 的行计入合计且缺失数量行数=0】
- **I6 文本规范化**（oracle.py:58-64）：单元格 → `str(v).strip()`；None → 空串；date/datetime → `%Y-%m-%d`。

## 3. 清洗行为规则（顺序执行，全部确定性）

- **R1 空行**：五列**全部**为空（规范化后）的行不计入“原始行数”，单独计入“空行数”。（oracle.py:134-137）【实测 case2：空行数=1，原始行数 21 = 22 条数据 − 1 空行】
- **R2 完全重复行去重**：去重键 =（日期可解析→ISO `YYYY-MM-DD`，否则原文；事项文本；类别文本；数量可解析→数值归一化文本（整数去小数点、小数至多 2 位去尾零），否则原文；状态文本）。键相同只保留**首次出现**，其后各条各计 1 次“重复行数”。（oracle.py:142-160）
  - 推论【实测 case2】：字符串日期行 `2026/07/18` 与日期单元格行 `2026-07-18`（其余四列相同）**算重复**，字符串日期行保留。
  - 恒等式：`去重后行数 = 原始行数 − 重复行数`。【实测 case1：25−3=22；case2：21−5=16；case3：9−2=7】
- **R3 缺失日期**：日期缺失/无法解析的行**不进入月度趋势**（月度图表与月度汇总均不含），计入“缺失日期行数”；其余统计照常包含该行。（oracle.py:181-186）【实测 case1：缺失 1 行（数量 4），数量合计 78，月度合计和 74】
- **R4 缺失类别/状态**：类别缺失 → 归入「未分类」；状态缺失 → 归入「未知」；两处均在图表与表格中正常出现。（oracle.py:188,192）【实测 case2：类别条目数含「未分类」1 条；case1：状态条目数含「未知」1 条】
- **R5 缺失数量**：缺失/非数字数量按 **0** 参与求和，计入“缺失数量行数”；该行条目数统计不受影响。（oracle.py:175-178）【实测 case1：缺失数量 1 行，合计 78 不受影响】
- **R6 完成态与阻塞**：状态**恰为**「已完成」或「完成」（全等，非子串）计为已完成；状态文本**包含**「阻塞」子串即计为阻塞事项。（oracle.py:48,194-197）【实测 case1：已完成 14、完成率 63.6%、阻塞 1（状态「已阻塞」）】

## 4. 汇总口径（对去重后的行）

- **S1 数量合计** = 去重后各行数量之和（含按 0 计的缺失行、含负数）。【实测 case3：−3+5+4+6+1+7+2 = 22】
- **S2 月度聚合**：按 `YYYY-MM` 聚合数量合计与条目数，月份**升序**；缺失日期行不参与。（oracle.py:183-186,199）
- **S3 类别/状态排序**：条目数**降序**、同数按名称升序（Unicode 码点），即 key `(-条数, 名称)`；「条目最多类别」取排序后第一。（oracle.py:200-201,203）【实测 case1：线上运维 7 与需求开发 7 并列，取「线上运维」】
- **S4 完成率** = 已完成条数 ÷ 去重后行数 × 100，保留 1 位小数（Python round，banker's rounding）；去重后行数为 0 → 完成率 0.0。（oracle.py:599-600）【实测 case1：14/22→63.6；case2：9/16→56.2】
- **S5 统计区间** = [最早月, 最晚月]（升序首尾）；无有效月份 → `[]`，「条目最多类别」→ `"-"`。（oracle.py:592,604）【实测：仅表头无数据行的 xlsx → 统计区间 `[]`、条目最多类别 `"-"`、完成率 0.0、exit 0，5 个产物正常生成且图表为空数据提示文案】

## 5. 图表产物（3 张 PNG）

- **C1 文件名与内容固定**：`月度趋势.png`（各月数量合计折线，带数值标注）、`类别分布.png`（各类别条目数条形，带数值标注）、`状态占比.png`（各状态条目占比饼图，显示百分比）。尺寸：折线/条形 figsize=(8,4.5)、饼图 (6.4,4.8)，dpi=150，matplotlib **Agg** 后端。（oracle.py:39-41,238-288）
- **C2 中文渲染**：字体 Microsoft YaHei，`axes.unicode_minus=False`（负号正常显示，不出方块）。（oracle.py:44-45）【实测 case3 含 −3 负数，图表正常生成】
- **C3 空数据回退**：无有效数据的图表画居中灰色提示文字（如「无有效日期数据」），不报错。（oracle.py:232-234,248,268,284）【实测：仅表头样例 exit 0】

## 6. PPT 产物（`汇报.pptx`，python-pptx）

- **P1 版式**：16:9（13.333×7.5 英寸），空白版式自绘；正文字体 Microsoft YaHei（含 East-Asia 字体设置）。（oracle.py:411-414）【实测：3 例均 slides=4、13.333×7.5in、内嵌图片 2、含表格 1】
- **P2 页面语义（≥4 页，前四页语义固定）**：
  - P1 封面：标题「月度工作汇报」+ 数据来源文件名 + 统计区间 + 有效记录数/数量合计/完成率；
  - P2 数据概览：原始/重复/空行/去重行数、覆盖月数与区间、数量合计、最多类别、完成率、缺失说明 6 条要点 + **内嵌月度趋势图**；
  - P3 类别明细：表格（列＝类别/条目数/数量合计/占比；末行合计，占比分母=去重后行数；类别按 S3 排序）+ **内嵌类别分布图**；
  - P4 结论与下月计划：左右两栏。
  - 允许实现追加页面，但 eval 要求与参照页数差 ≤2（见 eval/runner.py），且不得改变前四页语义。
- **P3 内容推导**：全部文案由数据规则推导，**不得含当前时间、随机内容**。（oracle.py:24,348-400）
- **P4 结论固定 5 条**：记录规模（原始/剔除重复/空行/有效/合计）、覆盖月数与最多类别、趋势（≥2 个月：末月 vs 首月，上升/下降/持平 + 百分比；首月为 0：绝对增量；<2 个月：明示无法计算）、完成情况（已完成/完成率/未完成/其中阻塞 N 条）、数据质量（缺失日期/缺失数量）。（oracle.py:348-377）
- **P5 下月计划规则**：最大投入类别保持投入；有阻塞则优先清理；有未完成则逐项跟进；有缺失则补录；末条固定「沿用本报表口径按月复盘」。下月 = 数据最末月的次月（12 月 → 次年 1 月）。（oracle.py:380-400）
- **P6 页脚**：每页有灰色小字页脚（数据来源/口径说明），具体文案实现内自由。

## 7. `summary.json` 产物

顶层键固定：`输入文件, 原始行数, 重复行数, 去重后行数, 空行数, 图数(=3), 页数, 图表(3 个 PNG 文件名), 关键汇总数字`。
`关键汇总数字` 固定键：`数量合计, 月份数, 统计区间, 月度数量合计{月:合计}, 类别数, 类别条目数{类别:条数}, 状态数, 状态条目数{状态:条数}, 已完成条数, 完成率, 阻塞条数, 缺失日期行数, 缺失数量行数, 条目最多类别`。（oracle.py:580-606）
样例期望值（实测）：

| 原始/重复/空行/去重 | 25/3/0/22 | 21/5/1/16 | 9/2/0/7 |

## 8. 错误契约

- **E1 输入文件不存在** → stderr 打印中文错误，**exit 2**，不产生产物。【实测：`输入文件不存在: ...`，exit 2】
- **E2 输入不合法**（第一个工作表无表头行 / 表头缺必需列）→ stderr 打印中文错误，**exit 2**。【实测：`工作表为空：没有表头行`、`表头缺少必需列：数量（实际表头：[...]）`，均 exit 2】
- **E3 成功** → exit 0，stdout 打印行数/汇总/产物路径摘要（格式实现内自由）。

## 9. 确定性要求

- **D1** 脚本内不得有当前时间/随机源；PPT 全部文案由数据推导。【码读 + 实测：oracle case1 重跑 5 个产物 md5 与原产物逐字节一致（diff 为空，BYTE_DETERMINISTIC_OK）】
- **D2** 实现保存 pptx 时须消除 zip 条目时间戳（如归一化为 1980-01-01），保证字节级可复现；写最终文件遇 PermissionError 允许少量重试（仅影响时机，不影响内容）。（oracle.py:521-543）
- **D3** D1/D2 约束的是“同实现同输入重跑一致”；不同实现之间不要求字节一致，只须通过 eval/runner.py 的检查。

## 10. 边界与非目标

- **N1** 只处理单文件、第一个工作表；不做多表合并、多文件批量、目录扫描。
- **N2** 不修改、不回写输入文件。
- **N3** 不支持模板/主题/品牌定制；版式以本 spec 语义为准，不做像素级规定。
- **N4** 不做数据修复（不补日期、不猜数量、不改状态），缺失一律按 §3 口径统计并如实呈现。
- **N5** 产物语言为中文；字体面向 Windows（Microsoft YaHei），其他系统不保证。
- **N6** 不产出 docx/pdf/HTML 等其他格式；图表格式固定 PNG。
- **N7** “月度”来自数据中的日期，不与当前日历月绑定。
- **N8** 不校验业务合理性（如数量为负不警告、不拦截），负数按数值参与求和。【实测 case3】

## 12. 交付物与自评（实现者必读，全部 MUST；v1.1 新增）

> 本节回答"代码写完之后还要做什么"。失败教训（2026-09-29，连续两轮）：
> 再生成只交付了 `package/scripts/monthly_report.py`，从未运行——`package/out` 不存在
> （eval 报 `units_found=false`），脚本本身还带语法错误（运行即崩）。
> 根因是本 spec 此前从未要求"实际运行"，故本节条款为交付必要条件，违反即评测失败。

- **V1 交付三件套**：`package/` 必须实际包含 contract.md §1 所列全部文件——
  `SKILL.md`、`scripts/monthly_report.py`、`requirements.txt`（另允许内部模块/资源）。
  只交脚本、缺 `SKILL.md` 或 `requirements.txt` 视为交付不完整。
- **V2 脚本必须先跑通再交付**：交付前至少验证
  `python -m py_compile package/scripts/monthly_report.py` 通过（语法可解析），
  且对 §12 V3 的每个 golden 输入实际执行、退出码 0。
  交付一个从未运行过的脚本 = 直接失败，无豁免。
- **V3 被测产物布局**：以下命令均以**资产根目录**（`skillfactory/assets/monthly-report-ppt/`）
  为工作目录，对三个 golden 输入逐个运行实现脚本：

  ```bash
  python package/scripts/monthly_report.py --input oracle/inputs/case1.xlsx --outdir package/out/case1
  python package/scripts/monthly_report.py --input oracle/inputs/case2.xlsx --outdir package/out/case2
  python package/scripts/monthly_report.py --input oracle/inputs/case3.xlsx --outdir package/out/case3
  ```

  布局规则：
  - **每个 case 一个单元目录，目录名与 `oracle/out/` 下参照目录同名**
    （`case1`/`case2`/`case3`），不得使用其他名字（配对规则见 V4）；
  - `--outdir` 就是单元目录本身：5 个产物（`月度趋势.png`、`类别分布.png`、
    `状态占比.png`、`汇报.pptx`、`summary.json`）**直接位于** `package/out/caseN/` 下，
    不得再嵌套子目录（如 `package/out/case1/out/...` 会导致 runner 找不到单元）；
  - 三个 case **不得共用同一 outdir**（同名产物互相覆盖，且无法与参照逐 case 配对）；
    也不得只跑部分 case 少交（见 V4 末条）；
  - `oracle/` 目录是评测参照基准，**不得写入、移动或覆盖其中任何文件**。
- **V4 runner 如何发现与配对单元**（评测语义，依据 eval/runner.py 实测）：
  - 产物单元 = **同时含 `汇报.pptx` 与 `summary.json` 的目录**；被测根目录自身是单元
    则按单单元评测，否则扫描其一级子目录（按名排序）；
  - 被测单元按**相对目录名**与参照单元配对（`case1`↔`case1`）；参照含 3 个单元时，
    被测必须逐 case 建同名子目录——目录名对不上会在 `pages_within_2_of_ref` 报
    "找不到与 'xxx' 对应的参照产物单元"；
  - 被测目录无任何单元 → `units_found=false`、exit 1 直接判负；
  - 注意：runner 只评测被测目录里**实际存在**的单元，少交的 case 不会单独报错，
    但按 V3 属交付不完整，同样判不合格——不得以少跑 case 规避检查。
- **V5 交付前自评门槛**：完成 V3 后运行

  ```bash
  python eval/runner.py package/out oracle/out
  ```

  要求 **exit 0、`ok=true`**：`units_found`、3 个单元 × 5 类检查、
  `reference_dir_has_units` 全部 pass。这是交付的必要步骤，不是可选步骤；
  自评不过不得交付。
