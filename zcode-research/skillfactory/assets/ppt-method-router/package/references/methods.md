# references/methods.md — 三类制作方法的执行要点

> 本文件是路由裁定后的**移交参考**：路由层（`scripts/route.py`）只决定选哪条路，
> 本文件描述每条路的执行要点、输入要求、验收标准与常见坑，供进入执行链时取用。
> 与 SKILL.md §3 的"能力边界与移交方式"一一对应，此处展开到可执行粒度。

---

## 1. editable_pptx — 数据驱动可编辑汇报

**定位**：以可编辑的 .pptx 为交付物，数据→图表→页面全链路可改，适合内部汇报、
例会材料、需要反复更新数字的场合。

**输入要求（开工前向用户/上游确认）**：
- 数据源：表格/台账/系统导出的结构化数据（Excel、CSV 均可），明确口径与时间范围；
- 汇报对象与时长：决定页数（例会 10 页内、专题 15–25 页）与详略；
- 更新频率：高频更新的页面应做成"改数即改图"的绑定结构，不手绘。

**执行要点**：
1. 先做数据清理与口径对齐，再谈版式——数据错了版式再好也是负资产；
2. 每个核心结论一页：标题写判断（"华东环比 +12%"），不写栏目名（"华东数据"）；
3. 图表选型跟着数据关系走：构成用堆叠/饼、趋势用折线、对比用柱、相关性用散点；
4. 母版统一字号/配色/页码，正文用占位文本框而非文本框贴图，保证可编辑性；
5. 收尾自检：任意页双击图表能改数、字体嵌入、脱离本机不缺字。

**验收标准**：交付 .pptx 源文件；抽 3 页改数字后图表正确联动；无占位符残留。

**常见坑**：把数据页做成整页图片（丧失可编辑性）；图表手动改标签导致下次更新错位。

## 2. template_fill — 套用既有公司模板

**定位**：以用户既有模板/品牌 VI 为骨架，只填充内容，保证对外材料与公司规范一致。

**输入要求**：
- 模板资产本体（.pptx/.potx）或 VI 规范（配色、字体、Logo 使用规则）；
- 明确"沿用哪些页"：封面/目录/章节页/内容页/结尾页的取舍；
- 内容素材：按模板占位结构整理好文案与图，不要求用户重排。

**执行要点**：
1. 先解析模板：列出可用版式（layout）与占位符（placeholder）清单，再映射内容；
2. 只在占位符内填内容，不新建游离文本框——这是"套模板"与"重新排版"的分界线；
3. 品牌 VI 优先于个人审美：颜色取模板主题色，不引入模板外的高饱和色；
4. Logo、密级、页脚等合规元素原样保留，不得因排版美观删改；
5. 无既有模板时的降级路径：向用户确认"是否由我按 VI 规范新建母版"，
   新建后仍按本方法流程交付，避免混入 visual_report 的自由版式做法。

**验收标准**：交付沿用模板母版的 .pptx；主题色/字体与模板一致；占位符外无游离元素。

**常见坑**：从旧 PPT 复制页面带入旧版式残留；粘贴内容时带源格式覆盖模板字体。

## 3. visual_report — 图文海报/信息图

**定位**：单页视觉物料，重传播与视觉冲击，交付图片（PNG/长图）或设计源稿，
文字层可编辑性让位于视觉效果。

**输入要求**：
- 一句话主题与目标受众：决定信息层级（3 秒能看懂主标题）；
- 核心信息点：建议 3–5 个，超过就拆多张或改回 editable_pptx 路径；
- 投放渠道：朋友圈/展位/打印的尺寸与安全边距不同（朋友圈竖版 3:4 起、展位留远视距离）。

**执行要点**：
1. 先定信息层级：主标题 → 副标题 → 3–5 个要点 → 落款/二维码，视觉权重依次递减；
2. 一张图一个视觉焦点，数据取整、放大关键数字，弱化次要标注；
3. 字号下限按渠道定（朋友圈手机端正文 ≥24px 等效），对比度保证可读；
4. 导出前 1:1 像素预览手机端效果，检查二维码可扫、裁切安全区内无关键信息；
5. 需要后续常改的元素（日期、价格）单独留图层/文本框，降低改版成本。

**验收标准**：交付指定尺寸图片；手机端缩略图下主标题可读；无文字溢出与元素重叠。

**常见坑**：信息塞太满（超过 5 个要点应劝退回 editable_pptx）；导出分辨率不足印刷模糊。

## 移交约定（三类通用）

- 路由输出的 `method` + `reasons` 随任务一并移交执行链；conflict/兜底情形
  （confidence ≤ 0.75 或 0.4）必须附上 reasons 中的复核提示，不得静默降级；
- 执行中发现需求实为另一类（例：套模板过程中用户要求自由海报页），**停止当前路径，
  回到路由层以新措辞重跑** `route.py`，而不是在单条路径内硬做；
- 三类路径的产物互不复用：海报图不充当汇报页，模板页不裁成海报，
  跨类需求拆成多次路由分别执行。
