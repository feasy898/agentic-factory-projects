# 生成周报骨架（weekly-report）

把本周散落在各处的记录（bullet 列表、工作日志、commit 信息、会议纪要等）整理成一份
**结构固定**、**条条有出处**的周报骨架。产出是骨架而非定稿：只做归类与出处标注，
不改写事实、不做绩效评价。

## 何时使用

- 每周五提交周报前；
- 任何周期性汇报节点（周会、双周报、迭代收尾）需要把一周记录汇总成固定格式时。

## 输入与产物

| 项 | 说明 |
|---|---|
| 输入 | 本周的零散工作记录，bullet 列表、工作日志、commit 信息、会议纪要皆可 |
| 产物 | 一个 Markdown 周报文件，命名 `周报-YYYY-Www.md`（ISO 8601 周次，如 `周报-2026-W40.md`） |
| 中间产物 | 输入记录清单（每条记录编号 R-01、R-02…，含五要素，见"来源引用五要素"） |

## 分步方法

1. **收集一周记录并编号。**
   动作：汇总本周全部来源（bullet 列表、工作日志、commit 信息、会议纪要），去除重复后
   逐条编号 R-01、R-02…，登记五要素（来源类型、编号、日期、原始位置、原文摘录）。
   可判定产物：一份输入记录清单（建议存为 `weekly-inputs-YYYY-Www.md` 或放在周报草稿头部），
   每条记录五要素齐全、编号不重不漏。
2. **确定年份周次并建立周报文件。**
   动作：按 ISO 8601 计算本周周次（周一为一周之始；如 2026-09-29 属 2026-W40），
   创建 `周报-YYYY-Www.md`，写入固定骨架（标题行 + 三个小节标题，见下方模板）。
   可判定产物：存在名为 `周报-YYYY-Www.md` 的文件，含 `## 本周完成`、`## 下周计划`、
   `## 风险与求助` 三个小节标题。
3. **按三小节归类。**
   动作：把清单中的记录逐条判定归属——已完成/有结论的工作归"本周完成"；输入中遗留未完、
   或明确表述"下周要做 X"的归"下周计划"；卡住、阻塞、依赖他人、需协调资源的归
   "风险与求助"。每条周报条目末尾标注出处编号，如 `- 完成登录接口联调 [R-03]`。
   一条记录可派生多条条目，但每条条目必须能指回至少一条 R-xx 记录。
   可判定产物：三个小节各有一版草稿条目，每条都带 `[R-xx]` 标注。
4. **复核每条进展的出处。**
   动作：逐条反向核对——该条在输入记录清单中能否找到对应记录？找不到出处的条目一律删除；
   核对"下周计划"仅来自输入中的遗留项或明确表述，不新增臆想计划；核对数字、项目名、
   结论等事实性内容与输入原文一致，未被改写或拔高。
   可判定产物：复核通过的周报——每条进展的 `[R-xx]` 都能在清单中找到；无出处条目数为 0。
5. **空节处理与定稿。**
   动作：某小节无任何条目时，**保留该小节标题**并在标题下一行写"无"；通读全文确认
   三个小节齐全、文件名周次正确、条目按重要性排序。
   可判定产物：最终 `周报-YYYY-Www.md`——三个小节标题齐全，空节下方标注"无"。

## 周报骨架模板

```markdown
# 周报 2026-W40（2026-09-28 ~ 2026-10-04）

## 本周完成
- <进展条目> [R-xx]

## 下周计划
- <计划条目，仅来自遗留项或明确表述> [R-xx]

## 风险与求助
- <阻塞项 / 需协调事项> [R-xx]
```

- 三个小节标题为固定写法，不得改名、不得增删；
- 某小节无内容时，保留标题，在其下一行写：`无`；
- 日期区间为该 ISO 周的周一至周日。

## 溯源红线

- **每条"本周完成"必须对应输入中的至少一条记录**，并标注 `[R-xx]` 出处；
  对应不上的条目一律删除——**不得编造、不得拔高**。
- "下周计划"不得虚构，只能来自输入中的遗留项或明确表述。
- 汇总只做归类与合并，不改写事实性内容（数字、结论、专有名词照抄输入）。
- 不做工作量与绩效评价（不写"效率高/低"、不对比成员间工作量）。

## 常见坑

1. **编造进展**：为了让周报"好看"补写输入中不存在的进展，或把"参与"写成"完成"。
   对策：先有记录清单、后有周报条目；每条带 `[R-xx]`，复核时逐条反向核对（步骤 4）。
2. **数据口径不一致**：不同来源对同一事项数字不同（如 commit 数 vs 工单数），或同类
   条目一会儿按人算一会儿按天算。对策：同一指标全篇只用一种口径，条目中注明口径
   （如"按工单数计 [R-05]"）；冲突数字以原始记录为准，不自行折算。
3. **遗漏阻塞项**：只写进展不写风险，"风险与求助"长期空白，管理者看不到卡点。
   对策：归类时专门扫一遍输入中的"卡住 / 阻塞 / 等待 / 依赖 / 需要"等关键词；
   确实没有也保留标题并标注"无"，不留空、不删标题。
4. **误删空节标题**：某节没内容就把标题删掉，破坏固定结构。
   对策：固定三小节永远保留，空节只标"无"（步骤 5）。
5. **周次或年份算错**：跨年周、以周日为一周之始的口径会导致 W 号对不上；不同工具的
   周次实现也可能不一致（实测 2026-09-29：Python `isocalendar()`、GNU `date +%V`、
   Node 手算均为 2026-W40，而本机 PowerShell 5.1 `-UFormat %V` 误报 W39）。
   对策：统一按 ISO 8601（周一为一周之始、含首个周四的周为第 1 周）计算，
   用两种独立实现交叉核对，写完后抽查文件名与日期区间是否一致。

## 来源引用五要素

输入记录清单中的每条记录，必须登记以下五个要素，缺任一要素视为出处不明，
不得作为"本周完成"的依据：

1. **来源类型**：bullet 列表 / 工作日志 / commit 信息 / 会议纪要等；
2. **唯一编号**：R-01、R-02…（周报条目通过 `[R-xx]` 指回）；
3. **日期**：该记录产生或覆盖的日期；
4. **原始位置**：文件路径、仓库+commit hash、URL 或文档名；
5. **原文摘录**：支撑该条周报内容的关键原句（数字与结论保持原文，不改写）。
